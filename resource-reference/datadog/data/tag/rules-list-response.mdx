`datadog_tag_rules_list_response` is a real, live data source: `ubx.Data`/`data`/`ubx.data` (per language) executes this lookup at resolve time, against Datadog's own real API, and returns whatever it finds. It is never created, modified, or destroyed by ubx -- see [docs/schema.md's own "Amendment: data sources"] for the real wire shape this compiles to (`data_sources[]`, never `resources[]`).

## Lookup arguments

<ResponseField name="include" type="string">
  A related resource to include alongside a tag rule in the response. Currently the only supported value is `score`. Optional lookup argument.
</ResponseField>

<ResponseField name="include_deleted" type="bool">
  Optional lookup argument.
</ResponseField>

<ResponseField name="include_disabled" type="bool">
  Optional lookup argument.
</ResponseField>

<ResponseField name="ts_end" type="number">
  Optional lookup argument.
</ResponseField>

<ResponseField name="ts_start" type="number">
  Optional lookup argument.
</ResponseField>

## Result properties

<ResponseField name="data" type="list(object)">
  An array of tag rule data objects. Returned by the lookup.
</ResponseField>

<ResponseField name="included" type="list(object)">
  Related resources fetched alongside the primary tag rules. Populated when an `include` query parameter is supplied. Returned by the lookup.
</ResponseField>
