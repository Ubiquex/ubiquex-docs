    </ResponseField>
    <ResponseField name="end" type="number">
      POSIX timestamp to end the downtime. If not provided, the downtime is in effect indefinitely until you cancel it. Optional.
    </ResponseField>
    <ResponseField name="id" type="number">
      The downtime ID. Computed by Datadog after `ship`.
    </ResponseField>
    <ResponseField name="message" type="string">
      A message to include with notifications for this downtime. Email notifications can be sent to specific users by using the same `@username` notation as events. Optional.
    </ResponseField>
    <ResponseField name="monitor_id" type="number">
      A single monitor to which the downtime applies. If not provided, the downtime applies to all monitors. Optional.
    </ResponseField>
    <ResponseField name="monitor_tags" type="list(string)">
      A comma-separated list of monitor tags. For example, tags that are applied directly to monitors, not tags that are used in monitor queries (which are filtered by the scope parameter), to which the downtime applies. The resulting downtime applies to monitors that match ALL provided monitor tags. For example, `service:postgres` **AND** `team:frontend`. Optional.
    </ResponseField>
    <ResponseField name="mute_first_recovery_notification" type="bool">
      If the first recovery notification during a downtime should be muted. Optional.
    </ResponseField>
    <ResponseField name="notify_end_states" type="list(string)">
      States for which `notify_end_types` sends out notifications for. Optional.
    </ResponseField>
    <ResponseField name="notify_end_types" type="list(string)">
      If set, notifies if a monitor is in an alert-worthy state (`ALERT`, `WARNING`, or `NO DATA`) when this downtime expires or is canceled. Applied to monitors that change states during the downtime (such as from `OK` to `ALERT`, `WARNING`, or `NO DATA`), and to monitors that already have an alert-worthy state when downtime begins. Optional.
    </ResponseField>
    <ResponseField name="parent_id" type="number">
      ID of the parent Downtime. Optional.
    </ResponseField>
    <ResponseField name="recurrence" type="object">
      An object defining the recurrence of the downtime. Optional.
      <Expandable title="properties">
        <ResponseField name="period" type="number">
          How often to repeat as an integer. For example, to repeat every 3 days, select a type of `days` and a period of `3`. Optional.
        </ResponseField>
        <ResponseField name="rrule" type="string">
          The `RRULE` standard for defining recurring events (**requires to set "type" to rrule**) For example, to have a recurring event on the first day of each month, set the type to `rrule` and set the `FREQ` to `MONTHLY` and `BYMONTHDAY` to `1`. Most common `rrule` options from the [iCalendar Spec](https://tools.ietf.org/html/rfc5545) are supported. **Note**: Attributes specifying the duration in `RRULE` are not supported (for example, `DTSTART`, `DTEND`, `DURATION`). More examples available in this [downtime guide](https://docs.datadoghq.com/monitors/guide/suppress-alert-with-downtimes/?tab=api) Optional.
        </ResponseField>
        <ResponseField name="type" type="string">
          The type of recurrence. Choose from `days`, `weeks`, `months`, `years`, `rrule`. Optional.
        </ResponseField>
        <ResponseField name="until_date" type="number">
          The date at which the recurrence should end as a POSIX timestamp. `until_occurences` and `until_date` are mutually exclusive. Optional.
        </ResponseField>
        <ResponseField name="until_occurrences" type="number">
          How many times the downtime is rescheduled. `until_occurences` and `until_date` are mutually exclusive. Optional.
        </ResponseField>
        <ResponseField name="week_days" type="list(string)">
          A list of week days to repeat on. Choose from `Mon`, `Tue`, `Wed`, `Thu`, `Fri`, `Sat` or `Sun`. Only applicable when type is weeks. First letter must be capitalized. Optional.
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="scope" type="list(string)">
      The scope(s) to which the downtime applies and must be in `key:value` format. For example, `host:app2`. Provide multiple scopes as a comma-separated list like `env:dev,env:prod`. The resulting downtime applies to sources that matches ALL provided scopes (`env:dev` **AND** `env:prod`). Optional.
    </ResponseField>
    <ResponseField name="start" type="number">
      POSIX timestamp to start the downtime. If not provided, the downtime starts the moment it is created. Optional.
    </ResponseField>
    <ResponseField name="timezone" type="string">
      The timezone in which to display the downtime's start and end times in Datadog applications. Optional.
    </ResponseField>
    <ResponseField name="updater_id" type="number">
      ID of the last user that updated the downtime. Computed by Datadog after `ship`.
    </ResponseField>
  </Expandable>
