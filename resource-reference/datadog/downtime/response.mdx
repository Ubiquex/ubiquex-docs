`datadog_downtime_response` is v2's own richer representation of a Datadog downtime -- a real, scheduled suppression window that mutes monitor alerts for a specific scope (a host, a service, a tag) during planned maintenance, so expected changes don't page anyone.

## Input properties

<ResponseField name="data" type="object" required>
  Object to create a downtime. Required.
  <Expandable title="properties">
    <ResponseField name="attributes" type="object" required>
      Downtime details. Required.
      <Expandable title="properties">
        <ResponseField name="display_timezone" type="string">
          The timezone in which to display the downtime's start and end times in Datadog applications. This is not used as an offset for scheduling. Optional.
        </ResponseField>
        <ResponseField name="message" type="string">
          A message to include with notifications for this downtime. Email notifications can be sent to specific users by using the same `@username` notation as events. Optional.
        </ResponseField>
        <ResponseField name="monitor_identifier" type="object" required>
          Monitor identifier for the downtime. Required.
          <Expandable title="properties">
            <ResponseField name="monitor_id" type="number">
              Optional; if omitted, computed by Datadog.
            </ResponseField>
            <ResponseField name="monitor_tags" type="list(string)">
              Optional; if omitted, computed by Datadog.
            </ResponseField>
          </Expandable>
        </ResponseField>
        <ResponseField name="mute_first_recovery_notification" type="bool">
          If the first recovery notification during a downtime should be muted. Optional.
        </ResponseField>
        <ResponseField name="notify_end_states" type="list(string)">
          States that will trigger a monitor notification when the `notify_end_types` action occurs. Optional.
        </ResponseField>
        <ResponseField name="notify_end_types" type="list(string)">
          Actions that will trigger a monitor notification if the downtime is in the `notify_end_types` state. Optional.
        </ResponseField>
        <ResponseField name="schedule" type="object">
          Schedule for the downtime. Optional.
          <Expandable title="properties">
            <ResponseField name="end" type="string">
              Optional; if omitted, computed by Datadog.
            </ResponseField>
            <ResponseField name="recurrences" type="list(object)">
              Optional; if omitted, computed by Datadog.
              <Expandable title="properties">
                <ResponseField name="duration" type="string">
                  Optional; if omitted, computed by Datadog.
                </ResponseField>
                <ResponseField name="rrule" type="string">
                  Optional; if omitted, computed by Datadog.
                </ResponseField>
                <ResponseField name="start" type="string">
                  Optional; if omitted, computed by Datadog.
                </ResponseField>
              </Expandable>
            </ResponseField>
            <ResponseField name="start" type="string">
              Optional; if omitted, computed by Datadog.
            </ResponseField>
            <ResponseField name="timezone" type="string">
              Optional; if omitted, computed by Datadog.
            </ResponseField>
          </Expandable>
        </ResponseField>
        <ResponseField name="scope" type="string" required>
          The scope to which the downtime applies. Must follow the [common search syntax](https://docs.datadoghq.com/logs/explorer/search_syntax/). Required.
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="type" type="string" required>
      Downtime resource type. Required.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="downtime_id" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>
