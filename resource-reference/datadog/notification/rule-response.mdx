`datadog_notification_rule_response` is a real, general-purpose rule controlling notification routing based on real conditions -- the general form the more specific `datadog_monitor_notification_rule_response`, `datadog_team_notification_rule_response`, and `datadog_incident_notification_rule` all specialize.

## Properties

<ResponseField name="data" type="object">
  Data of the notification rule create request: the rule type, and the rule attributes. All fields are required. Optional; if omitted, computed by Datadog.
  <Expandable title="properties">
    <ResponseField name="attributes" type="object" required>
      Attributes of the notification rule create request. Required.
      <Expandable title="properties">
        <ResponseField name="enabled" type="bool">
          Field used to enable or disable the rule. Optional.
        </ResponseField>
        <ResponseField name="name" type="string" required>
          Name of the notification rule. Required.
        </ResponseField>
        <ResponseField name="routing" type="object">
          Routing configuration for the notification rule. Optional.
          <Expandable title="properties">
            <ResponseField name="mode" type="string" required>
              The routing mode for the notification rule. `manual` sends notifications to the configured targets. Required.
            </ResponseField>
          </Expandable>
        </ResponseField>
        <ResponseField name="selectors" type="object" required>
          Selectors are used to filter security issues for which notifications should be generated. Users can specify rule severities, rule types, a query to filter security issues on tags and attributes, and the trigger source. Only the trigger_source field is required. Required.
          <Expandable title="properties">
            <ResponseField name="query" type="string">
              The query is composed of one or several key:value pairs, which can be used to filter security issues on tags and attributes. Optional.
            </ResponseField>
            <ResponseField name="rule_types" type="list(string)">
              Security rule types used as filters in security rules. Optional.
            </ResponseField>
            <ResponseField name="severities" type="list(string)">
              The security rules severities to consider. Optional.
            </ResponseField>
            <ResponseField name="trigger_source" type="string" required>
              The type of security issues on which the rule applies. Notification rules based on security signals need to use the trigger source "security_signals", while notification rules based on security vulnerabilities need to use the trigger source "security_findings". Required.
            </ResponseField>
          </Expandable>
        </ResponseField>
        <ResponseField name="targets" type="list(string)" required>
          List of recipients to notify when a notification rule is triggered. Many different target types are supported, such as email addresses, Slack channels, and PagerDuty services. The appropriate integrations need to be properly configured to send notifications to the specified targets. Required.
        </ResponseField>
        <ResponseField name="time_aggregation" type="number">
          Time aggregation period (in seconds) is used to aggregate the results of the notification rule evaluation. Results are aggregated over a selected time frame using a rolling window, which updates with each new evaluation. Notifications are only sent for new issues discovered during the window. Time aggregation is only available for vulnerability-based notification rules. When omitted or set to 0, no aggregation is done. Optional.
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="type" type="string" required>
      The rule type associated to notification rules. Required.
    </ResponseField>
  </Expandable>
</ResponseField>
