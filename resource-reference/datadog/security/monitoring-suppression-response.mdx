`datadog_security_monitoring_suppression_response` is a real, scoped rule that suppresses a Cloud SIEM security signal matching real criteria (already investigated, known false positive) without disabling the underlying detection rule for everyone else.

## Example

    package main

    import (
    	security "github.com/ubiquex/ubx-sdk-datadog/sdk/go/datadog/security"

    )

    func main() {
    	ubx.Main(ubx.Stack("example", func() {
    		ubx.Intent(ubx.IntentInfo{Summary: "example own monitoring suppression response"})

    		ubx.Resource(security.MonitoringSuppressionResponse, "example", security.MonitoringSuppressionResponseConfig{
    			Data:          map[string]any{"attributes": map[string]any{"name": "example-name"}},
    			SuppressionId: "example",
    		})
    	}))
    }

## Properties

<ResponseField name="data" type="object" required>
  Object for a single suppression rule. Required.
  <Expandable title="properties">
    <ResponseField name="attributes" type="object" required>
      Object containing the attributes of the suppression rule to be created. Required.
      <Expandable title="properties">
        <ResponseField name="data_exclusion_query" type="string">
          An exclusion query on the input data of the security rules, which could be logs, Agent events, or other types of data based on the security rule. Events matching this query are ignored by any detection rules referenced in the suppression rule. Optional.
        </ResponseField>
        <ResponseField name="description" type="string">
          A description for the suppression rule. Optional.
        </ResponseField>
        <ResponseField name="enabled" type="bool" required>
          Whether the suppression rule is enabled. Required.
        </ResponseField>
        <ResponseField name="expiration_date" type="number">
          A Unix millisecond timestamp giving an expiration date for the suppression rule. After this date, it won't suppress signals anymore. Optional.
        </ResponseField>
        <ResponseField name="name" type="string" required>
          The name of the suppression rule. Required.
        </ResponseField>
        <ResponseField name="rule_query" type="string" required>
          The rule query of the suppression rule, with the same syntax as the search bar for detection rules. Required.
        </ResponseField>
        <ResponseField name="start_date" type="number">
          A Unix millisecond timestamp giving the start date for the suppression rule. After this date, it starts suppressing signals. Optional.
        </ResponseField>
        <ResponseField name="suppression_query" type="string">
          The suppression query of the suppression rule. If a signal matches this query, it is suppressed and is not triggered. It uses the same syntax as the queries to search signals in the Signals Explorer. Optional.
        </ResponseField>
        <ResponseField name="tags" type="list(string)">
          List of tags associated with the suppression rule. Optional.
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="type" type="string" required>
      The type of the resource. The value should always be `suppressions`. Required.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="suppression_id" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>
