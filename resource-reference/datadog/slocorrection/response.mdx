---
title: "datadog_slocorrection_response"
description: "`datadog_slocorrection_response` excludes a specific time window -- one-time or recurring -- from an SLO's own error-budget calculation."
---

It's the real mechanism for making sure a scheduled maintenance window or a planned deployment doesn't unfairly count against reliability targets that were never meant to cover it.

## Example

## Properties

<ResponseField name="data" type="object">
  The data object associated with the SLO correction to be created. Optional; if omitted, computed by Datadog.
  <Expandable title="properties">
    <ResponseField name="attributes" type="object">
      The attribute object associated with the SLO correction to be created. Exactly one of `slo_id` or `slo_query` must be provided. Optional.
      <Expandable title="properties">
        <ResponseField name="category" type="string" required>
          Category the SLO correction belongs to. Required.
        </ResponseField>
        <ResponseField name="description" type="string">
          Description of the correction being made. Optional.
        </ResponseField>
        <ResponseField name="duration" type="number">
          Length of time (in seconds) for a specified `rrule` recurring SLO correction. Optional.
        </ResponseField>
        <ResponseField name="end" type="number">
          Ending time of the correction in epoch seconds. Optional.
        </ResponseField>
        <ResponseField name="rrule" type="string">
          The recurrence rules as defined in the iCalendar RFC 5545. The supported rules for SLO corrections are `FREQ`, `INTERVAL`, `COUNT`, `UNTIL` and `BYDAY`. Optional.
        </ResponseField>
        <ResponseField name="slo_id" type="string">
          ID of the single SLO that this correction applies to. Optional.
        </ResponseField>
        <ResponseField name="slo_query" type="string">
          Query that matches the SLOs this correction applies to. The query uses the [Events search syntax](https://docs.datadoghq.com/events/explorer/searching/) and can filter SLOs by SLO tags. Optional.
        </ResponseField>
        <ResponseField name="start" type="number" required>
          Starting time of the correction in epoch seconds. Required.
        </ResponseField>
        <ResponseField name="timezone" type="string">
          The timezone to display in the UI for the correction times (defaults to "UTC"). Optional.
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="type" type="string" required>
      SLO correction resource type. Required.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="slo_correction_id" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>
