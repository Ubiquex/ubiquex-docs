`datadog_organization_response` represents one organization inside a real multi-org account, the deployment model Datadog itself recommends for MSPs and larger companies that need to keep each client's or team's data fully separated. A parent organization can create and view usage for child organizations without ever seeing the underlying metrics inside them, and users can be granted access to the parent, to specific children, or both.

Real, typed bindings generated directly from the real Datadog OpenAPI specification, in every SDK language -- every tab below is a complete, runnable program, not a fragment, real enough to save and run exactly as shown.

## Input properties

<ResponseField name="billing" type="object">
  A JSON array of billing type. Optional.
  <Expandable title="properties">
    <ResponseField name="type" type="string">
      The type of billing. Only `parent_billing` is supported. Optional.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="description" type="string">
  Description of the organization. Optional.
</ResponseField>

<ResponseField name="name" type="string">
  The name of the child organization, limited to 32 characters. Optional.
</ResponseField>

<ResponseField name="public_id" type="string">
  The `public_id` of the organization you are operating within. Optional.
</ResponseField>

<ResponseField name="settings" type="object">
  A JSON array of settings. Optional.
  <Expandable title="properties">
    <ResponseField name="private_widget_share" type="bool">
      Whether or not the organization users can share widgets outside of Datadog. Optional.
    </ResponseField>
    <ResponseField name="saml" type="object">
      Set the boolean property enabled to enable or disable single sign on with SAML. See the SAML documentation for more information about all SAML settings. Optional.
      <Expandable title="properties">
        <ResponseField name="enabled" type="bool">
          Whether or not SAML is enabled for this organization. Optional.
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="saml_autocreate_access_role" type="string">
      The access role of the user. Options are **st** (standard user), **adm** (admin user), or **ro** (read-only user). Optional.
    </ResponseField>
    <ResponseField name="saml_autocreate_users_domains" type="object">
      Has two properties, `enabled` (boolean) and `domains`, which is a list of domains without the @ symbol. Optional.
      <Expandable title="properties">
        <ResponseField name="domains" type="list(string)">
          List of domains where the SAML automated user creation is enabled. Optional.
        </ResponseField>
        <ResponseField name="enabled" type="bool">
          Whether or not the automated user creation based on SAML domain is enabled. Optional.
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="saml_can_be_enabled" type="bool">
      Whether or not SAML can be enabled for this organization. Optional.
    </ResponseField>
    <ResponseField name="saml_idp_endpoint" type="string">
      Identity provider endpoint for SAML authentication. Optional.
    </ResponseField>
    <ResponseField name="saml_idp_initiated_login" type="object">
      Has one property enabled (boolean). Optional.
      <Expandable title="properties">
        <ResponseField name="enabled" type="bool">
          Whether SAML IdP initiated login is enabled, learn more in the [SAML documentation](https://docs.datadoghq.com/account_management/saml/#idp-initiated-login). Optional.
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="saml_idp_metadata_uploaded" type="bool">
      Whether or not a SAML identity provider metadata file was provided to the Datadog organization. Optional.
    </ResponseField>
    <ResponseField name="saml_login_url" type="string">
      URL for SAML logging. Optional.
    </ResponseField>
    <ResponseField name="saml_strict_mode" type="object">
      Has one property enabled (boolean). Optional.
      <Expandable title="properties">
        <ResponseField name="enabled" type="bool">
          Whether or not the SAML strict mode is enabled. If true, all users must log in with SAML. Learn more on the [SAML Strict documentation](https://docs.datadoghq.com/account_management/saml/#saml-strict). Optional.
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="subscription" type="object">
  Subscription definition. Optional.
  <Expandable title="properties">
    <ResponseField name="type" type="string">
      The subscription type. Types available are `trial`, `free`, and `pro`. Optional.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="trial" type="bool">
  Only available for MSP customers. Allows child organizations to be created on a trial plan. Optional.
</ResponseField>
