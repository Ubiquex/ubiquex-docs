`datadog_automation_rule_response` is a real Datadog Case Management automation rule -- a trigger condition (a new case matching certain criteria) paired with an action (assign, tag, notify) that runs automatically so a security or ops team doesn't have to triage every case by hand.

## Properties

<ResponseField name="data" type="object" required>
  Data object for creating an automation rule. Required.
  <Expandable title="properties">
    <ResponseField name="attributes" type="object" required>
      Attributes required to create an automation rule. Required.
      <Expandable title="properties">
        <ResponseField name="action" type="object" required>
          Defines what happens when the rule triggers. Combines an action type with action-specific configuration data. Required.
          <Expandable title="properties">
            <ResponseField name="data" type="object" required>
              Configuration for the action to execute, dependent on the action type. Required.
              <Expandable title="properties">
                <ResponseField name="agent_type" type="string">
                  The type of AI agent to assign. Required when the action type is `ASSIGN_AGENT`. Optional.
                </ResponseField>
                <ResponseField name="assigned_agent_id" type="string">
                  The identifier of the AI agent to assign to the case. Required when the action type is `ASSIGN_AGENT`. Optional.
                </ResponseField>
                <ResponseField name="handle" type="string">
                  The handle of the Datadog workflow to execute. Required when the action type is `EXECUTE_WORKFLOW`. Optional.
                </ResponseField>
              </Expandable>
            </ResponseField>
            <ResponseField name="type" type="string" required>
              The type of automated action to perform when the rule triggers. `EXECUTE_WORKFLOW` runs a Datadog workflow; `ASSIGN_AGENT` assigns an AI agent to the case. Required.
            </ResponseField>
          </Expandable>
        </ResponseField>
        <ResponseField name="name" type="string" required>
          Name of the automation rule. Required.
        </ResponseField>
        <ResponseField name="state" type="string">
          Whether the automation rule is active. Enabled rules trigger on matching case events; disabled rules are inactive but preserve their configuration. Optional.
        </ResponseField>
        <ResponseField name="trigger" type="object" required>
          Defines when the rule activates. Combines a trigger type (the case event to listen for) with optional trigger data (conditions that narrow when the trigger fires). Required.
          <Expandable title="properties">
            <ResponseField name="data" type="object">
              Additional configuration for the trigger, dependent on the trigger type. For `STATUS_TRANSITIONED` triggers, specify `from_status_name` and `to_status_name`. For `ATTRIBUTE_VALUE_CHANGED` triggers, specify `field` and `change_type`. Optional.
              <Expandable title="properties">
                <ResponseField name="approval_type" type="string">
                  The approval outcome to match. Used with `CASE_REVIEW_APPROVED` triggers. Optional.
                </ResponseField>
                <ResponseField name="change_type" type="string">
                  The kind of attribute change to match. Allowed values: `VALUE_ADDED`, `VALUE_DELETED`, `ANY_CHANGES`. Used with `ATTRIBUTE_VALUE_CHANGED` triggers. Optional.
                </ResponseField>
                <ResponseField name="field" type="string">
                  The case attribute field name to monitor for changes. Used with `ATTRIBUTE_VALUE_CHANGED` triggers. Optional.
                </ResponseField>
                <ResponseField name="from_status_name" type="string">
                  The originating status name. Used with `STATUS_TRANSITIONED` triggers to match transitions from this status. Optional.
                </ResponseField>
                <ResponseField name="to_status_name" type="string">
                  The destination status name. Used with `STATUS_TRANSITIONED` triggers to match transitions to this status. Optional.
                </ResponseField>
              </Expandable>
            </ResponseField>
            <ResponseField name="type" type="string" required>
              The case event that activates the automation rule. Required.
            </ResponseField>
          </Expandable>
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="type" type="string" required>
      JSON:API resource type for case automation rules. Required.
    </ResponseField>
  </Expandable>
