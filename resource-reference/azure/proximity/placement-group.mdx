`azure_proximity_placement_group` pulls compute resources physically together in the same datacenter, the opposite goal of an availability set or zone, which deliberately spread VMs apart for resilience. It exists for workloads where network latency between tiers matters more than fault isolation -- a database tier and an application tier on different hardware types can still be pinned into the same proximity group. The group is a colocation constraint, not a capacity guarantee: it's pinned to a datacenter by whichever resource uses it first, and stays pinned until every resource in the group is stopped or deleted.
