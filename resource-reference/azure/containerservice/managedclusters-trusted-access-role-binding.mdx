`azure_containerservice_managedclusters_trusted_access_role_binding` grants another Azure resource's own system-assigned managed identity secure, RBAC-scoped access to an AKS cluster's own API server, without exposing the cluster to public networks.

## Properties

<ResponseField name="properties" type="object" required>
  Properties for trusted access role binding Required.
  <Expandable title="properties">
    <ResponseField name="provisioning_state" type="string">
      The current provisioning state of trusted access role binding. Computed by Microsoft Azure after `ship`.
    </ResponseField>
    <ResponseField name="roles" type="list(string)" required>
      A list of roles to bind, each item is a resource type qualified role name. For example: 'Microsoft.MachineLearningServices/workspaces/reader'. Required.
    </ResponseField>
    <ResponseField name="source_resource_id" type="string" required>
      The ARM resource ID of source resource that trusted access is configured for. Required.
