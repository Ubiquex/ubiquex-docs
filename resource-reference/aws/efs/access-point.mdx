`aws_efs_access_point` is a real, application-specific entry point into an `aws_efs_file_system`, enforcing its own POSIX user identity and a fixed root directory, so different applications sharing the same file system see only their own scoped directory rather than the file system's full root.

## Example

  <Tab title="Go">
    ```go
    package main

    import (
    	efs "github.com/ubiquex/ubx-sdk-aws/sdk/go/aws/efs"
    	ubx "github.com/ubiquex/ubx-sdk-go/runtime"
    )

    func main() {
    	ubx.Main(ubx.Stack("example", func() {
    		ubx.Intent(ubx.IntentInfo{Summary: "example own access point"})

    		ubx.Resource(efs.AccessPoint, "example", efs.AccessPointConfig{
    			FileSystemId:    "example",
    			AccessPointTags: []map[string]any{{"key": "example"}},
    			ClientToken:     "example",
    			PosixUser:       map[string]any{"gid": "example"},
    			RootDirectory:   map[string]any{"creation_info": map[string]any{"owner_gid": "example"}},
    		})
    	}))
    }
    ```

## Input properties

<ResponseField name="access_point_tags" type="list(object)">
  An array of key-value pairs to apply to this resource. For more information, see [Tag](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/aws-properties-resource-tags.html). Optional.
  <Expandable title="properties">
    <ResponseField name="key" type="string">
      The key of a tag in the access_point_tags list on the EFS access point, corresponding to the Key property of the CloudFormation AccessPointTags tag objects. Optional; if omitted, computed by AWS. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="value" type="string">
      The value of a tag applied to the EFS access point, used for metadata and resource categorization. Optional; if omitted, computed by AWS. **(AI-inferred)**
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="client_token" type="string">
  The opaque string specified in the request to ensure idempotent creation. Optional.
</ResponseField>

<ResponseField name="file_system_id" type="string" required>
  The ID of the EFS file system that the access point applies to. Accepts only the ID format for input when specifying a file system, for example ``fs-0123456789abcedf2``. Required.
</ResponseField>

<ResponseField name="posix_user" type="object">
  The full POSIX identity, including the user ID, group ID, and any secondary group IDs, on the access point that is used for all file system operations performed by NFS clients using the access point. Optional.
  <Expandable title="properties">
    <ResponseField name="gid" type="string" required>
      The POSIX group ID used for all file system operations using this access point. Required.
    </ResponseField>
    <ResponseField name="secondary_gids" type="list(string)">
      Secondary POSIX group IDs used for all file system operations using this access point. Optional.
    </ResponseField>
    <ResponseField name="uid" type="string" required>
      The POSIX user ID used for all file system operations using this access point. Required.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="root_directory" type="object">
  Specifies the directory on the Amazon EFS file system that the access point provides access to. The access point exposes the specified file system path as the root directory of your file system to applications using the access point. NFS clients using the access point can only access data in the access point's ``RootDirectory`` and its subdirectories. Optional.
  <Expandable title="properties">
    <ResponseField name="creation_info" type="object">
      Required if the ``RootDirectory`` &gt; ``Path`` specified does not exist. Specifies the POSIX IDs and permissions to apply to the access point's ``RootDirectory`` &gt; ``Path``. If the access point root directory does not exist, EFS creates it with these settings when a client connects to the access point. When specifying ``CreationInfo``, you must include values for all properties. Amazon EFS creates a root directory only if you have provided the CreationInfo: OwnUid, OwnGID, and permissions for the directory. If you do not provide this information, Amazon EFS does not create the root directory. If the root directory does not exist, attempts to mount using the access point will fail. If you do not provide ``CreationInfo`` and the specified ``RootDirectory`` does not exist, attempts to mount the file system using the access point will fail. Optional.
      <Expandable title="properties">
        <ResponseField name="owner_gid" type="string" required>
          Specifies the POSIX group ID to apply to the ``RootDirectory``. Accepts values from 0 to 2^32 (4294967295). Required.
        </ResponseField>
        <ResponseField name="owner_uid" type="string" required>
          Specifies the POSIX user ID to apply to the ``RootDirectory``. Accepts values from 0 to 2^32 (4294967295). Required.
        </ResponseField>
        <ResponseField name="permissions" type="string" required>
          Specifies the POSIX permissions to apply to the ``RootDirectory``, in the format of an octal number representing the file's mode bits. Required.
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="path" type="string">
      Specifies the path on the EFS file system to expose as the root directory to NFS clients using the access point to access the EFS file system. A path can have up to four subdirectories. If the specified path does not exist, you are required to provide the ``CreationInfo``. Optional.
    </ResponseField>
  </Expandable>
</ResponseField>
