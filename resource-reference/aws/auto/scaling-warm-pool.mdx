`aws_auto_scaling_warm_pool` keeps a pool of pre-initialized EC2 instances attached to an `aws_auto_scaling_auto_scaling_group` in a stopped or running state outside the group's own capacity count, so a scale-out event can pull an already-booted instance into service instead of waiting on a cold launch.

## Properties

<ResponseField name="auto_scaling_group_name" type="string" required>
  The name of the Auto Scaling group for which the warm pool is configured. Required. **(AI-inferred)**
</ResponseField>

<ResponseField name="instance_reuse_policy" type="object">
  Configures the instance reuse policy for the warm pool, which controls whether instances removed during scale-in are reused when the Auto Scaling group scales out. Optional. **(AI-inferred)**
  <Expandable title="properties">
    <ResponseField name="reuse_on_scale_in" type="bool">
      When true, instances that are scaled in from the Auto Scaling group are returned to the warm pool for reuse instead of being terminated. Optional. **(AI-inferred)**
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="max_group_prepared_capacity" type="number">
  Specifies the maximum number of instances that can be in the warm pool and the Auto Scaling group together, defaulting to the group's maximum capacity if not provided. Optional. **(AI-inferred)**
</ResponseField>

<ResponseField name="min_size" type="number">
  Specifies the minimum number of instances to maintain in the warm pool. Optional. **(AI-inferred)**
</ResponseField>

<ResponseField name="pool_state" type="string">
  Specifies whether instances in the warm pool are stopped (Stopped, so they do not incur instance charges) or running (Running, so they incur instance charges). Optional. **(AI-inferred)**
</ResponseField>
