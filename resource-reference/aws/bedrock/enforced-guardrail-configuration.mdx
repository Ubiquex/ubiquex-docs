`aws_bedrock_enforced_guardrail_configuration` designates a real `aws_bedrock_guardrail` from a management account to be automatically enforced across every member account and organizational unit in AWS Organizations, eliminating per-account guardrail configuration in favor of one control point. Cross-account safeguards for Bedrock Guardrails reached general availability in April 2026, roughly four months ago.

## Input properties

<ResponseField name="guardrail_identifier" type="string" required>
  Identifier for the guardrail, could be the ID or the ARN Required.
</ResponseField>

<ResponseField name="guardrail_version" type="string" required>
  Numerical guardrail version (not DRAFT) Required.
</ResponseField>

<ResponseField name="model_enforcement" type="object">
  Model-specific information for the enforced guardrail configuration. If not present, the configuration is enforced on all models Optional.
  <Expandable title="properties">
    <ResponseField name="excluded_models" type="list(string)" required>
      Models to exclude from enforcement. If a model is in both lists, it is excluded Required.
    </ResponseField>
    <ResponseField name="included_models" type="list(string)" required>
      Models to enforce the guardrail on Required.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="selective_content_guarding" type="object">
  Selective content guarding controls for enforced guardrails Optional.
  <Expandable title="properties">
    <ResponseField name="messages" type="string">
      Selective guarding mode for user messages Optional.
    </ResponseField>
    <ResponseField name="system" type="string">
      Selective guarding mode for system prompts Optional.
    </ResponseField>
  </Expandable>
</ResponseField>
