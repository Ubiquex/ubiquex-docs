`aws_lambda_code_signing_config` defines a real policy that requires deployed Lambda function code to be signed by a trusted AWS Signer profile before Lambda will accept it, rejecting unsigned or tampered deployment packages.

## Input properties

<ResponseField name="allowed_publishers" type="object" required>
  When the CodeSigningConfig is later on attached to a function, the function code will be expected to be signed by profiles from this list Required.
  <Expandable title="properties">
    <ResponseField name="signing_profile_version_arns" type="list(string)" required>
      List of Signing profile version Arns Required.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="code_signing_policies" type="object">
  Policies to control how to act if a signature is invalid Optional.
  <Expandable title="properties">
    <ResponseField name="untrusted_artifact_on_deployment" type="string" required>
      Indicates how Lambda operations involve updating the code artifact will operate. Default to Warn if not provided Required.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="description" type="string">
  A description of the CodeSigningConfig Optional.
</ResponseField>

<ResponseField name="tags" type="list(object)">
  A list of tags to apply to CodeSigningConfig resource Optional.
  <Expandable title="properties">
    <ResponseField name="key" type="string">
