`aws_io_t_job_template` is a real, reusable configuration, rollout rate, timeout, abort criteria, that an `aws_io_t_job` can be created from, so the same recurring job shape doesn't need to be configured from scratch every time.

## Input properties

<ResponseField name="abort_config" type="object">
  The criteria that determine when and how a job abort takes place. Optional.
  <Expandable title="properties">
    <ResponseField name="criteria_list" type="list(object)" required>
      Specifies a list of criteria that define when a running IoT job is aborted, including the action (CANCEL or CONTINUE), failure type (FAILED or TIMED_OUT), minimum number of executed things, and threshold percentage. Required. **(AI-inferred)**
      <Expandable title="properties">
        <ResponseField name="action" type="string">
          The action to take when the abort criteria threshold is reached, which for AWS IoT Job templates is always 'CANCEL'. Optional; if omitted, computed by AWS. **(AI-inferred)**
        </ResponseField>
        <ResponseField name="failure_type" type="string">
          Specifies the type of job execution failure (e.g., FAILED or TIMED_OUT) that triggers this abort criterion in the IoT job template's abort configuration. Optional; if omitted, computed by AWS. **(AI-inferred)**
        </ResponseField>
        <ResponseField name="min_number_of_executed_things" type="number">
          Specifies the minimum number of things that must have executed the job before the thresholdPercentage in this abort criterion can trigger an abort action. Optional; if omitted, computed by AWS. **(AI-inferred)**
        </ResponseField>
        <ResponseField name="threshold_percentage" type="number">
          The threshold percentage of total job executions that must fail with the specified failure type in order to trigger the job abort, expressed as a number between 0 and 100. Optional; if omitted, computed by AWS. **(AI-inferred)**
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="description" type="string" required>

<ResponseField name="job_executions_retry_config" type="object">
  Specifies the retry configuration for failed job executions, including the retry criteria that define which failure types can be retried and the maximum number of retry attempts. Optional. **(AI-inferred)**
  <Expandable title="properties">
    <ResponseField name="retry_criteria_list" type="list(object)">
      A list of retry criteria, each specifying a failure type (FAILED, TIMED_OUT, or ALL) and the maximum number of retry attempts for job executions that match that failure type, used to configure automatic retries for the job template. Optional. **(AI-inferred)**
      <Expandable title="properties">
        <ResponseField name="failure_type" type="string">
          The type of job execution failure that triggers a retry, such as FAILED, TIMED_OUT, or ALL, used in the retry criteria for an AWS IoT job template. Optional; if omitted, computed by AWS. **(AI-inferred)**
        </ResponseField>
        <ResponseField name="number_of_retries" type="number">
          Specifies the maximum number of retry attempts for a job execution when it fails with the associated failure type, after which the execution is considered failed. Optional; if omitted, computed by AWS. **(AI-inferred)**
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="job_executions_rollout_config" type="object">
  Allows you to create a staged rollout of a job. Optional.
  <Expandable title="properties">
    <ResponseField name="exponential_rollout_rate" type="object">
      Allows you to create an exponential rate of rollout for a job. Optional.
      <Expandable title="properties">
        <ResponseField name="base_rate_per_minute" type="number" required>
          The number of IoT things that are notified of the job per minute at the start of the rollout, before any rate increases are applied. Required. **(AI-inferred)**
        </ResponseField>
        <ResponseField name="increment_factor" type="number" required>
          The multiplier applied to the base job execution rollout rate at each interval defined by the rate increase criteria, causing the rate of job executions to grow exponentially over time. Required. **(AI-inferred)**
        </ResponseField>
        <ResponseField name="rate_increase_criteria" type="object" required>
          Specifies the threshold of notified or succeeded job executions that triggers an increase in the job rollout rate during exponential rollout. Required. **(AI-inferred)**
          <Expandable title="properties">
            <ResponseField name="number_of_notified_things" type="number">
              The number of notified things at which the job rollout rate will be increased as part of the exponential rollout configuration. Optional. **(AI-inferred)**
            </ResponseField>
            <ResponseField name="number_of_succeeded_things" type="number">
              The number of succeeded job executions (things) that must be reached before the rollout rate is increased exponentially for the remaining things in the job. Optional. **(AI-inferred)**
            </ResponseField>
          </Expandable>
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="maximum_per_minute" type="number">
      Specifies the maximum number of job executions that AWS IoT starts per minute for this job template's rollout, throttling the rate at which the job is deployed to devices. Optional. **(AI-inferred)**
    </ResponseField>
  </Expandable>
</ResponseField>
