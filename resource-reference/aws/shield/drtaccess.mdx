`aws_shield_drtaccess` grants the real AWS DDoS Response Team access to an account's resources and, optionally, its own support cases and account details, so the DRT can assist directly during an active `aws_shield_protection` incident under AWS Shield Advanced.

## Example

<Tabs>
  <Tab title="Go">
    ```go
    package main

    import (
    	shield "github.com/ubiquex/ubx-sdk-aws/sdk/go/aws/shield"
    	ubx "github.com/ubiquex/ubx-sdk-go/runtime"
    )

    func main() {
    	ubx.Main(ubx.Stack("example", func() {
    		ubx.Intent(ubx.IntentInfo{Summary: "example own drtaccess"})

    		ubx.Resource(shield.Drtaccess, "example", shield.DrtaccessConfig{
    			RoleArn:       "arn:aws:iam::123456789012:policy/example",
    			LogBucketList: []string{"example"},
    		})
    	}))
    }
    ```

## Input properties

<ResponseField name="log_bucket_list" type="list(string)">
  Authorizes the Shield Response Team (SRT) to access the specified Amazon S3 bucket containing log data such as Application Load Balancer access logs, CloudFront logs, or logs from third party sources. You can associate up to 10 Amazon S3 buckets with your subscription. Optional.
</ResponseField>

<ResponseField name="role_arn" type="string" required>
  Authorizes the Shield Response Team (SRT) using the specified role, to access your AWS account to assist with DDoS attack mitigation during potential attacks. This enables the SRT to inspect your AWS WAF configuration and create or update AWS WAF rules and web ACLs. Required.
</ResponseField>

## Output properties

<ResponseField name="account_id" type="string">
  The AWS account ID of the account that has configured the Shield Response Team (DRT) access, automatically populated with the current account ID. Computed by AWS after `ship`. **(AI-inferred)**
</ResponseField>
