`aws_guard_duty_custom_detection_rule_association` attaches a real GuardDuty custom detection rule, identified by its own catalog rule_id, to an `aws_guard_duty_detector` for a specific account. Mode controls whether the rule actually generates findings (LIVE) or only evaluates silently for testing (DRY_RUN) before a caller turns it loose. The rule's own logic is authored and cataloged separately; this resource only manages whether and how it applies to one detector.

## Input properties

<ResponseField name="mode" type="string" required>
  Whether the rule runs in LIVE mode (generates findings) or DRY_RUN mode (evaluates without generating findings). Required.
</ResponseField>

<ResponseField name="rule_id" type="string" required>
  The catalog identifier of the custom detection rule to associate. Required.
</ResponseField>

<ResponseField name="tags" type="list(object)">
