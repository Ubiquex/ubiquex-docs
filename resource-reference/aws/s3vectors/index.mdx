`aws_s3_vectors_index` creates a real vector index within an S3 vector bucket, storing and querying up to two billion embeddings per index natively in S3 for similarity search, commonly used as the storage layer behind a Bedrock knowledge base rather than a separate vector database. Amazon S3 Vectors reached general availability in December 2025, roughly eight months ago, so behavior here is verified live rather than assumed from general knowledge.

## Input properties

<ResponseField name="data_type" type="string" required>
  The data type of the vectors to be inserted into the vector index. Required.
</ResponseField>

<ResponseField name="dimension" type="number" required>
  The dimensions of the vectors to be inserted into the vector index. Required.
</ResponseField>

<ResponseField name="distance_metric" type="string" required>
  The distance metric to be used for similarity search. Required.
</ResponseField>

<ResponseField name="encryption_configuration" type="object">
  The encryption configuration for the index. Optional.
  <Expandable title="properties">
    <ResponseField name="kms_key_arn" type="string">
      AWS Key Management Service (KMS) customer managed key ID to use for the encryption configuration. This parameter is allowed if and only if sseType is set to aws:kms Optional.
    </ResponseField>
    <ResponseField name="sse_type" type="string">
      Defines the server-side encryption type for index encryption configuration. Defaults to the parent vector bucket's encryption settings when unspecified. Optional.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="index_name" type="string">
  The name of the vector index to create. Optional.
</ResponseField>

<ResponseField name="metadata_configuration" type="object">
  The metadata configuration for the vector index. Optional.
  <Expandable title="properties">
    <ResponseField name="non_filterable_metadata_keys" type="list(string)">
      Non-filterable metadata keys allow you to enrich vectors with additional context during storage and retrieval. Unlike default metadata keys, these keys cannot be used as query filters. Non-filterable metadata keys can be retrieved but cannot be searched, queried, or filtered. You can access non-filterable metadata keys of your vectors after finding the vectors. Optional.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="tags" type="list(object)">
  User tags (key-value pairs) to associate with the index. Optional.
  <Expandable title="properties">
    <ResponseField name="key" type="string">
      Defines the user-supplied key of a tag attached to the S3 Vectors Index resource, which is used to organize and identify the index through metadata and cost-allocation tags. Optional; if omitted, computed by AWS. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="value" type="string">
      Optional; if omitted, computed by AWS.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="vector_bucket_arn" type="string">
  The Amazon Resource Name (ARN) of the vector bucket. Optional.
</ResponseField>

<ResponseField name="vector_bucket_name" type="string">
  The name of the vector bucket that contains the vector index. Optional.
</ResponseField>

  The Amazon Resource Name (ARN) of the index Computed by AWS after `ship`.
