`aws_io_t_resource_specific_logging` configures real, per-resource IoT Core logging levels, overriding the account's own default logging level for a specific thing, thing group, or topic when only that resource's traffic needs closer visibility.

## Example

<Tabs>
  <Tab title="Go">
    ```go
    package main

    import (
    	iot "github.com/ubiquex/ubx-sdk-aws/sdk/go/v2/aws/iot"
    	ubx "github.com/ubiquex/ubx-sdk-go/runtime"
    )

    func main() {
    	ubx.Main(ubx.Stack("example", func() {
    		ubx.Intent(ubx.IntentInfo{Summary: "example own t resource specific logging"})

    		ubx.Resource(iot.ResourceSpecificLogging, "example", iot.ResourceSpecificLoggingConfig{
    			LogLevel:   "example",
    			TargetName: "example-target-name",
    			TargetType: "example",
    		})
    	}))
    }
    ```

## Input properties

<ResponseField name="log_level" type="string" required>
  The log level for a specific target. Valid values are: ERROR, WARN, INFO, DEBUG, or DISABLED. Required.
</ResponseField>

<ResponseField name="target_name" type="string" required>
  The target name. Required.
</ResponseField>

<ResponseField name="target_type" type="string" required>
  The target type. Value must be THING_GROUP, CLIENT_ID, SOURCE_IP, PRINCIPAL_ID, or EVENT_TYPE. Required.
</ResponseField>

## Output properties

<ResponseField name="target_id" type="string">
  Unique Id for a Target (TargetType:TargetName), this will be internally built to serve as primary identifier for a log target. Computed by AWS after `ship`.
</ResponseField>
