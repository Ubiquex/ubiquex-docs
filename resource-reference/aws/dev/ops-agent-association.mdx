`aws_dev_ops_agent_association` connects a real external service, GitHub, Slack, ServiceNow, Dynatrace, an AWS account, and more, to an `aws_dev_ops_agent_agent_space`, so the DevOps Agent operator app can actually read from and act on that service.

## Input properties

<ResponseField name="agent_space_id" type="string" required>
  The unique identifier of the AgentSpace Required.
</ResponseField>

<ResponseField name="configuration" type="any" required>
  The configuration that directs how AgentSpace interacts with the given service Required.
</ResponseField>

<ResponseField name="linked_association_ids" type="list(string)">
  Set of linked association IDs for parent-child relationships Optional.
</ResponseField>

<ResponseField name="service_id" type="string" required>
  The identifier for the associated service. For SourceAws and Aws configurations, this must be 'aws'. For all other service types, this is a UUID generated from the RegisterService command Required.
</ResponseField>

## Output properties

<ResponseField name="association_id" type="string">
  The unique identifier of the association Computed by AWS after `ship`.
</ResponseField>

<ResponseField name="created_at" type="string">
  The timestamp when the association was created Computed by AWS after `ship`.
</ResponseField>

<ResponseField name="updated_at" type="string">
  The timestamp when the association was last updated Computed by AWS after `ship`.
</ResponseField>
