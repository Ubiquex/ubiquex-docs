`aws_direct_connect_lag` bundles multiple `aws_direct_connect_connection`s into a single, real logical interface with combined bandwidth and automatic failover, the Direct Connect equivalent of link aggregation on a physical switch.

## Input properties

<ResponseField name="connections_bandwidth" type="string" required>
  The bandwidth of the individual physical dedicated connections bundled by the LAG. Required.
</ResponseField>

<ResponseField name="lag_name" type="string" required>
  The name of the LAG. Required.
</ResponseField>

<ResponseField name="location" type="string" required>
  The location for the LAG. Required.
</ResponseField>

<ResponseField name="minimum_links" type="number">
  The minimum number of physical dedicated connections that must be operational for the LAG itself to be operational. Optional.
</ResponseField>

<ResponseField name="provider_name" type="string">
  The name of the service provider associated with the requested LAG. Optional.
</ResponseField>

<ResponseField name="request_macsec" type="bool">
  Indicates whether you want the LAG to support MAC Security (MACsec). Optional.
</ResponseField>

<ResponseField name="tags" type="list(object)">
  The tags associated with the LAG. Optional.
  <Expandable title="properties">
    <ResponseField name="key" type="string">
      Specifies the key of a tag attached to the AWS Direct Connect LAG, used for cost allocation, access control, and resource organization. Optional; if omitted, computed by AWS. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="value" type="string">
      The value portion of a tag key-value pair attached to the Direct Connect LAG, used for metadata and resource management. Optional; if omitted, computed by AWS. **(AI-inferred)**
    </ResponseField>
  </Expandable>
</ResponseField>
