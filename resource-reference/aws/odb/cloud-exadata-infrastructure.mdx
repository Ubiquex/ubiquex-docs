`aws_odb_cloud_exadata_infrastructure` provisions a real Oracle Exadata infrastructure, physical Exadata compute and storage, within Oracle Database@AWS, the underlying hardware layer that `aws_odb_cloud_vm_cluster`s are created on top of. Oracle Database@AWS runs on infrastructure managed by Oracle Cloud Infrastructure but delivered from within AWS's own data centers.

## Input properties

<ResponseField name="availability_zone" type="string">
  The name of the Availability Zone (AZ) where the Exadata infrastructure is located. Optional.
</ResponseField>

<ResponseField name="availability_zone_id" type="string">
  The AZ ID of the AZ where the Exadata infrastructure is located. Optional.
</ResponseField>

<ResponseField name="compute_count" type="number">
  The number of database servers for the Exadata infrastructure. Optional.
</ResponseField>

<ResponseField name="customer_contacts_to_send_to_oci" type="list(object)">
  The email addresses of contacts to receive notification from Oracle about maintenance updates for the Exadata infrastructure. Optional.
  <Expandable title="properties">
    <ResponseField name="email" type="string">
      The email address of a customer contact that Oracle Cloud Infrastructure (OCI) will send notifications to regarding this Exadata infrastructure. Optional; if omitted, computed by AWS. **(AI-inferred)**
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="database_server_type" type="string">
  The database server model type of the Exadata infrastructure. For the list of valid model names, use the ListDbSystemShapes operation. Optional.
</ResponseField>

<ResponseField name="display_name" type="string">
  The user-friendly name for the Exadata infrastructure. Optional.
</ResponseField>

<ResponseField name="maintenance_window" type="object">
  The scheduling details for the maintenance window. Patching and system updates take place during the maintenance window. Optional.
  <Expandable title="properties">
    <ResponseField name="custom_action_timeout_in_mins" type="number">
      The timeout duration for custom actions in minutes. Optional.
    </ResponseField>
    <ResponseField name="days_of_week" type="list(string)">
      The days of the week when maintenance can be performed. Optional.
    </ResponseField>
    <ResponseField name="hours_of_day" type="list(number)">
      The hours of the day when maintenance can be performed. Optional.
    </ResponseField>
    <ResponseField name="is_custom_action_timeout_enabled" type="bool">
      Indicates whether custom action timeout is enabled. Optional.
    </ResponseField>
    <ResponseField name="lead_time_in_weeks" type="number">
      The lead time in weeks before the maintenance window. Optional.
    </ResponseField>
    <ResponseField name="months" type="list(string)">
      The months when maintenance can be performed. Optional.
    </ResponseField>
    <ResponseField name="patching_mode" type="string">
      The patching mode for the maintenance window. Optional.
    </ResponseField>
    <ResponseField name="preference" type="string">
      The preference for the maintenance window scheduling. Optional.
    </ResponseField>
    <ResponseField name="weeks_of_month" type="list(number)">
      The weeks of the month when maintenance can be performed. Optional.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="shape" type="string">
  The model name of the Exadata infrastructure. Optional.
</ResponseField>

<ResponseField name="storage_count" type="number">
  The number of storage servers that are activated for the Exadata infrastructure. Optional.
</ResponseField>

<ResponseField name="storage_server_type" type="string">

</ResponseField>

<ResponseField name="tags" type="list(object)">

    <ResponseField name="value" type="string">
      Optional; if omitted, computed by AWS.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="compute_model" type="string">
  The OCI model compute model used when you create or clone an instance: ECPU or OCPU. An ECPU is an abstracted measure of compute resources. ECPUs are based on the number of cores elastically allocated from a pool of compute and storage servers. An OCPU is a legacy physical measure of compute resources. OCPUs are based on the physical core of a processor with hyper-threading enabled. Computed by AWS after `ship`.
