`aws_odb_cloud_vm_cluster` creates a real Exadata VM cluster on top of an `aws_odb_cloud_exadata_infrastructure`, the compute layer that Oracle databases actually run on within Oracle Database@AWS, requiring both an Exadata infrastructure and an `aws_odb_network` to already exist.

## Example

<Tabs>
  <Tab title="Go">
    ```go
    package main

    import (
    	odb "github.com/ubiquex/ubx-sdk-aws/sdk/go/v2/aws/odb"
    	ubx "github.com/ubiquex/ubx-sdk-go/runtime"
    )

    func main() {
    	ubx.Main(ubx.Stack("example", func() {
    		ubx.Intent(ubx.IntentInfo{Summary: "example own cloud vm cluster"})

    		ubx.Resource(odb.CloudVmCluster, "example", odb.CloudVmClusterConfig{
    			CloudExadataInfrastructureId: "example",
    			ClusterName:                  "example-cluster-name",
    			CpuCoreCount:                 1,
    			DataCollectionOptions:        map[string]any{"is_diagnostics_events_enabled": true},
    			DataStorageSizeInTbs:         1,
    			DbNodeStorageSizeInGbs:       1,
    			DbServers:                    []string{"example"},
    			DisplayName:                  "example-display-name",
    		})
    	}))
    }
    ```

## Input properties

<ResponseField name="compute_model" type="string">
  The OCI model compute model used when you create or clone an instance: ECPU or OCPU. An ECPU is an abstracted measure of compute resources. ECPUs are based on the number of cores elastically allocated from a pool of compute and storage servers. An OCPU is a legacy physical measure of compute resources. OCPUs are based on the physical core of a processor with hyper-threading enabled. Computed by AWS after `ship`.
