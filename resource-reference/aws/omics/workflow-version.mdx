`aws_omics_workflow_version` publishes a real, immutable version of an `aws_omics_workflow`'s definition, letting runs pin to a specific version rather than always using the workflow's current definition.

## Example

  <Tab title="Go">
    ```go

    // go.mod: replace github.com/ubiquex/ubx-sdk-aws/sdk/go => ./local-sdk/aws/sdk/go

    import (
    	omics "github.com/ubiquex/ubx-sdk-aws/sdk/go/aws/omics"
    	ubx "github.com/ubiquex/ubx-sdk-go/runtime"
    )

    func main() {
    	ubx.Main(ubx.Stack("example", func() {
    		ubx.Intent(ubx.IntentInfo{Summary: "example own workflow version"})

    		ubx.Resource(omics.WorkflowVersion, "example", omics.WorkflowVersionConfig{
    			VersionName:             "example-version-name",
    			WorkflowId:              "example",
    			Accelerators:            "example",
    			ContainerRegistryMap:    map[string]any{"image_mappings": []map[string]any{{"destination_image": "example"}}},

    			DefinitionRepository:    map[string]any{"connection_arn": "example"},
    			DefinitionUri:           "example",
    			Description:             "Managed by ubx.",
    		})
    	}))
    }
    ```

## Input properties

<ResponseField name="accelerators" type="string">
  Specifies a comma-separated list of accelerator types (such as GPU) that are available to tasks in this workflow version, controlling whether GPU-accelerated compute resources can be used. Optional. **(AI-inferred)**
</ResponseField>

<ResponseField name="container_registry_map" type="object">
  Maps container names to the registry URIs from which the workflow's container images are pulled, enabling customization of image sources (e.g., private or custom registries) for the workflow version. Optional. **(AI-inferred)**
  <Expandable title="properties">
    <ResponseField name="image_mappings" type="list(object)">
      The image_mappings field defines a list of container image mappings that link container names used in the workflow definition to their corresponding image URIs in the container registry map of the AWS Omics workflow version. Optional. **(AI-inferred)**
      <Expandable title="properties">
        <ResponseField name="destination_image" type="string">
          Specifies the destination container image URI that a source image from the container registry map is overridden with for this workflow version's runtime. Optional; if omitted, computed by AWS. **(AI-inferred)**
        </ResponseField>
        <ResponseField name="source_image" type="string">
          Defines the original container image reference (e.g., `myorg/myapp:latest`) that appears in the workflow definition and is mapped to a destination image for the container registry. Optional; if omitted, computed by AWS. **(AI-inferred)**
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="registry_mappings" type="list(object)">
      Optional.
      <Expandable title="properties">
        <ResponseField name="ecr_account_id" type="string">
          The AWS account ID associated with the Amazon ECR container registry entry in the container registry map of the workflow version. Optional; if omitted, computed by AWS. **(AI-inferred)**
        </ResponseField>
        <ResponseField name="ecr_repository_prefix" type="string">
          Specifies the ECR repository prefix (including AWS account ID and region) that maps to a container registry name, allowing the workflow version to resolve and pull container images from Amazon ECR. Optional; if omitted, computed by AWS. **(AI-inferred)**
        </ResponseField>
        <ResponseField name="upstream_registry_url" type="string">
          Optional; if omitted, computed by AWS.
        </ResponseField>
        <ResponseField name="upstream_repository_prefix" type="string">
          Optional; if omitted, computed by AWS.
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="container_registry_map_uri" type="string">
  For an AWS Omics workflow version, this optional string is the URI (such as an S3 URI) to a file containing the container registry map that overrides the default container image registry locations for the workflow steps. Optional. **(AI-inferred)**
</ResponseField>

<ResponseField name="definition_repository" type="object">
  Specifies the repository (e.g., an S3 URI or Git location) from which the workflow definition for this Omics workflow version is retrieved. Optional. **(AI-inferred)**
  <Expandable title="properties">
    <ResponseField name="connection_arn" type="string">
      The ARN of the AWS CodeStar Connections connection used to access the git repository that contains the workflow definition. Optional. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="exclude_file_patterns" type="list(string)">
      A list of file patterns (e.g., glob patterns) that should be excluded from consideration when loading workflow definition files from the configured source repository in the definition_repository block. Optional. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="full_repository_id" type="string">
      The full identifier of the repository that contains the workflow definition, used to locate the source file when the definition is fetched from a repository. Optional. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="source_reference" type="object">
      Identifies the specific revision (such as a Git branch, tag, or commit SHA) within the definition repository that this workflow version points to, determining the exact workflow definition source. Optional. **(AI-inferred)**
      <Expandable title="properties">
        <ResponseField name="type" type="string">
          The type of source repository (either 'GIT' or 'S3') that contains the workflow definition, used with the source reference to specify which version of the definition to use. Optional. **(AI-inferred)**
        </ResponseField>
        <ResponseField name="value" type="string">
          Optional.
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="definition_uri" type="string">
  The S3 URI (or other supported location) where the workflow definition file (e.g., a WDL or Nextflow script) is stored, used to specify the execution logic for this workflow version when the definition is not provided inline. Optional. **(AI-inferred)**
</ResponseField>

<ResponseField name="description" type="string">
  The description of the workflow version, used to provide a human-readable summary or note about the specific version of the AWS Omics workflow. Optional. **(AI-inferred)**
</ResponseField>

<ResponseField name="engine" type="string">
  Specifies the workflow engine used by this version, such as WDL or Nextflow. Optional. **(AI-inferred)**
</ResponseField>

<ResponseField name="main" type="string">
  Specifies the main workflow script file (e.g., a WDL file or Nextflow main.nf) within the workflow source that serves as the entry point for the workflow version. Optional. **(AI-inferred)**
</ResponseField>

<ResponseField name="parameter_template" type="any">
  Specifies the template of input parameters for the workflow, mapping each parameter name to its configuration (e.g., data type, required flag) as defined by the workflow version. Optional. **(AI-inferred)**
</ResponseField>

<ResponseField name="parameter_template_path" type="string">
  Path to the primary workflow parameter template JSON file inside the repository Optional.
</ResponseField>

<ResponseField name="readme_markdown" type="string">
  The markdown content for the workflow's README file. This provides documentation and usage information for users of the workflow. Optional.
</ResponseField>

<ResponseField name="readme_path" type="string">
  The path to the workflow README markdown file within the repository. This file provides documentation and usage information for the workflow. If not specified, the README.md file from the root directory of the repository will be used. Optional.
</ResponseField>

<ResponseField name="readme_uri" type="string">
  The S3 URI of the README file for the workflow. This file provides documentation and usage information for the workflow. The S3 URI must begin with s3://USER-OWNED-BUCKET/. The requester must have access to the S3 bucket and object. The max README content length is 500 KiB. Optional.
</ResponseField>

<ResponseField name="storage_capacity" type="number">
  Specifies the storage capacity in gigabytes for the workflow, controlling the amount of data storage available during workflow runs. Optional. **(AI-inferred)**
</ResponseField>

<ResponseField name="storage_type" type="string">
  Determines whether the workflow version uses static or dynamic task-storage allocation (STATIC or DYNAMIC, with DYNAMIC as the default) for AWS Omics run tasks. Optional. **(AI-inferred)**
</ResponseField>

<ResponseField name="tags" type="any">
  A map of resource tags Optional.
</ResponseField>

<ResponseField name="version_name" type="string" required>
  The version_name field assigns a user-defined name to this version of the Omics workflow, which must be unique among all versions of the same workflow. Required. **(AI-inferred)**
</ResponseField>

<ResponseField name="workflow_bucket_owner_id" type="string">
  Specifies the AWS account ID that owns the S3 bucket containing the workflow definition files, which is required to grant cross-account access when the bucket is owned by a different account. Optional. **(AI-inferred)**
</ResponseField>

<ResponseField name="workflow_id" type="string" required>
  The unique identifier of the parent Omics workflow to which this workflow version belongs. Required. **(AI-inferred)**
</ResponseField>

## Output properties

<ResponseField name="arn" type="string">
  The Amazon Resource Name (ARN) that uniquely identifies this Omics workflow version. Computed by AWS after `ship`. **(AI-inferred)**
</ResponseField>

<ResponseField name="creation_time" type="string">
  The timestamp (string in ISO 8601 format) when this workflow version was created, as returned by AWS HealthOmics. Computed by AWS after `ship`. **(AI-inferred)**
</ResponseField>

<ResponseField name="status" type="string">
  The current lifecycle status of the workflow version (e.g., CREATING, ACTIVE, UPDATING, DELETING, or FAILED), as determined by AWS HealthOmics. Computed by AWS after `ship`. **(AI-inferred)**
</ResponseField>

<ResponseField name="type" type="string">
  The workflow engine type (such as WDL or Nextflow) for this Omics workflow version, automatically assigned by the service when the version is created. Computed by AWS after `ship`. **(AI-inferred)**
</ResponseField>

<ResponseField name="uuid" type="string">
  Computed by AWS after `ship`.
</ResponseField>
