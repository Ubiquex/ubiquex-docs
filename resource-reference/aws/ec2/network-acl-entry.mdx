`aws_ec2_network_acl_entry` defines one real, numbered, stateless allow or deny rule inside a network ACL, evaluated in rule-number order, the actual, individually addressable rule resource within a network ACL's broader rule set.

## Input properties

<ResponseField name="cidr_block" type="string">
  The IPv4 CIDR range to allow or deny, in CIDR notation (for example, 172.16.0.0/24). Requirement is conditional: You must specify the CidrBlock or Ipv6CidrBlock property Optional.
</ResponseField>

<ResponseField name="egress" type="bool">
  Indicates whether this is an egress rule (rule is applied to traffic leaving the subnet) Optional.
</ResponseField>

<ResponseField name="icmp" type="object">
  Specifies the ICMP type and code for the network ACL rule when the protocol is ICMP or ICMPv6, used to match specific ICMP traffic patterns. Optional. **(AI-inferred)**
  <Expandable title="properties">
    <ResponseField name="code" type="number">
      The ICMP code number, used to filter ICMP traffic in a network ACL entry, where it must be specified when the ICMP type is set to a specific value (e.g., 0 for echo request) rather than -1. Optional. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="type" type="number">
      The ICMP type number for the ICMP protocol, used when the protocol is set to ICMP (e.g., 8 for echo request). Optional. **(AI-inferred)**
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="ipv6_cidr_block" type="string">
  The IPv6 network range to allow or deny, in CIDR notation (for example 2001:db8:1234:1a00::/64) Optional.
</ResponseField>

<ResponseField name="network_acl_id" type="string" required>
  The ID of the network ACL Required.
</ResponseField>

<ResponseField name="port_range" type="object">
  Specifies the inclusive lower and upper bounds of the port range to match for the network ACL rule, typically used when the protocol is TCP or UDP. Optional. **(AI-inferred)**
  <Expandable title="properties">
    <ResponseField name="from" type="number">
      The starting (lower) port number of the TCP or UDP port range that this network ACL entry rule applies to, used together with the 'to' value to define the range of allowed or denied destination ports. Optional. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="to" type="number">
      Specifies the highest port number in the inclusive range of ports that this network ACL entry applies to, paired with the port_range.from value to define the upper boundary of allowed or denied traffic. Optional. **(AI-inferred)**
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="protocol" type="number" required>
  The protocol number. A value of "-1" means all protocols. If you specify "-1" or a protocol number other than "6" (TCP), "17" (UDP), or "1" (ICMP), traffic on all ports is allowed, regardless of any ports or ICMP types or codes that you specify. If you specify protocol "58" (ICMPv6) and specify an IPv4 CIDR block, traffic for all ICMP types and codes allowed, regardless of any that you specify. If you specify protocol "58" (ICMPv6) and specify an IPv6 CIDR block, you must specify an ICMP type and code Required.
</ResponseField>

<ResponseField name="rule_action" type="string" required>
  Indicates whether to allow or deny the traffic that matches the rule Required.
</ResponseField>

<ResponseField name="rule_number" type="number" required>
  Rule number to assign to the entry, such as 100. ACL entries are processed in ascending order by rule number. Entries can't use the same rule number unless one is an egress rule and the other is an ingress rule Required.
</ResponseField>

## Output properties

<ResponseField name="id" type="string">
  A computed identifier that combines the network ACL ID and rule number to uniquely represent this network ACL entry. Computed by AWS after `ship`. **(AI-inferred)**
</ResponseField>
