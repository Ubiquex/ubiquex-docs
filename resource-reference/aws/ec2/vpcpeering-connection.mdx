`aws_ec2_vpcpeering_connection` directly connects two VPCs' own private IP address spaces, letting instances in each communicate as if on the same network, without a transit gateway, a VPN, or traffic ever leaving AWS's own backbone.

## Input properties

<ResponseField name="assume_role_region" type="string">
  The Region code to use when calling Security Token Service (STS) to assume the PeerRoleArn, if provided. Optional.
</ResponseField>

<ResponseField name="peer_owner_id" type="string">
  The AWS account ID of the owner of the accepter VPC. Optional.
</ResponseField>

<ResponseField name="peer_region" type="string">
  The Region code for the accepter VPC, if the accepter VPC is located in a Region other than the Region in which you make the request. Optional.
</ResponseField>

<ResponseField name="peer_role_arn" type="string">
  The Amazon Resource Name (ARN) of the VPC peer role for the peering connection in another AWS account. Optional.
</ResponseField>

<ResponseField name="peer_vpc_id" type="string" required>
  The ID of the VPC with which you are creating the VPC peering connection. You must specify this parameter in the request. Required.
</ResponseField>

<ResponseField name="tags" type="list(object)">
