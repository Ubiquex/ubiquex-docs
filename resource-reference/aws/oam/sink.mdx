`aws_oam_sink` creates a real attachment point in a monitoring account under CloudWatch Observability Access Manager, the resource that an `aws_oam_link` from a source account actually connects to; a sink is managed by the monitoring account, one per Region, and must exist along with its own sink policy before any source account can link to it.

## Example

<Tabs>
  <Tab title="Go">
    ```go
    package main

    import (
    	oam "github.com/ubiquex/ubx-sdk-aws/sdk/go/aws/oam"
    	ubx "github.com/ubiquex/ubx-sdk-go/runtime"
    )

    func main() {
    	ubx.Main(ubx.Stack("example", func() {
    		ubx.Intent(ubx.IntentInfo{Summary: "example own sink"})

    		ubx.Resource(oam.Sink, "example", oam.SinkConfig{
    			Name:   "example",
    			Policy: "example",
    			Tags:   "example",
    		})
    	}))
    }
    ```
  </Tab>

## Input properties

<ResponseField name="name" type="string" required>
  The name of the ObservabilityAccessManager Sink. Required.
</ResponseField>

<ResponseField name="policy" type="any">
  The policy of this ObservabilityAccessManager Sink. Optional.
</ResponseField>

<ResponseField name="tags" type="any">
  Tags to apply to the sink Optional.
</ResponseField>

## Output properties

<ResponseField name="arn" type="string">
  The Amazon resource name (ARN) of the ObservabilityAccessManager Sink Computed by AWS after `ship`.
</ResponseField>
