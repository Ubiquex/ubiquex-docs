`aws_pinpoint_email_identity` verifies a real sending domain or email address for use with an `aws_pinpoint_email_channel`, the SES-backed identity-verification step required before Pinpoint (or SES directly) will send mail from it.

## Example

<Tabs>
  <Tab title="Go">
    ```go
    package main

    import (
    	pinpointemail "github.com/ubiquex/ubx-sdk-aws/sdk/go/v2/aws/pinpointemail"
    	ubx "github.com/ubiquex/ubx-sdk-go/runtime"
    )

    func main() {
    	ubx.Main(ubx.Stack("example", func() {
    		ubx.Intent(ubx.IntentInfo{Summary: "example own identity"})

    		ubx.Resource(pinpointemail.Identity, "example", pinpointemail.IdentityConfig{
    			Name:                      "example",
    			DkimSigningEnabled:        true,
    			FeedbackForwardingEnabled: true,
    			MailFromAttributes:        map[string]any{"behavior_on_mx_failure": "example"},
    			Tags:                      []map[string]any{{"key": "example"}},
    		})
    	}))
    }
    ```

    import ubx_sdk as ubx
    from ubx.aws.pinpointemail import Identity, IdentityConfig
    from ubx.aws.pinpointemail.identity import Identity_MailFromAttributes, Identity_Tags

    def describe():
        ubx.intent("example own identity")

        ubx.resource(Identity, "example", IdentityConfig(
            name="example",
            dkim_signing_enabled=True,
            feedback_forwarding_enabled=True,
            mail_from_attributes=Identity_MailFromAttributes(behavior_on_mx_failure="example"),
            tags=[Identity_Tags(key="example")],
        ))

    if __name__ == "__main__":
        ubx.run("example", describe)

## Input properties

<ResponseField name="dkim_signing_enabled" type="bool">
  Specifies whether DKIM signing is enabled for the email identity, allowing emails sent from the identity to be signed with the associated DKIM key. Optional. **(AI-inferred)**
</ResponseField>

<ResponseField name="feedback_forwarding_enabled" type="bool">
  Enables or disables feedback forwarding for the email identity, causing Amazon Pinpoint to send bounce and complaint notifications to the Return-Path address when enabled. Optional. **(AI-inferred)**
</ResponseField>

<ResponseField name="mail_from_attributes" type="object">
  Specifies the custom MAIL FROM domain and the behavior (use the default value or reject the message) to take when the MAIL FROM domain is not available for this Pinpoint email identity. Optional. **(AI-inferred)**
  <Expandable title="properties">
    <ResponseField name="behavior_on_mx_failure" type="string">
      Determines whether Pinpoint uses the default MAIL FROM domain or rejects the message when the custom MAIL FROM domain's MX record is missing or misconfigured (USE_DEFAULT_VALUE or REJECT_MESSAGE). Optional. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="mail_from_domain" type="string">
      The custom MAIL FROM domain that Amazon Pinpoint uses as the envelope MAIL FROM address for emails sent from this email identity. Optional. **(AI-inferred)**
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="name" type="string" required>
  The email address or domain name that serves as the Amazon Pinpoint email identity for sending email. Required. **(AI-inferred)**
</ResponseField>

<ResponseField name="tags" type="list(object)">
  Assigns a list of key-value tags to the Amazon Pinpoint email identity to help organize, identify, and manage the resource (e.g., for cost allocation and access control). Optional. **(AI-inferred)**
  <Expandable title="properties">
    <ResponseField name="key" type="string">
      The key (name) of a tag attached to the Amazon Pinpoint email identity, used to categorize, manage, and track the resource according to your tagging conventions. Optional; if omitted, computed by AWS. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="value" type="string">
      Specifies the value of a tag key-value pair to be associated with the Amazon Pinpoint email identity. Optional; if omitted, computed by AWS. **(AI-inferred)**
    </ResponseField>
  </Expandable>
</ResponseField>

## Output properties

<ResponseField name="id" type="string">
  The email address or domain name that serves as the unique identifier for this Pinpoint email identity. Computed by AWS after `ship`. **(AI-inferred)**
</ResponseField>

<ResponseField name="identity_dnsrecord_name1" type="string">
  The first DNS record name that must be added to your domain's DNS settings to verify ownership of the Amazon Pinpoint email identity. Computed by AWS after `ship`. **(AI-inferred)**
</ResponseField>

<ResponseField name="identity_dnsrecord_name2" type="string">
  The name of the second DNS record (typically a DKIM record) required for email identity verification in Amazon Pinpoint. Computed by AWS after `ship`. **(AI-inferred)**
</ResponseField>

<ResponseField name="identity_dnsrecord_name3" type="string">
  The third DNS record name returned for the email identity, which must be added to your domain's DNS configuration to verify domain ownership. Computed by AWS after `ship`. **(AI-inferred)**
</ResponseField>

<ResponseField name="identity_dnsrecord_value1" type="string">
  This read-only attribute provides the value of the first DNS TXT record that Amazon Pinpoint requires you to add to your domain's DNS settings to verify the email identity for sending email. Computed by AWS after `ship`. **(AI-inferred)**
</ResponseField>

<ResponseField name="identity_dnsrecord_value2" type="string">
  The second of the three CNAME record values that Amazon Pinpoint provides for a domain-based email identity; you must publish this value in your DNS to verify domain ownership and enable DKIM email signing. Computed by AWS after `ship`. **(AI-inferred)**
</ResponseField>

<ResponseField name="identity_dnsrecord_value3" type="string">
  The value of the third DNS record (TXT record) that must be created in the domain's DNS settings to verify ownership of the email identity in Amazon Pinpoint. Computed by AWS after `ship`. **(AI-inferred)**
</ResponseField>
