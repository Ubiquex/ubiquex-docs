`aws_network_interface` creates a real Elastic Network Interface, a virtual network card with its own private IP addresses and security groups, that can be attached to an EC2 instance.

## Example

<Tabs>
  <Tab title="Go">
    ```go
    package main

    import (
    	network "github.com/ubiquex/ubx-sdk-aws/sdk/go/aws/network"
    	ubx "github.com/ubiquex/ubx-sdk-go/runtime"
    )

    func main() {
    	ubx.Main(ubx.Stack("example", func() {
    		ubx.Intent(ubx.IntentInfo{Summary: "example own interface"})

    		ubx.Resource(network.Interface, "example", network.InterfaceConfig{
    			SubnetId:                        "example",
    			ConnectionTrackingSpecification: map[string]any{"tcp_established_timeout": 1},
    			Description:                     "Managed by ubx.",
    			EnablePrimaryIpv6:               true,
    			GroupSet:                        []string{"example"},
    			InterfaceType:                   "example",
    			Ipv4PrefixCount:                 1,
    			Ipv4Prefixes:                    []map[string]any{{"ipv4_prefix": "example"}},
    		})
    	}))
    }
    ```
  </Tab>

## Input properties

<ResponseField name="connection_tracking_specification" type="object">
  Specifies the connection tracking configuration for the network interface, including idle timeout values for established TCP connections and UDP flows to control stateful traffic tracking. Optional. **(AI-inferred)**
  <Expandable title="properties">
    <ResponseField name="tcp_established_timeout" type="number">
      Specifies the timeout (in seconds) for TCP established connections for the network interface's connection tracking configuration. Optional. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="udp_stream_timeout" type="number">
      The timeout in seconds for UDP streams in the established state on this network interface, after which connection tracking removes the flow if no packets are seen. Optional. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="udp_timeout" type="number">
      Specifies the idle timeout in seconds for UDP traffic on the network interface, determining how long a UDP flow remains active in connection tracking before it expires. Optional. **(AI-inferred)**
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="description" type="string">
  A description for the network interface. Optional.
</ResponseField>

<ResponseField name="enable_primary_ipv6" type="bool">
  If you have instances or ENIs that rely on the IPv6 address not changing, to avoid disrupting traffic to instances or ENIs, you can enable a primary IPv6 address. Enable this option to automatically assign an IPv6 associated with the ENI attached to your instance to be the primary IPv6 address. When you enable an IPv6 address to be a primary IPv6, you cannot disable it. Traffic will be routed to the primary IPv6 address until the instance is terminated or the ENI is detached. If you have multiple IPv6 addresses associated with an ENI and you enable a primary IPv6 address, the first IPv6 address associated with the ENI becomes the primary IPv6 address. Optional.
</ResponseField>

<ResponseField name="group_set" type="list(string)">
  A list of security group IDs associated with this network interface. Optional.
</ResponseField>

<ResponseField name="interface_type" type="string">
  Indicates the type of network interface. Optional.
</ResponseField>

<ResponseField name="ipv4_prefix_count" type="number">
  The number of IPv4 prefixes to assign to a network interface. When you specify a number of IPv4 prefixes, Amazon EC2 selects these prefixes from your existing subnet CIDR reservations, if available, or from free spaces in the subnet. By default, these will be /28 prefixes. You can't specify a count of IPv4 prefixes if you've specified one of the following: specific IPv4 prefixes, specific private IPv4 addresses, or a count of private IPv4 addresses. Optional.
</ResponseField>

<ResponseField name="ipv4_prefixes" type="list(object)">
  Assigns a list of IPv4 prefixes to the network interface. If you want EC2 to automatically assign IPv4 prefixes, use the Ipv4PrefixCount property and do not specify this property. Presently, only /28 prefixes are supported. You can't specify IPv4 prefixes if you've specified one of the following: a count of IPv4 prefixes, specific private IPv4 addresses, or a count of private IPv4 addresses. Optional.
  <Expandable title="properties">

</ResponseField>

</ResponseField>

<ResponseField name="ipv6_addresses" type="list(object)">
  One or more specific IPv6 addresses from the IPv6 CIDR block range of your subnet to associate with the network interface. If you're specifying a number of IPv6 addresses, use the Ipv6AddressCount property and don't specify this property. Optional.
  <Expandable title="properties">

When you specify a number of IPv6 prefixes, Amazon EC2 selects these prefixes from your existing subnet CIDR reservations, if available, or from free spaces in the subnet. By default, these will be /80 prefixes. You can't specify a count of IPv6 prefixes if you've specified one of the following: specific IPv6 prefixes, specific IPv6 addresses, or a count of IPv6 addresses. Optional.

Optional.
