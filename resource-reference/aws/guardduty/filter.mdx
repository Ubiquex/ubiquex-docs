`aws_guard_duty_filter` automatically suppresses or auto-archives real findings matching a defined criteria from an `aws_guard_duty_detector`, cutting down alert noise from findings a caller has already determined aren't actionable.

## Example

<Tabs>
  <Tab title="Go">
    ```go
    package main

    import (
    	guardduty "github.com/ubiquex/ubx-sdk-aws/sdk/go/v2/aws/guardduty"
    	ubx "github.com/ubiquex/ubx-sdk-go/runtime"
    )

    func main() {
    	ubx.Main(ubx.Stack("example", func() {
    		ubx.Intent(ubx.IntentInfo{Summary: "example own filter"})

    		ubx.Resource(guardduty.Filter, "example", guardduty.FilterConfig{
    			DetectorId:      "example",
    			FindingCriteria: map[string]any{"criterion": "example"},
    			Name:            "example",
    			Action:          "example",
    			Description:     "Managed by ubx.",
    			Rank:            1,
    			Tags:            []map[string]any{{"key": "example"}},
    		})
    	}))
    }
    ```

## Properties

<ResponseField name="action" type="string">
  Specifies the action taken by the GuardDuty filter when a finding matches the filter criteria, either 'NOOP' to leave the finding's state unchanged or 'ARCHIVE' to archive the finding. Optional. **(AI-inferred)**
</ResponseField>

<ResponseField name="description" type="string">
  A user-supplied description of the GuardDuty filter, used to explain the purpose or criteria of the filter. Optional. **(AI-inferred)**
</ResponseField>

<ResponseField name="detector_id" type="string" required>
  The unique identifier of the GuardDuty detector that this filter is associated with. Required. **(AI-inferred)**
</ResponseField>

<ResponseField name="finding_criteria" type="object" required>
  Defines the criteria used to filter GuardDuty findings, consisting of conditions on fields such as severity, type, or resource. Required. **(AI-inferred)**
  <Expandable title="properties">
    <ResponseField name="criterion" type="any">
      Specifies the conditions used to filter findings, where each key is a finding field name (e.g., severity, type) and the value defines the comparison operators (Eq, Lt, Gt, etc.) and values to match. Optional. **(AI-inferred)**
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="name" type="string" required>
  The name of the GuardDuty filter, which uniquely identifies the filter within the detector and is required when creating or updating the filter. Required. **(AI-inferred)**
</ResponseField>

<ResponseField name="rank" type="number">
  Rank sets the filter's priority among other GuardDuty filters, where a lower value places it higher in the saved-filters list. Optional. **(AI-inferred)**
</ResponseField>

<ResponseField name="tags" type="list(object)">
  Defines the list of key-value tags to attach to the GuardDuty filter for resource categorization and cost allocation. Optional. **(AI-inferred)**
  <Expandable title="properties">
    <ResponseField name="key" type="string">
      The key of a tag attached to the GuardDuty filter, corresponding to the Key attribute of a Tag object in the AWS CloudFormation AWS::GuardDuty::Filter resource. Optional; if omitted, computed by AWS. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="value" type="string">
      The value component of a key-value tag attached to the GuardDuty filter resource, used for organizing, identifying, and managing the filter in AWS. Optional; if omitted, computed by AWS. **(AI-inferred)**
    </ResponseField>
  </Expandable>
</ResponseField>
