`aws_guard_duty_master` associates a real GuardDuty member account with an administrator account through GuardDuty's original, invitation-based multi-account mechanism, sending or accepting the actual invitation between the two. "Master" is legacy terminology AWS has since replaced with "administrator" across GuardDuty's own API (GetMasterAccount and similar calls are deprecated in favor of administrator-account equivalents), and this whole invitation-based mechanism itself is superseded, though not removed, by GuardDuty's newer AWS Organizations-integrated administrator delegation, which AWS now recommends instead.

## Example

<Tabs>
  <Tab title="Go">
    ```go
    package main

    import (
    	guardduty "github.com/ubiquex/ubx-sdk-aws/sdk/go/v2/aws/guardduty"
    	ubx "github.com/ubiquex/ubx-sdk-go/runtime"
    )

    func main() {
    	ubx.Main(ubx.Stack("example", func() {
    		ubx.Intent(ubx.IntentInfo{Summary: "example own master"})

    		ubx.Resource(guardduty.Master, "example", guardduty.MasterConfig{
    			DetectorId:   "example",
    			MasterId:     "example",
    			InvitationId: "example",
    		})
    	}))
    }
    ```

## Properties

<ResponseField name="detector_id" type="string" required>
  Unique ID of the detector of the GuardDuty member account. Required.
</ResponseField>

<ResponseField name="invitation_id" type="string">
  Value used to validate the master account to the member account. Optional.
</ResponseField>

<ResponseField name="master_id" type="string" required>
  ID of the account used as the master account. Required.
</ResponseField>
