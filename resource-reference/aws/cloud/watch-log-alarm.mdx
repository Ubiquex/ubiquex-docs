`aws_cloud_watch_log_alarm` runs a real CloudWatch Logs Insights query on a schedule and alarms when its aggregated results breach a threshold across a defined number of recent executions, catching patterns and error rates directly in log data without first building a metric filter to extract a number from it.

## Input properties

<ResponseField name="action_log_line_count" type="number">
  The number of log lines to include in alarm notifications. Valid values are 0 to 50. Optional.
</ResponseField>

<ResponseField name="action_log_line_role_arn" type="string">
  The ARN of the IAM role that grants CloudWatch permissions to fetch log lines for alarm notifications. Required when ActionLogLineCount is greater than 0. Optional.
</ResponseField>

<ResponseField name="actions_enabled" type="bool">
  Indicates whether actions should be executed during any changes to the alarm state. The default is TRUE. Optional.
</ResponseField>

<ResponseField name="alarm_actions" type="list(string)">
  The list of actions to execute when this alarm transitions into an ALARM state from any other state. Optional.
</ResponseField>

<ResponseField name="alarm_description" type="string">
  The description of the log alarm. Optional.
</ResponseField>

<ResponseField name="alarm_name" type="string">
  The name of the log alarm. Optional.
</ResponseField>

<ResponseField name="comparison_operator" type="string" required>
  The arithmetic operation to use when comparing the specified threshold and the query results. Valid values are GreaterThanOrEqualToThreshold, GreaterThanThreshold, LessThanThreshold, and LessThanOrEqualToThreshold. Required.
</ResponseField>

<ResponseField name="insufficient_data_actions" type="list(string)">
  The actions to execute when this alarm transitions to the INSUFFICIENT_DATA state from any other state. Optional.
</ResponseField>

<ResponseField name="okactions" type="list(string)">
  The actions to execute when this alarm transitions to the OK state from any other state. Optional.
</ResponseField>

<ResponseField name="query_results_to_alarm" type="number" required>
  The number of query results that must be breaching to trigger the alarm. Required.
</ResponseField>

<ResponseField name="query_results_to_evaluate" type="number" required>
  The number of query results over which data is compared to the specified threshold. Required.
</ResponseField>

<ResponseField name="scheduled_query_configuration" type="object" required>
  The scheduled query configuration for the log alarm. Required.
  <Expandable title="properties">
    <ResponseField name="aggregation_expression" type="string" required>
      The aggregation expression for the scheduled query, e.g. count(*) or avg(latency) by host. Required.
    </ResponseField>
    <ResponseField name="log_group_identifiers" type="list(string)">
      The log groups to query. Optional.
    </ResponseField>
    <ResponseField name="query_string" type="string" required>
      The query string to execute against the specified log groups. Required.
    </ResponseField>
    <ResponseField name="schedule_configuration" type="object" required>
      The schedule configuration for the scheduled query. Required.
      <Expandable title="properties">
        <ResponseField name="end_time_offset" type="number">
          The number of seconds into the past to end the query window. Must be a non-negative value and cannot exceed 2592000 seconds (30 days). Optional.
        </ResponseField>
        <ResponseField name="schedule_expression" type="string" required>
          The expression that defines when the scheduled query runs, e.g. rate(1 minute). Required.
        </ResponseField>
        <ResponseField name="start_time_offset" type="number" required>
          The number of seconds into the past to start the query window. Must be a positive value and cannot exceed 2592000 seconds (30 days). Required.
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="scheduled_query_role_arn" type="string" required>
      The ARN of the IAM role that grants permissions to execute the scheduled query. Required.
    </ResponseField>
    <ResponseField name="tags" type="list(object)">
      A list of key-value pairs to associate with the scheduled query that backs the log alarm. Optional.
      <Expandable title="properties">
        <ResponseField name="key" type="string">
          Optional; if omitted, computed by AWS.
        </ResponseField>
        <ResponseField name="value" type="string">
          Optional; if omitted, computed by AWS.
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="tags" type="list(object)">
  A list of key-value pairs to associate with the log alarm. Optional.
  <Expandable title="properties">
    <ResponseField name="key" type="string">
      Optional; if omitted, computed by AWS.
    </ResponseField>
    <ResponseField name="value" type="string">
      The value associated with a tag key applied to the CloudWatch alarm, which aids in identifying, organizing, and managing AWS resources and costs. Optional; if omitted, computed by AWS. **(AI-inferred)**
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="threshold" type="number" required>
  The value to compare against the results of the scheduled query evaluation. Required.
</ResponseField>

<ResponseField name="treat_missing_data" type="string">
  Sets how this alarm is to handle missing data points. Valid values are breaching, notBreaching, ignore, and missing. Optional.
</ResponseField>

<ResponseField name="warm_up_configuration" type="object">
  The warm-up configuration for an alarm. A warm-up period delays alarm evaluation after you create or update the alarm. This reduces alarm noise from missing data while a new resource or service starts up. During the warm-up period, the alarm stays in INSUFFICIENT_DATA and doesn't perform alarm actions. Optional.
  <Expandable title="properties">
    <ResponseField name="only_start_evaluating_after_warm_up_period_ends" type="bool">
      Specifies whether the alarm waits for the full warm-up period before it starts evaluating. If true, the alarm waits the entire WarmUpPeriodDurationInMinutes before it starts evaluating, even if metric data arrives earlier. If false, the alarm ends the warm-up period early and starts evaluating as soon as it has enough metric data to fill its evaluation window. This is the default behavior. Optional.
    </ResponseField>
    <ResponseField name="warm_up_period_duration_in_minutes" type="number">
      The length of the warm-up period, in minutes. For this duration after you create or update the alarm, the alarm stays in INSUFFICIENT_DATA and doesn't perform alarm actions. Valid values range from 1 to 2,880 minutes (2 days). You can change this value while the alarm is still in its warm-up period. Changes have no effect after the warm-up period ends. Optional.
    </ResponseField>
  </Expandable>
</ResponseField>

## Output properties

<ResponseField name="arn" type="string">
  The ARN of the log alarm. Computed by AWS after `ship`.
