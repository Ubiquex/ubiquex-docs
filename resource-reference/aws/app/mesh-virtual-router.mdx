`aws_app_mesh_virtual_router` handles traffic for one or more `aws_app_mesh_virtual_service`s, with routes that distribute traffic across `aws_app_mesh_virtual_node`s by weighted percentage, HTTP header, path, or gRPC method, the mechanism behind canary and blue/green traffic shifts without touching application code.

## Input properties

<ResponseField name="mesh_name" type="string" required>
  The name of the service mesh in which the virtual router is defined. Required. **(AI-inferred)**
</ResponseField>

<ResponseField name="mesh_owner" type="string">
  Specifies the AWS account ID of the mesh owner when creating a virtual router in a shared App Mesh mesh owned by another AWS account; if omitted, the mesh is assumed to be in your current account. Optional. **(AI-inferred)**
</ResponseField>

<ResponseField name="spec" type="object" required>
  Specifies the virtual router's desired configuration, primarily its Listener property that defines the port mapping and protocol for traffic received by the virtual router. Required. **(AI-inferred)**
  <Expandable title="properties">
    <ResponseField name="listeners" type="list(object)" required>
      Defines the port mappings (port and protocol) that the virtual router listens on for traffic from virtual services. Required. **(AI-inferred)**
      <Expandable title="properties">
        <ResponseField name="port_mapping" type="object">
          Specifies the port number and protocol (such as http or tcp) that the virtual router listener uses to receive incoming traffic. Optional; if omitted, computed by AWS. **(AI-inferred)**
          <Expandable title="properties">
            <ResponseField name="port" type="number">

            </ResponseField>
            <ResponseField name="protocol" type="string">
