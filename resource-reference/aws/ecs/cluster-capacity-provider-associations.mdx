`aws_ecs_cluster_capacity_provider_associations` is the real, actual link between an `aws_ecs_cluster` and one or more `aws_ecs_capacity_provider`s, along with the cluster's own default capacity provider strategy.

## Example

## Properties

<ResponseField name="capacity_providers" type="list(string)">
  List of capacity providers to associate with the cluster Optional.
</ResponseField>

<ResponseField name="cluster" type="string" required>
  The name of the cluster Required.
</ResponseField>

<ResponseField name="default_capacity_provider_strategy" type="list(object)" required>
  List of capacity providers to associate with the cluster Required.
  <Expandable title="properties">
    <ResponseField name="base" type="number">
      The base setting defines the minimum number of tasks that must run on the specified capacity provider before other providers in the default strategy are used, ensuring baseline capacity for the cluster. Optional; if omitted, computed by AWS. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="capacity_provider" type="string">
      The name of the capacity provider to be used for this entry in the default capacity provider strategy. Optional; if omitted, computed by AWS. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="weight" type="number">
      Determines the relative proportion of tasks that should be placed on this capacity provider as part of the default strategy, where a higher value increases the share of tasks routed to it. Optional; if omitted, computed by AWS. **(AI-inferred)**
    </ResponseField>
  </Expandable>
</ResponseField>
