`aws_data_zone_domain_unit` creates a real, nested organizational unit within an `aws_data_zone_domain`, letting a large domain's assets, users, and policies be subdivided by team or business unit rather than managed as one flat namespace.

## Example

## Input properties

<ResponseField name="description" type="string">
  The description of the domain unit. Optional.
</ResponseField>

<ResponseField name="domain_identifier" type="string" required>
  The ID of the domain where you want to create a domain unit. Required.
</ResponseField>

<ResponseField name="name" type="string" required>
  The name of the domain unit. Required.
</ResponseField>

<ResponseField name="parent_domain_unit_identifier" type="string" required>
  The ID of the parent domain unit. Required.
</ResponseField>

## Output properties

<ResponseField name="created_at" type="string">
  The timestamp at which the domain unit was created. Computed by AWS after `ship`.
</ResponseField>

<ResponseField name="domain_id" type="string">
  The ID of the domain where the domain unit was created. Computed by AWS after `ship`.
</ResponseField>

<ResponseField name="id" type="string">
  The ID of the domain unit. Computed by AWS after `ship`.
</ResponseField>

<ResponseField name="identifier" type="string">
  The identifier of the domain unit that you want to get. Computed by AWS after `ship`.
</ResponseField>

<ResponseField name="last_updated_at" type="string">
  The timestamp at which the domain unit was last updated. Computed by AWS after `ship`.
</ResponseField>

<ResponseField name="parent_domain_unit_id" type="string">
  The ID of the parent domain unit. Computed by AWS after `ship`.
</ResponseField>
