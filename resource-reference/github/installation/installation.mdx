`github_installation` is a real, live installation of a GitHub App on a user account, organization, or enterprise -- which repositories it can see, which permissions it was granted, and the credentials (access_tokens_url, client_id) GitHub issues for it to act with. Every GitHub App integration, from a CI bot to a security scanner, is represented on GitHub's own side by exactly one of these per account it's installed on.

## Input properties

<ResponseField name="client_id" type="string" required>
  The Client ID of the GitHub App to install. Required.
</ResponseField>

<ResponseField name="enterprise" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="installation_id" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="org" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="repositories" type="list(string)">
  The names of the repositories to which the installation will be granted access. This is the simple name of the repository, not the full name (e.g., `hello-world` not `octocat/hello-world`). This is only required when `repository_selection` is `selected`. Optional.
</ResponseField>

<ResponseField name="repository_selection" type="string" required>
  The repository selection for the GitHub App. Must be one of: * `all` - the installation can access all repositories in the organization. * `selected` - the installation can access only the listed repositories. * `none` - no repository permissions are requested. Only use when the app does not request repository permissions. Required.
</ResponseField>
