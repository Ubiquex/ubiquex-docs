`github_organization_custom_repository_role` is a repository-level permission role an organization defines on top of GitHub's own built-in roles (read/triage/write/maintain/admin) -- a named base role plus a real, granted subset of fine-grained permissions layered on it. Organizations use these when none of GitHub's own five built-in roles matches a real team's actual responsibilities.

## Input properties

<ResponseField name="base_role" type="string" required>
  The system role from which this role inherits permissions. Required.
</ResponseField>

<ResponseField name="description" type="string">
  A short description about who this role is for or what permissions it grants. Optional; if omitted, computed by GitHub.
</ResponseField>

<ResponseField name="name" type="string" required>
  The name of the custom role. Required.
</ResponseField>

<ResponseField name="org" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="permissions" type="list(string)" required>
  A list of additional permissions included in this role. Required.
</ResponseField>

<ResponseField name="role_id" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>
