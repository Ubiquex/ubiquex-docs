---
title: "github_team_repository"
description: "`github_team_repository` grants a team access to a repository at a specific permission level..."
---

`github_team_repository` grants a team access to a repository at a specific permission level, adding the repository to the team's own list of managed repositories.

## Example

<ResponseField name="org" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="owner_path" type="string" required>
  path parameter, not part of the API's own resource representation (renamed from "owner": that name is already used by a differently-typed, real response attribute) Required.
</ResponseField>

<ResponseField name="owner_path2" type="string" required>
  path parameter, not part of the API's own resource representation (renamed from "owner": that name is already used by a differently-typed, real response attribute) Required.
</ResponseField>

<ResponseField name="permission" type="string">
  The permission to grant the team on this repository. We accept the following permissions to be set: `pull`, `triage`, `push`, `maintain`, `admin` and you can also specify a custom repository role name, if the owning organization has defined any. If no permission is specified, the team's `permission` attribute will be used to determine what permission to grant the team on this repository. Optional.
</ResponseField>

<ResponseField name="repo" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="team_slug" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>
