`github_check_run` is one individual test result inside a check suite, created and updated by a GitHub App as it moves through `queued`, `in_progress`, and `completed` -- the real, per-test granularity behind a pull request's own status checks.

## Example

    	check "github.com/ubiquex/ubx-sdk-github/sdk/go/github/check"

    func main() {
    	ubx.Main(ubx.Stack("example", func() {

    		})
    	}))
    }

## Input properties

<ResponseField name="actions" type="list(object)">
  Displays a button on GitHub that can be clicked to alert your app to do additional tasks. For example, a code linting app can display a button that automatically fixes detected errors. The button created in this object is displayed after the check run completes. When a user clicks the button, GitHub sends the [`check_run.requested_action` webhook](https://docs.github.com/enterprise-cloud@latest/webhooks/event-payloads/#check_run) to your app. Each action includes a `label`, `identifier` and `description`. A maximum of three actions are accepted. To learn more about check runs and requested actions, see "[Check runs and requested actions](https://docs.github.com/enterprise-cloud@latest/rest/guides/using-the-rest-api-to-interact-with-checks#check-runs-and-requested-actions)." Optional.
  <Expandable title="properties">
    <ResponseField name="description" type="string">
      A short explanation of the action, displayed to users. Maximum length is 40 characters. Optional; if omitted, computed by GitHub. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="identifier" type="string">
      A short identifier for the action, maximum length of 20 characters. Optional; if omitted, computed by GitHub. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="label" type="string">
      The short text label for the action button, displayed in the GitHub UI. Must be 20 characters or fewer. Optional; if omitted, computed by GitHub. **(AI-inferred)**
    </ResponseField>
  </Expandable>
</ResponseField>
