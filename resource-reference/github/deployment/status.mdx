`github_deployment_status` marks one deployment's own real outcome -- `pending`, `in_progress`, `success`, `failure`, `error`, `queued` -- and is what a `deployment_status` webhook subscriber actually consumes to know whether a deployment it triggered succeeded.

## Input properties

<ResponseField name="auto_inactive" type="bool">
  Adds a new `inactive` status to all prior non-transient, non-production environment deployments with the same repository and `environment` name as the created status's deployment. An `inactive` status is only added to deployments that had a `success` state. Default: `true` Optional.
</ResponseField>

<ResponseField name="deployment_id" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="description" type="string">
  A short description of the status. The maximum description length is 140 characters. Optional; if omitted, computed by GitHub.
</ResponseField>

<ResponseField name="environment" type="string">
  Name for the target deployment environment, which can be changed when setting a deploy status. For example, `production`, `staging`, or `qa`. If not defined, the environment of the previous status on the deployment will be used, if it exists. Otherwise, the environment of the deployment will be used. Optional; if omitted, computed by GitHub.
</ResponseField>

<ResponseField name="environment_url" type="string">
  Sets the URL for accessing your environment. Default: `""` Optional; if omitted, computed by GitHub.
</ResponseField>

<ResponseField name="log_url" type="string">
  The full URL of the deployment's output. This parameter replaces `target_url`. We will continue to accept `target_url` to support legacy uses, but we recommend replacing `target_url` with `log_url`. Setting `log_url` will automatically set `target_url` to the same value. Default: `""` Optional; if omitted, computed by GitHub.
</ResponseField>

<ResponseField name="owner" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="repo" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="state" type="string" required>
  The state of the status. When you set a transient deployment to `inactive`, the deployment will be shown as `destroyed` in GitHub. Required.
</ResponseField>

<ResponseField name="status_id" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="target_url" type="string">
  The target URL to associate with this status. This URL should contain output to keep the user updated while the task is running or serve as historical information for what happened in the deployment. &gt; [!NOTE] &gt; It's recommended to use the `log_url` parameter, which replaces `target_url`. Optional; if omitted, computed by GitHub.
</ResponseField>
