`github_deployment_branch_policy` restricts which branches are even allowed to deploy to a given environment, matched by a real custom name pattern -- the guardrail that stops an arbitrary branch from ever reaching a protected environment by accident.

## Input properties

<ResponseField name="branch_policy_id" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="environment_name" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="name" type="string" required>
  The name pattern that branches or tags must match in order to deploy to the environment. Wildcard characters will not match `/`. For example, to match branches that begin with `release/` and contain an additional single slash, use `release/*/*`. For more information about pattern matching syntax, see the [Ruby File.fnmatch documentation](https://ruby-doc.org/core-2.5.1/File.html#method-c-fnmatch). Required.
</ResponseField>

<ResponseField name="owner" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="repo" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="type" type="string">
  Whether this rule targets a branch or tag Optional; if omitted, computed by GitHub.
</ResponseField>
