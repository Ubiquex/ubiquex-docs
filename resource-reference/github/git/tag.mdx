`github_git_tag` is a real, named marker attached to one specific commit, typically used for a release or another point worth being able to find again without walking the commit history to locate it.

## Example

## Input properties

<ResponseField name="message" type="string" required>
  The tag message. Required.
</ResponseField>

<ResponseField name="object" type="string" required>
  The SHA of the git object this is tagging. Required.
</ResponseField>

<ResponseField name="owner" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="repo" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="tag" type="string" required>
  The tag's name. This is typically a version (e.g., "v0.0.1"). Required.
</ResponseField>

<ResponseField name="tag_sha" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="tagger" type="object">
  An object with information about the individual creating the tag. Optional; if omitted, computed by GitHub.
  <Expandable title="properties">
    <ResponseField name="date" type="string">
      When this object was tagged. This is a timestamp in [ISO 8601](https://en.wikipedia.org/wiki/ISO_8601) format: `YYYY-MM-DDTHH:MM:SSZ`. Optional.
    </ResponseField>
    <ResponseField name="email" type="string" required>
      The email of the author of the tag Required.
    </ResponseField>
    <ResponseField name="name" type="string" required>
      The name of the author of the tag Required.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="type" type="string" required>
  The type of the object we're tagging. Normally this is a `commit` but it can also be a `tree` or a `blob`. Required.
</ResponseField>

## Output properties

<ResponseField name="node_id" type="string">
  The GraphQL Node ID of the git tag. Computed by GitHub after `ship`. **(AI-inferred)**
</ResponseField>

<ResponseField name="sha" type="string">
  The SHA-1 hash of the git tag object, which serves as its unique identifier. Computed by GitHub after `ship`. **(AI-inferred)**
</ResponseField>

<ResponseField name="tagger" type="object">

  URL for the tag Computed by GitHub after `ship`.
</ResponseField>

<ResponseField name="verification" type="object">
  The verification object for the Git tag, containing details such as whether the tag is verified, the reason for verification, the signature, and the signed payload. Computed by GitHub after `ship`. **(AI-inferred)**
  <Expandable title="properties">
    <ResponseField name="payload" type="string" required>
      The payload of the tag verification, i.e., the signed content that was verified against the signature. Required. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="reason" type="string" required>
      Indicates the reason for the tag verification status, such as 'valid_signature', 'unsigned', 'invalid_signature', 'expired_key', or 'unknown_key'. Required. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="signature" type="string" required>
      The GPG or SSH signature generated by the signing key, used to verify the authenticity and integrity of the tag. Required. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="verified" type="bool" required>
      Whether the tag's signature is verified. Required. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="verified_at" type="string" required>
      The timestamp indicating when the tag's signature verification was performed. Required. **(AI-inferred)**
    </ResponseField>
  </Expandable>
</ResponseField>
