`github_git_tree` represents the real directory structure and file contents of a repository at one specific point in its history -- what a commit object actually points at to say what the repository looked like right then.

## Input properties

<ResponseField name="base_tree" type="string">
  The SHA1 of an existing Git tree object which will be used as the base for the new tree. If provided, a new Git tree object will be created from entries in the Git tree object pointed to by `base_tree` and entries defined in the `tree` parameter. Entries defined in the `tree` parameter will overwrite items from `base_tree` with the same `path`. If you're creating new changes on a branch, then normally you'd set `base_tree` to the SHA1 of the Git tree object of the current latest commit on the branch you're working on. If not provided, GitHub will create a new Git tree object from only the entries defined in the `tree` parameter. If you create a new commit pointing to such a tree, then all files which were a part of the parent commit's tree and were not defined in the `tree` parameter will be listed as deleted by the new commit. Optional.
</ResponseField>

<ResponseField name="owner" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="repo" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="tree" type="list(object)" required>
  Objects (of `path`, `mode`, `type`, and `sha`) specifying a tree structure. Required.
  <Expandable title="properties">
    <ResponseField name="content" type="string">
      The content of the file (blob) represented by this tree entry. This field is typically populated only for blob entries, often when the tree is fetched recursively and the file is small enough to include inline. Optional; if omitted, computed by GitHub. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="mode" type="string">
      The file mode for the tree entry. Valid values are 100644 (regular file), 100755 (executable file), 040000 (subdirectory), 160000 (submodule/gitlink), and 120000 (symbolic link). Optional; if omitted, computed by GitHub. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="path" type="string">
      The file path relative to the repository root for the tree entry. Optional; if omitted, computed by GitHub. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="sha" type="string">
      The SHA-1 hash of the git object (blob or tree) referenced by this tree entry. Optional; if omitted, computed by GitHub. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="type" type="string">
      The type of the tree entry, which is one of 'blob' (file), 'tree' (subdirectory), or 'commit' (submodule). Optional; if omitted, computed by GitHub. **(AI-inferred)**
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="tree_sha" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

## Output properties

<ResponseField name="sha" type="string">
  The SHA-1 hash of the tree object, assigned by GitHub when the tree is created. Computed by GitHub after `ship`. **(AI-inferred)**
</ResponseField>

<ResponseField name="truncated" type="bool">
  Whether the tree is truncated due to GitHub's limits (e.g., too many entries). Computed by GitHub after `ship`. **(AI-inferred)**
</ResponseField>

<ResponseField name="url" type="string">
  The GitHub API URL for this tree. Computed by GitHub after `ship`. **(AI-inferred)**
</ResponseField>
