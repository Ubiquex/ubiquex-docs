`github_milestone` groups a real set of issues or pull requests toward one shared target -- a due date, a completion percentage tracked automatically as items in it open and close -- the mechanism for watching a body of related work move toward done rather than tracking each item in isolation.

## Input properties

<ResponseField name="description" type="string">
  A description of the milestone. Optional; if omitted, computed by GitHub.
</ResponseField>

<ResponseField name="due_on" type="string">
  The milestone due date. This is a timestamp in [ISO 8601](https://en.wikipedia.org/wiki/ISO_8601) format: `YYYY-MM-DDTHH:MM:SSZ`. Optional; if omitted, computed by GitHub.
</ResponseField>

<ResponseField name="milestone_number" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="owner" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="repo" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="state" type="string">
  The state of the milestone. Either `open` or `closed`. Optional; if omitted, computed by GitHub.
</ResponseField>

<ResponseField name="title" type="string" required>
  The title of the milestone. Required.
</ResponseField>
