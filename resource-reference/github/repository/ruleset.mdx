`github_repository_ruleset` is a named, real set of rules -- who can push to a branch, how commits must be formatted, who can delete a tag -- applied to one or many branches or tags via a pattern, and unlike a classic branch protection rule, a ruleset can also apply across every repository in an organization at once, up to 75 per repository.

## Input properties

<ResponseField name="bypass_actors" type="list(object)">
  The actors that can bypass the rules in this ruleset Optional; if omitted, computed by GitHub.
  <Expandable title="properties">
    <ResponseField name="actor_id" type="number">
      The unique identifier of the user, team, integration, or repository role that is exempt from the ruleset. Optional; if omitted, computed by GitHub. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="actor_type" type="string">
      The type of actor that can bypass the ruleset. Allowed values: Integration, OrganizationAdmin, RepositoryRole, Team, DeployKey, User. Optional; if omitted, computed by GitHub. **(AI-inferred)**
    </ResponseField>
    <ResponseField name="bypass_mode" type="string">
      The bypass mode for the actor, specifying when rules can be bypassed. Allowed values: 'always' (bypass always), 'pull_request' (bypass only for pull request rules), or 'exempt' (actor is exempt from the rule). Optional; if omitted, computed by GitHub. **(AI-inferred)**
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="conditions" type="object">
  Conditions for an organization ruleset. The branch and tag rulesets conditions object should contain both `repository_name` and `ref_name` properties, or both `repository_id` and `ref_name` properties, or both `repository_property` and `ref_name` properties. The push rulesets conditions object does not require the `ref_name` property. For repository policy rulesets, the conditions object should only contain the `repository_name`, the `repository_id`, or the `repository_property`. Optional; if omitted, computed by GitHub.
</ResponseField>

<ResponseField name="enforcement" type="string" required>
  The enforcement level of the ruleset. `evaluate` allows admins to test rules before enforcing them. Admins can view insights on the Rule Insights page (`evaluate` is only available with GitHub Enterprise). Required.
</ResponseField>

<ResponseField name="name" type="string" required>
  The name of the ruleset. Required.
</ResponseField>

<ResponseField name="org" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="rules" type="list(object)">
  An array of rules within the ruleset. Optional; if omitted, computed by GitHub.
  <Expandable title="properties">
    <ResponseField name="parameters" type="object">
      Rule-specific configuration parameters that vary depending on the type of rule being enforced. Optional; if omitted, computed by GitHub. **(AI-inferred)**
      <Expandable title="properties">
        <ResponseField name="update_allows_fetch_and_merge" type="bool">
          A boolean that controls whether the 'update' rule permits merging changes into a branch using the fetch and merge method. When true, fetch and merge is allowed; when false, it is disallowed. Optional; if omitted, computed by GitHub. **(AI-inferred)**
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="type" type="string">
      The type of rule in a repository ruleset. This rule has type 'creation', which restricts who can create branches in the repository. Optional; if omitted, computed by GitHub. **(AI-inferred)**
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="ruleset_id" type="string" required>
  path parameter, not part of the API's own resource representation Required.
</ResponseField>

<ResponseField name="target" type="string">
  The target of the ruleset Optional; if omitted, computed by GitHub.
</ResponseField>
