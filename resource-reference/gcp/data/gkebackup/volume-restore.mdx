`google_gkebackup_volume_restore` is a real, live data source: `ubx.Data`/`data`/`ubx.data` (per language) executes this lookup at resolve time, against Google Cloud's own real API, and returns whatever it finds. It is never created, modified, or destroyed by ubx -- see [docs/schema.md's own "Amendment: data sources"] for the real wire shape this compiles to (`data_sources[]`, never `resources[]`).

## Example

<Tabs>
  <Tab title="Go">
    ```go
    package main

    import (
    	ubx "github.com/ubiquex/ubx-sdk-go/runtime"
    	gkebackup "github.com/ubiquex/ubx-sdk-google/sdk/go/google/data/gkebackup"
    )

    func main() {
    	ubx.Main(ubx.Stack("example", func() {
    		ubx.Intent(ubx.IntentInfo{Summary: "look up google_gkebackup_volume_restore"})

    		ubx.Data(gkebackup.VolumeRestore, "example", gkebackup.VolumeRestoreConfig{
    			Name: "example",
    		})
    	}))
    }
    ```

## Result properties

<ResponseField name="complete_time" type="string">
  Output only. The timestamp when the associated underlying volume restoration completed. Returned by the lookup.
</ResponseField>

<ResponseField name="create_time" type="string">
  Output only. The timestamp when this VolumeRestore resource was created. Returned by the lookup.
</ResponseField>

<ResponseField name="etag" type="string">
  Output only. `etag` is used for optimistic concurrency control as a way to help prevent simultaneous updates of a volume restore from overwriting each other. It is strongly suggested that systems make use of the `etag` in the read-modify-write cycle to perform volume restore updates in order to avoid race conditions. Returned by the lookup.
</ResponseField>

<ResponseField name="state" type="string">
  Output only. The current state of this VolumeRestore. Returned by the lookup.
</ResponseField>

<ResponseField name="state_message" type="string">
  Output only. A human readable message explaining why the VolumeRestore is in its current state. Returned by the lookup.
</ResponseField>
