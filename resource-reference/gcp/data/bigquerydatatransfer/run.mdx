`google_bigquerydatatransfer_run` is a real, live data source: `ubx.Data`/`data`/`ubx.data` (per language) executes this lookup at resolve time, against Google Cloud's own real API, and returns whatever it finds. It is never created, modified, or destroyed by ubx -- see [docs/schema.md's own "Amendment: data sources"] for the real wire shape this compiles to (`data_sources[]`, never `resources[]`).

## Example

<Tabs>
  <Tab title="Go">
    ```go
    package main

    import (
    	ubx "github.com/ubiquex/ubx-sdk-go/runtime"
    	bigquerydatatransfer "github.com/ubiquex/ubx-sdk-google/sdk/go/google/data/bigquerydatatransfer"
    )

    func main() {
    	ubx.Main(ubx.Stack("example", func() {
    		ubx.Intent(ubx.IntentInfo{Summary: "look up google_bigquerydatatransfer_run"})

    		ubx.Data(bigquerydatatransfer.Run, "example", bigquerydatatransfer.RunConfig{
    			Name: "example",
    		})
    	}))
    }
    ```
  </Tab>

  Output only. The BigQuery target dataset id. Returned by the lookup.
</ResponseField>

  Represents preferences for sending email notifications for transfer run events. Returned by the lookup.
  <Expandable title="properties">

    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="end_time" type="string">
  Output only. Time when transfer run ended. Parameter ignored by server for input requests. Returned by the lookup.
</ResponseField>

Each `Status` message contains three pieces of data: error code, error message, and error details.     <ResponseField name="details" type="list(map(any))">
      A list of messages that carry the error details. There is a common set of message types for APIs to use. Optional lookup argument.

<ResponseField name="notification_pubsub_topic" type="string">
  Output only. Pub/Sub topic where a notification will be sent after this transfer run finishes. The format for specifying a pubsub topic is: `projects/&#123;project_id&#125;/topics/&#123;topic_id&#125;` Returned by the lookup.
</ResponseField>

<ResponseField name="params" type="map(any)">
  Output only. Parameters specific to each data source. For more information see the bq tab in the 'Setting up a data transfer' section for each data source. For example the parameters for Cloud Storage transfers are listed here: https://cloud.google.com/bigquery-transfer/docs/cloud-storage-transfer#bq Returned by the lookup.
</ResponseField>

<ResponseField name="run_time" type="string">
  For batch transfer runs, specifies the date and time of the data should be ingested. Returned by the lookup.
</ResponseField>

<ResponseField name="schedule" type="string">
  Output only. Describes the schedule of this transfer run if it was created as part of a regular schedule. For batch transfer runs that are scheduled manually, this is empty. NOTE: the system might choose to delay the schedule depending on the current load, so `schedule_time` doesn't always match this. Returned by the lookup.
</ResponseField>

<ResponseField name="schedule_time" type="string">
  Minimum time after which a transfer run can be started. Returned by the lookup.
</ResponseField>

<ResponseField name="start_time" type="string">
  Output only. Time when transfer run was started. Parameter ignored by server for input requests. Returned by the lookup.
</ResponseField>

<ResponseField name="state" type="string">
  Data transfer run state. Ignored for input requests. Returned by the lookup.
</ResponseField>

<ResponseField name="update_time" type="string">
  Output only. Last time the data transfer run state was updated. Returned by the lookup.
</ResponseField>

<ResponseField name="user_id" type="string">
  Deprecated. Unique ID of the user on whose behalf transfer is done. Returned by the lookup.
</ResponseField>
