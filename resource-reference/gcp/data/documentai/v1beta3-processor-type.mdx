`google_documentai_v1beta3_processor_type` is a real, live data source: `ubx.Data`/`data`/`ubx.data` (per language) executes this lookup at resolve time, against Google Cloud's own real API, and returns whatever it finds. It is never created, modified, or destroyed by ubx -- see [docs/schema.md's own "Amendment: data sources"] for the real wire shape this compiles to (`data_sources[]`, never `resources[]`).

## Result properties

<ResponseField name="allow_creation" type="bool">
  Whether the processor type allows creation. If true, users can create a processor of this processor type. Otherwise, users need to request access. Returned by the lookup.
</ResponseField>

<ResponseField name="available_locations" type="list(object)">
  The locations in which this processor is available. Returned by the lookup.
</ResponseField>

<ResponseField name="category" type="string">
  The processor category, used by UI to group processor types. Returned by the lookup.
</ResponseField>

<ResponseField name="launch_stage" type="string">
  Launch stage of the processor type Returned by the lookup.
</ResponseField>

<ResponseField name="sample_document_uris" type="list(string)">
  A set of Cloud Storage URIs of sample documents for this processor. Returned by the lookup.
</ResponseField>

<ResponseField name="type" type="string">
  The processor type, such as: `OCR_PROCESSOR`, `INVOICE_PROCESSOR`. Returned by the lookup.
</ResponseField>
