## Example

<Tabs>
  <Tab title="Go">
    ```go
    // ubx sdk gen --only google_pubsublite --lang go --out ./local-sdk
    // go.mod: replace github.com/ubiquex/ubx-sdk-google/sdk/go => ./local-sdk/google_pubsublite/sdk/go
    package main

    import (
    	ubx "github.com/ubiquex/ubx-sdk-go/runtime"
    	pubsublite "github.com/ubiquex/ubx-sdk-google/sdk/go/google_pubsublite/pubsublite"
    )

    func main() {
    	ubx.Main(ubx.Stack("payments", func() {
    		ubx.Intent(ubx.IntentInfo{Summary: "payments own topic"})

    		ubx.Resource(pubsublite.PubsubliteTopic, "ci-runner", pubsublite.PubsubliteTopicConfig{
    			Name: "ci-runner",
    		})
    	}))
    }
    ```
  </Tab>

## Properties

<ResponseField name="name" type="string">
  The name of the topic. Structured like: projects/&#123;project_number&#125;/locations/&#123;location&#125;/topics/&#123;topic_id&#125; Optional; if omitted, computed by Google Cloud.
</ResponseField>

<ResponseField name="partition_config" type="object">
  The settings for a topic's partitions. Optional; if omitted, computed by Google Cloud.
  <Expandable title="properties">
    <ResponseField name="capacity" type="object">
      The throughput capacity configuration for each partition. Optional.
      <Expandable title="properties">
        <ResponseField name="publish_mib_per_sec" type="number">
          Publish throughput capacity per partition in MiB/s. Must be &gt;= 4 and &lt;= 16. Optional.
        </ResponseField>
        <ResponseField name="subscribe_mib_per_sec" type="number">
          Subscribe throughput capacity per partition in MiB/s. Must be &gt;= 4 and &lt;= 32. Optional.
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="count" type="string">
      The number of partitions in the topic. Must be at least 1. Once a topic has been created the number of partitions can be increased but not decreased. Message ordering is not guaranteed across a topic resize. For more information see https://cloud.google.com/pubsub/lite/docs/topics#scaling_capacity Optional.
    </ResponseField>
    <ResponseField name="scale" type="number">
      DEPRECATED: Use capacity instead which can express a superset of configurations. Every partition in the topic is allocated throughput equivalent to `scale` times the standard partition throughput (4 MiB/s). This is also reflected in the cost of this topic; a topic with `scale` of 2 and count of 10 is charged for 20 partitions. This value must be in the range [1,4]. Optional.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="reservation_config" type="object">
  The settings for this topic's Reservation usage. Optional; if omitted, computed by Google Cloud.
  <Expandable title="properties">
    <ResponseField name="throughput_reservation" type="string">
      The Reservation to use for this topic's throughput capacity. Structured like: projects/&#123;project_number&#125;/locations/&#123;location&#125;/reservations/&#123;reservation_id&#125; Optional.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="retention_config" type="object">
  The settings for a topic's message retention. Optional; if omitted, computed by Google Cloud.
  <Expandable title="properties">
    <ResponseField name="per_partition_bytes" type="string">
      The provisioned storage, in bytes, per partition. If the number of bytes stored in any of the topic's partitions grows beyond this value, older messages will be dropped to make room for newer ones, regardless of the value of `period`. Optional.
    </ResponseField>
    <ResponseField name="period" type="string">
      How long a published message is retained. If unset, messages will be retained as long as the bytes retained for each partition is below `per_partition_bytes`. Optional.
    </ResponseField>
  </Expandable>
</ResponseField>
