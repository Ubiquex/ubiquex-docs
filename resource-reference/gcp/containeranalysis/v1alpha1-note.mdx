`google_containeranalysis_v1alpha1_note` defines a kind of metadata (e.g. a vulnerability or build provenance type) that Container Analysis occurrence(s) can be recorded against.

## Example

<Tabs>
  <Tab title="Go">
    ```go
    package main

    import (
    	ubx "github.com/ubiquex/ubx-sdk-go/runtime"
    	containeranalysis "github.com/ubiquex/ubx-sdk-google/sdk/go/google/containeranalysis"
    )

    func main() {
    	ubx.Main(ubx.Stack("example", func() {
    		ubx.Intent(ubx.IntentInfo{Summary: "example own v1alpha1 note"})

    		ubx.Resource(containeranalysis.V1alpha1Note, "example", containeranalysis.V1alpha1NoteConfig{
    			Name: "example",
    		})
    	}))
    }
    ```
  </Tab>
  <Tab title="TypeScript">

<ResponseField name="attestation_authority" type="object">
  Note kind that represents a logical attestation "role" or "authority". For example, an organization might have one `AttestationAuthority` for "QA" and one for "build". This Note is intended to act strictly as a grouping mechanism for the attached Occurrences (Attestations). This grouping mechanism also provides a security boundary, since IAM ACLs gate the ability for a principle to attach an Occurrence to a given Note. It also provides a single point of lookup to find all attached Attestation Occurrences, even if they don't all live in the same project. Optional; if omitted, computed by Google Cloud.
  <Expandable title="properties">
    <ResponseField name="hint" type="object">

Because the name of a Note acts as its resource reference, it is important to disambiguate the canonical name of the Note (which might be a UUID for security purposes) from "readable" names more suitable for debug output. Note that these hints should NOT be used to look up AttestationAuthorities in security sensitive contexts, such as when looking up Attestations to verify. Optional.
      <Expandable title="properties">
