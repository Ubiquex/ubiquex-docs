`google_bigtableadmin_app_profile` defines how a specific application connects to a Bigtable instance -- which cluster(s) it's routed to and the isolation guarantees it gets -- letting different apps sharing one instance be configured independently.

## Example

<Tabs>

    ```go
    package main

    import (
    	ubx "github.com/ubiquex/ubx-sdk-go/runtime"

    )

    func main() {
    	ubx.Main(ubx.Stack("example", func() {
    		ubx.Intent(ubx.IntentInfo{Summary: "example own app profile"})

    		ubx.Resource(bigtableadmin.AppProfile, "example", bigtableadmin.AppProfileConfig{

    		})
    	}))
    }
    ```

<ResponseField name="data_boost_isolation_read_only" type="object">
  Data Boost is a serverless compute capability that lets you run high-throughput read jobs and queries on your Bigtable data, without impacting the performance of the clusters that handle your application traffic. Data Boost supports read-only use cases with single-cluster routing. Optional; if omitted, computed by Google Cloud.

<ResponseField name="description" type="string">
  Long form description of the use case for this AppProfile. Optional; if omitted, computed by Google Cloud.
</ResponseField>

<ResponseField name="etag" type="string">
  Strongly validated etag for optimistic concurrency control. Preserve the value returned from `GetAppProfile` when calling `UpdateAppProfile` to fail the request if there has been a modification in the meantime. The `update_mask` of the request need not include `etag` for this protection to apply. See [Wikipedia](https://en.wikipedia.org/wiki/HTTP_ETag) and [RFC 7232](https://tools.ietf.org/html/rfc7232#section-2.3) for more details. Optional; if omitted, computed by Google Cloud.
</ResponseField>

<ResponseField name="multi_cluster_routing_use_any" type="object">
  Read/write requests are routed to the nearest cluster in the instance, and will fail over to the nearest cluster that is available in the event of transient errors or delays. Clusters in a region are considered equidistant. Choosing this option sacrifices read-your-writes consistency to improve availability. Optional; if omitted, computed by Google Cloud.
  <Expandable title="properties">
    <ResponseField name="cluster_ids" type="list(string)">
      The set of clusters to route to. The order is ignored; clusters will be tried in order of distance. If left empty, all clusters are eligible. Optional.
    </ResponseField>
    <ResponseField name="row_affinity" type="any">
      If enabled, Bigtable will route the request based on the row key of the request, rather than randomly. Instead, each row key will be assigned to a cluster, and will stick to that cluster. If clusters are added or removed, then this may affect which row keys stick to which clusters. To avoid this, users can use a cluster group to specify which clusters are to be used. In this case, new clusters that are not a part of the cluster group will not be routed to, and routing will be unaffected by the new cluster. Moreover, clusters specified in the cluster group cannot be deleted unless removed from the cluster group. Optional.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="name" type="string">
  The unique name of the app profile, up to 50 characters long. Values are of the form `projects/&#123;project&#125;/instances/&#123;instance&#125;/appProfiles/_a-zA-Z0-9*`. Optional; if omitted, computed by Google Cloud.
</ResponseField>

<ResponseField name="priority" type="string">
  This field has been deprecated in favor of `standard_isolation.priority`. If you set this field, `standard_isolation.priority` will be set instead. The priority of requests sent using this app profile. Optional; if omitted, computed by Google Cloud.
</ResponseField>

<ResponseField name="single_cluster_routing" type="object">
  Unconditionally routes all read/write requests to a specific cluster. This option preserves read-your-writes consistency but does not improve availability. Optional; if omitted, computed by Google Cloud.
  <Expandable title="properties">
    <ResponseField name="allow_transactional_writes" type="bool">
      Whether or not `CheckAndMutateRow` and `ReadModifyWriteRow` requests are allowed by this app profile. It is unsafe to send these requests to the same table/row/column in multiple clusters. Optional.
    </ResponseField>
    <ResponseField name="cluster_id" type="string">
      The cluster to which read/write requests should be routed. Optional.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="standard_isolation" type="object">
  Standard options for isolating this app profile's traffic from other use cases. Optional; if omitted, computed by Google Cloud.
  <Expandable title="properties">
    <ResponseField name="memory_config" type="any">
      If set, eligible single-row requests (currently limited to ReadRows) using this app profile will be routed to the memory layer. All eligible writes populate the memory layer. MemoryConfig can only be set if the AppProfile uses single cluster routing and the configured cluster has a memory layer enabled. Optional.
    </ResponseField>
    <ResponseField name="priority" type="string">
      The priority of requests sent using this app profile. Optional.
    </ResponseField>
  </Expandable>
</ResponseField>
