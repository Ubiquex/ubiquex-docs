---

`kubernetes_autoscaling_horizontal_pod_autoscaler` automatically adjusts a real Deployment or StatefulSet's own replica count based on observed CPU, memory, custom, or external metrics -- scaling out under real load and back in once it passes, without a human watching a dashboard. This is the `autoscaling/v2` shape, the real, current, preferred one -- Kubernetes' own per-API-group discovery signal confirms it, and it's the one this plain, unversioned typeName now resolves to. `v1` (`kubernetes_autoscaling_v1_horizontal_pod_autoscaler`), still served for compatibility, only ever supports a single CPU-utilization target; this v2 shape replaces that with a real `metrics` array supporting multiple concurrent metrics at once, plus real status conditions reporting whether the autoscaler is actually able to scale right now.
