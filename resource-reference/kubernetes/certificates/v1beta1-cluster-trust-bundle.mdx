The v1beta1 shape of `kubernetes_certificates_cluster_trust_bundle` -- ClusterTrustBundle's own beta API generation, kept being served alongside the now-stable v1 API this cluster's own pinned schema also carries. New trust bundles should target the stable `kubernetes_certificates_cluster_trust_bundle` instead.

## Example

<Tabs>
  <Tab title="Go">
    ```go
    package main

    import (
    	ubx "github.com/ubiquex/ubx-sdk-go/runtime"
    	certificates "github.com/ubiquex/ubx-sdk-kubernetes/sdk/go/kubernetes/certificates"
    )

    func main() {
    	ubx.Main(ubx.Stack("example", func() {
    		ubx.Intent(ubx.IntentInfo{Summary: "example own v1beta1 cluster trust bundle"})

    		ubx.Resource(certificates.V1beta1ClusterTrustBundle, "example", certificates.V1beta1ClusterTrustBundleConfig{
    			Name: "example",
    			Spec: map[string]any{"trust_bundle": "example"},
    		})
    	}))
    }
    ```

    <ResponseField name="trust_bundle" type="string" required>
      trustBundle contains the individual X.509 trust anchors for this bundle, as PEM bundle of PEM-wrapped, DER-formatted X.509 certificates. The data must consist only of PEM certificate blocks that parse as valid X.509 certificates. Each certificate must include a basic constraints extension with the CA bit set. The API server will reject objects that contain duplicate certificates, or that use PEM block headers. Users of ClusterTrustBundles, including Kubelet, are free to reorder and deduplicate certificate blocks in this file according to their own logic, as well as to drop PEM block headers and inter-block data. Required.
