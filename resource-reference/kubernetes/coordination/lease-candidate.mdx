`kubernetes_coordination_lease_candidate` registers one real instance of a control-plane component (like `kube-scheduler`) as competing for leadership during coordinated leader election, carrying its own identity, binary version, and emulation version -- real information the cluster uses to deterministically pick a leader during a rolling upgrade rather than picking whichever instance happened to grab the lease first.

Real, typed bindings generated directly from the real Kubernetes OpenAPI specification, in every SDK language -- every tab below is a complete, runnable program, not a fragment, real enough to save and run exactly as shown.
