title: "A real Helm release"
description: "Ship a real helm_release, ubx's own multi-provider stack in action."
---

A Helm release is a genuinely different provider from plain Kubernetes
resources. This tutorial ships one in the same stack as your secret,
using multi-provider support directly.

## Declare both providers

```bash
cat >> .ubx/config.hcl << 'EOF'
thirdparty_providers = {
  "hashicorp/kubernetes" = "2.31.0"
  "hashicorp/helm" = "2.13.0"
}
EOF
```

## Author it

```go
package main

import (
	ubx "github.com/ubiquex/ubx-sdk-go/runtime"
	release "github.com/ubiquex/ubx-sdk-helm/sdk/go/helm/release"
)

func main() {
	ubx.Main(ubx.Stack("payments", func() {
		ubx.Intent(ubx.IntentInfo{Summary: "payments migrator helm release"})

		ubx.Resource(release.Release, "payments-migrator", release.ReleaseConfig{
			Name:       "payments-migrator",
			Repository: "acme",
			Chart:      "migrator",
			Namespace:  "payments",
		})
	}))
}
```
```bash
ubx plan --from-code create_release.go --stack payments
```

```bash
Plan  payments · from create_release.go

  + helm_release.payments-migrator create  (hashicorp/helm)
      name: "payments-migrator"
      namespace: "payments"

delta: +1 create(s), ~0 change(s), -0 terminate(s)
```

Recorded on the resource itself: this one's real owning provider is
`hashicorp/helm`, not `hashicorp/kubernetes`, decided automatically.

## Ship it

```bash
ubx ship <hash>
```

```bash
  ✓ helm_release.payments-migrator : shipped
1 resource(s), 1 shipped, 0 failed
```

## What you just did

You shipped a genuinely different provider type, in the same stack, as
one connected decision, with the executor correctly dispatching it to
its own real provider binary.
