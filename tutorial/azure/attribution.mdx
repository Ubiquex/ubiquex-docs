Azure has its own real, distinct attribution backend, Activity Log.
This tutorial finds a real drift and reads the real actor behind it.

## Change something by hand

```bash
az storage queue metadata update --name pipeline-events \
  --account-name acmepayments --metadata team=payments
```

## Find it

```bash
ubx scan --stack payments --propose both
```

```bash
Drift found  payments.azurerm_storage_queue.pipeline-events

  drift_adopt   ...    record-only · records reality as signed
      ~ 1 attribute(s) changed: metadata
```

## See the real Azure attribution

```bash
ubx ship <adopt-hash>
ubx why payments.azurerm_storage_queue.pipeline-events
```

```bash
source: azure_audit
  actor: platform-admin@acme.onmicrosoft.com
  event: Microsoft.Storage/storageAccounts/queueServices/write, at ...
```

Azure's own real identity string and its own real operation name,
structured differently from AWS or GCP, carrying the same real
guarantee.
