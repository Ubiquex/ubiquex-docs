Same commands, `hashicorp/azurerm` instead of `hashicorp/aws`. Two real
resources, one referencing the other, shown in all five mediums.

## Set up a stack

```bash
mkdir payments-azure && cd payments-azure
ubx init --source hashicorp/azurerm --provider-version 3.116.0
```

## Author both resources

<Tabs>
  <Tab title="Markdown">
    ```bash
    cat > platform.md << 'EOF'
    Provision a storage account called "acmepayments" in resource group
    "payments-rg", region "eastus", standard tier, locally redundant.

    Create a storage queue called "pipeline-events" inside that account.
    EOF
    ubx plan --from-doc platform.md --stack payments
    ```
  </Tab>
  <Tab title="Go">
    ```go
    package main

    import (
    	ubx "github.com/ubiquex/ubx-sdk-go/runtime"
    	storage "github.com/ubiquex/ubx-sdk-azure/sdk/go/azurerm/storage"
    )

    func main() {
    	ubx.Main(ubx.Stack("payments", func() {
    		ubx.Intent(ubx.IntentInfo{Summary: "payments storage account and queue"})

    		account := ubx.Resource(storage.Account, "acmepayments", storage.AccountConfig{
    			Name:                    "acmepayments",
    			ResourceGroupName:       "payments-rg",
    			Location:                "eastus",
    			AccountTier:             "Standard",
    			AccountReplicationType:  "LRS",
    		})

    		ubx.Resource(storage.Queue, "pipeline-events", storage.QueueConfig{
    			Name:               "pipeline-events",
    			StorageAccountName: account.Field("name"),
    		})
    	}))
    }
    ```
  </Tab>
  <Tab title="TypeScript">
    ```bash
    git clone https://github.com/Ubiquex/ubx-sdk-azure.git
    ```
    ```typescript
    import { stack, intent, resource } from "@ubx/sdk";
    import { Account } from "./ubx-sdk-azure/sdk/typescript/azurerm/storage/account.ts";
    import { Queue } from "./ubx-sdk-azure/sdk/typescript/azurerm/storage/queue.ts";

    export default stack("payments", () => {
      intent({ summary: "payments storage account and queue" });

      const account = resource(Account, "acmepayments", {
        name: "acmepayments",
        resourceGroupName: "payments-rg",
        location: "eastus",
        accountTier: "Standard",
        accountReplicationType: "LRS",
      });

      resource(Queue, "pipeline-events", {
        name: "pipeline-events",
        storageAccountName: account.name,
      });
    });
    ```
    A real, local, cloned import, never a remote URL, the hermetic
    evaluator's own `--no-remote` flag refuses anything else.
  </Tab>
  <Tab title="Python">
    ```bash
    git clone https://github.com/Ubiquex/ubx-sdk-azure.git
    ```
    Save this file **inside** the cloned repo's own `sdk/python/`
    directory (alongside the `ubx/` namespace package it imports from),
    as `ubx-sdk-azure/sdk/python/create_platform.py`:
    ```python
    import ubx_sdk as ubx
    from azurerm.storage import Account, AccountConfig, Queue, QueueConfig

    def describe():
        ubx.intent("payments storage account and queue")

        account = ubx.resource(Account, "acmepayments", AccountConfig(
            name="acmepayments",
            resource_group_name="payments-rg",
            location="eastus",
            account_tier="Standard",
            account_replication_type="LRS",
        ))

        ubx.resource(Queue, "pipeline-events", QueueConfig(
            name="pipeline-events",
            storage_account_name=account.name,
        ))

    if __name__ == "__main__":
        ubx.run("payments", describe)
    ```

Every tab resolves to the exact same delta:

```bash
Plan  payments

  + azurerm_storage_account.acmepayments create
      name: "acmepayments"
      resource_group_name: "payments-rg"
      location: "eastus"
      account_tier: "Standard"
      account_replication_type: "LRS"

  + azurerm_storage_queue.pipeline-events create
      name: "pipeline-events"
      storage_account_name: $ref:payments.azurerm_storage_account.acmepayments.name

delta: +2 create(s), ~0 change(s), -0 terminate(s)
```

The queue's `storage_account_name` is a real reference, not a typed-in
string that could quietly drift out of sync if the account were ever
renamed.
