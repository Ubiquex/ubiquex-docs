description: "Draw one resource as a real D2 node and ship it."
---

The diagram medium is a structural parser, not an AI. This tutorial
draws one real resource in D2 and ships it, no drafting step at all.

## Write a diagram

```bash
cat > platform.d2 << 'EOF'
queue: "pipeline-events" {
  class: aws_sqs_queue
  message_retention_seconds: "1209600"
}
EOF
```

The `class` names the real provider type. Every other attribute is a
literal value, exactly as written.

## Plan it

```bash
ubx plan --from-diagram platform.d2 --stack payments
```

```bash
Plan  payments · from platform.d2

  + aws_sqs_queue.pipeline-events create
      message_retention_seconds: "1209600"

delta: +1 create(s), ~0 change(s), -0 terminate(s)

ubx-proposal: c53c22fae1ae...
next: ubx ship c53c22fae1ae...
```

No "drafting via..." line, this resolved instantly, structurally, with
no model involved anywhere.

## Ship it

```bash
ubx ship c53c22fae1ae...
```

```bash
  ✓ aws_sqs_queue.pipeline-events : shipped
1 resource(s), 1 shipped, 0 failed
```

## What you just did

You described a real resource as a diagram node and shipped it, with
zero AI involvement at any point, the diagram parser read your D2 file
directly and produced a fully resolved proposal.
