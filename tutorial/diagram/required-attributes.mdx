---
title: "Required attributes"
description: "Set an attribute a diagram can't express structurally, with ubx_required."
---

A diagram naturally shows structure, not every configuration detail. For
an attribute a real provider schema marks required, `ubx_required` is
the real, narrowly-scoped escape hatch.

## Add a role with a required policy

```bash
cat >> platform.d2 << 'EOF'
role: "ci-runner" {
  class: aws_iam_role
  ubx_required.assume_role_policy: "{\"Version\":\"2012-10-17\",\"Statement\":[{\"Effect\":\"Allow\",\"Principal\":{\"Service\":\"ec2.amazonaws.com\"},\"Action\":\"sts:AssumeRole\"}]}"
}
EOF
```

`assume_role_policy` is genuinely required by the real schema, `ubx_required` sets it as a literal, directly.

## Plan it

```bash
ubx plan --from-diagram platform.d2 --stack payments
```

```bash
Plan  payments · from platform.d2

  + aws_iam_role.ci-runner create
      assume_role_policy: { "Version": "2012-10-17", ... }

delta: +2 create(s), ~0 change(s), -0 terminate(s)
```

## Try setting something not required

```bash
cat >> platform.d2 << 'EOF'
extra: "extra" {
  class: aws_iam_role
  ubx_required.description: "not actually required"
}
EOF
```

```bash
ubx plan --from-diagram platform.d2 --stack payments
```

```bash
render: ubx_required.description refused -- "description" is not a
required attribute on aws_iam_role's own schema; ubx_required only
accepts genuinely required attributes
```

The escape hatch is scoped narrowly, on purpose. Anything not truly
required stays out of the diagram medium's own reach.

## What you just did

You used the one real, deliberate exception the diagram medium allows,
and saw it refuse to widen beyond its actual scope.
