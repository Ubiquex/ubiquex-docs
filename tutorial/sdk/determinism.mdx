The previous tutorial proved three languages resolve identically. This
one shows the actual mechanism that guarantees a single program is
consistent with *itself*, every time it runs.

## Resolve the same program twice

```bash
ubx resolve --from-code create_platform.go --out run1.json
ubx resolve --from-code create_platform.go --out run2.json
diff run1.json run2.json
```

```bash
(no output)
```

Identical output, byte for byte.

## What's actually happening underneath

Every SDK evaluation genuinely runs your program twice, silently, and
compares the two results before ever handing you one. You never see the
first run unless something's actually wrong.

If a program ever depended on something that isn't truly fixed, an
unordered map, a timestamp, the two runs would disagree, and resolution
would refuse outright rather than silently pick one.

## Why this matters for you directly

Your program has no access to the network, the filesystem, or the clock
while it runs. Its only real inputs are its own arguments. That's not a
restriction you have to remember to respect, it's structurally
enforced, the same hermetic sandbox every SDK evaluation runs inside.

## What you just did

You confirmed directly that determinism here isn't a promise you have
to trust, it's an active check that runs on every single resolution,
silently, before you ever see a result.
