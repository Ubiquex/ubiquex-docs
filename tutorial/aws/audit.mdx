By now your ledger has real history, from every earlier tutorial. This
one reads it back four real ways.

## Real, computed metrics

```bash
ubx stats
```

```bash
ubx stats: 20 proposal(s) total

By kind:
  adoption: 16
  change: 3
  drift_adopt: 1

Acceptance method:
  local: 19 (95%)
  pr_merge: 1 (5%)

Signed-flow drift resolution: 100% (1 of 1 surfaced drift(s) resolved)
```

Every number computed from your own real ledger, nothing asserted.

## Per-attribute provenance

```bash
ubx blame payments.aws_sqs_queue.pipeline-events
```

```bash
Blame  payments.aws_sqs_queue.pipeline-events

▸ 1 attribute(s) · set by 8224643bbbc5... (change) · ...
    message_retention_seconds: 345600

▸ 3 attribute(s) · set by 45f63ce10849... (change) · ...
    name: "pipeline-events"
    fifo_queue: false
```

Not just "this resource changed", exactly which proposal set each
specific value.

## A referenceable inventory

```bash
ubx addresses --stack payments
```

```bash
payments.aws_sqs_queue.pipeline-events
  provider: hashicorp/aws@6.54.0
  @payments.aws_sqs_queue.pipeline-events.id (always present)
  @payments.aws_sqs_queue.pipeline-events.arn (computed, known after ship)
  @payments.aws_sqs_queue.pipeline-events.message_retention_seconds (always present)
```

Every attribute already formatted as the literal `@...` form you'd
paste directly into a document or diagram, if another stack ever needs
to reference this queue.

Every hash recomputed from scratch, every link re-checked.
