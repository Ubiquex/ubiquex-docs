---
title: "Onboarding existing infrastructure"
description: "Bring real, already-existing AWS resources under the ledger."
---

Real infrastructure managed by Terraform for years can join ubx's
ledger directly, read once from its own state file.

## Point at a real state file

```bash
ubx scan --all --tfstate ./terraform.tfstate --stack legacy
```

```bash
adopted: legacy.aws_vpc.main
adopted: legacy.aws_subnet.public-a
...
12 adopted, 0 skipped, 0 attribute(s) redacted
next: ubx accept <hash>  (record them as-is, zero blast radius)
```

Every resource's identity came from the state file. Every actual value
came from a real, live read, never trusted from the file itself.

## Accept them

```bash
ubx accept <hash>
```

```bash
accepted <hash> (stack legacy)
12 resource(s) adopted, 0 changed
```

## Confirm they're real ledger entries now

```bash
ubx status --stack legacy
```

```bash
legacy.aws_vpc.main: adoption <hash> (accepted ...)
legacy.aws_subnet.public-a: adoption <hash> (accepted ...)
...
```

Twelve resources, previously invisible to ubx, now full, ordinary
ledger entries, driftable and revertable like anything you'd shipped
yourself.

## What you just did

You brought a real, years-old Terraform-managed environment under the
ledger, using its own state file only to bootstrap identity, never as a
source of truth for current values.
