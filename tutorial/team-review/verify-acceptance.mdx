---
title: "Re-verifying acceptance"
description: "Confirm a PR-merge acceptance still checks out against real history."
---

The whole point of PR-merge acceptance is that it's re-checkable,
forever. This tutorial re-checks it right now.

## Ask ubx to re-derive it

```bash
ubx why 45f63ce10849... --verify-acceptance --github-repo acme/infra
```

```bash
--- verify-acceptance ---
git: merge commit <sha> exists in .
git: proposal.json at that commit still hashes to 45f63ce10849...
github API: PR #42's approvers are unchanged ([roozbeh])
```

Every field was independently re-checked, not read back from a stored
claim.

## See what a real mismatch looks like

If a reviewer ever dismissed their approval after the fact:

```bash
ubx why 45f63ce10849... --verify-acceptance --github-repo acme/infra
```

```bash
github API: MISMATCH -- PR #42's approvers are now [], recorded
acceptance has [roozbeh]
```

The ledger's own record is still honest, it correctly recorded what
was true at acceptance time. This check tells you reality has since
moved, which is exactly what re-verification exists to catch.

## Run it across your whole ledger

```bash
ubx verify --repo-dir . --github-repo acme/infra
```

```bash
verify: 3 proposal(s) checked
chain: intact
acceptance: 3 re-derived, 0 convenience-tier (local), 0 inconclusive
```

Every real PR-merge acceptance in your ledger, re-checked in one
command.

## What you just did

You confirmed a real signature is still genuinely valid, not by
trusting a stored claim, but by independently re-deriving it against
real, current git history and the real GitHub API.
