---
title: "Accepting via a real merged PR"
description: "Open a real PR, merge it, derive acceptance from that merge."
---

Local acceptance means you, on your own machine. This tutorial signs a
proposal a stronger way, real review, in a real pull request.

## Resolve a proposal, don't accept it locally

```bash
ubx resolve --from-code create_platform.go --stack payments --out proposal.json
ubx propose proposal.json
```

```bash
ubx-proposal: 45f63ce108492f6581fe452cc96421ca50195abae1c365ec3b76d700c38a8974
```

## Commit it with the real trailer convention

```bash
git checkout -b add-queue
git add proposal.json
git commit -m "Add pipeline-events queue"
```

Edit the commit or PR description to include, verbatim:

```
ubx-proposal: 45f63ce108492f6581fe452cc96421ca50195abae1c365ec3b76d700c38a8974
```

## Open and merge the PR

Push the branch, open a real pull request, get it reviewed, merge it.

```bash
git push -u origin add-queue
```

## Derive acceptance from the merge

```bash
ubx accept --from-merge <merge-sha> \
  --proposal-file proposal.json \
  --github-repo acme/infra
```

```bash
accepted 45f63ce10849... (stack payments) via PR #42, 1 approver(s)
```

Nothing here was asserted. The merge commit's real existence, the
file's real content at that commit, the real approving reviewer, all
independently derived from git and the GitHub API.

## What you just did

You signed a real proposal by merging a genuinely reviewed pull
request, a stronger signature than typing `yes` locally, one that
anyone can independently re-check later.
