---
title: "ubx sdk"
description: "Generate typed, provider-verified bindings for the SDK."
---

Writing SDK code by hand against a real provider's hundreds of resource
types would mean either hand-typing every attribute name or trusting
loosely-typed maps. `ubx sdk gen` generates real, typed bindings
directly from a provider's own live schema, so `ubx.Resource(...)` calls
are compiler-checked against the exact wire attribute names the real
provider expects.

## Usage

```bash
ubx sdk gen --lang <go|ts|py> [flags]
```

## Examples

```bash
ubx sdk gen --lang go
```

```bash
generated 1682 resource type(s) for hashicorp/aws@6.54.0 -> sdk/generated/go/hashicorp-aws
```

## Flags

<ResponseField name="--lang" type="string" default="ts">
  Target language: `ts`, `go`, or `py` (default `ts`).
</ResponseField>

<ResponseField name="--out" type="string" default="sdk/generated">
  Directory to write generated bindings into (default `sdk/generated`).
</ResponseField>

<ResponseField name="--timeout" type="string" default="60s">
  Timeout per provider, launching and fetching its schema (default `60s`).
</ResponseField>

## Notes

Reads the real `[thirdparty_providers]` table from your config, the same source of
truth `ubx resolve`/`ubx ship` already read, there's no legacy
single-provider fallback here. Every language writes a real, repo-shaped
tree per provider, its own manifest, one directory per service, one file
per resource type, meant to be committed to git and reviewed like any
other generated code. Re-run this after bumping a provider's pinned
version.
