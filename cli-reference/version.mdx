---
title: "ubx version"
description: "Print the exact build ubx is running."
---

Knowing exactly which build you're running matters more than it sounds
like it should. If a bug gets fixed, or a feature ships, the only way to
be sure your installed binary actually has it is to check its real
build identity, not just trust that a recent-looking install is
current.

`ubx version` prints a string that's never ambiguous about what it was
built from: the release version if it's a real tagged release, `dev` if
not, always with the exact short commit it was compiled at, and a
`-dirty` suffix if that build had uncommitted changes on top of the
commit it reports.

## Usage

```bash
ubx version
```

## Examples

A real release build:

```bash
ubx version
```

```bash
0.2.0+8f2a1b3
```

A local development build, with uncommitted changes on top:

```bash
ubx version
```

```bash
dev+8f2a1b3-dirty
```

## Flags

This command takes no flags beyond the standard `-h`/`--help`.

## Notes

The `-dirty` suffix exists specifically to catch a real, easy-to-make
mistake: rebuilding from a commit that looks right, but actually has
uncommitted local changes sitting on top of it. Relying on the commit
suffix alone can't distinguish "built from exactly that commit" from
"built from that commit plus whatever's currently sitting uncommitted,"
which matters most in exactly the moment you're re-testing a fix.
