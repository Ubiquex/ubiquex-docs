---
title: "ubx revert-plan"
description: "Emit the reconciliation steps for an accepted revert, never applies anything itself."
---

Once a `drift_revert` proposal is accepted, someone still has to
actually make the correction happen in the real cloud. `ubx revert-plan`
never does that itself, it emits exactly what needs to happen: a
human-readable list of changed attributes, and, with `--tf-dir`, a real
corrective diff for whatever's safely rewritable plus a manual-steps
list for whatever isn't.

## Usage

```bash
ubx revert-plan <proposal-id> [--tf-dir <dir>]
```

## Examples

```bash
ubx revert-plan 37b097a1d5e0...
```

```bash
--- plan ---
payments.aws_sqs_queue.pipeline-events: message_retention_seconds: 1209600 -> 86400

no --tf-dir given -- make the correction above in cloud via your own tooling; ubx never makes it for you
```

With a `.tf` directory, a real corrective diff:

```bash
ubx revert-plan 37b097a1d5e0... --tf-dir ./terraform
```

```bash
--- plan ---
payments.aws_sqs_queue.pipeline-events: message_retention_seconds: 1209600 -> 86400

--- .tf diff ---
--- main.tf (before)
+++ main.tf (after)
@@ -12,7 +12,7 @@
-  message_retention_seconds = 1209600
+  message_retention_seconds = 86400
```

## Flags

<ResponseField name="--ledger-dir" type="string" default=".">
  Root directory containing `ledger/` and `.ubx/` (default `.`).
</ResponseField>

<ResponseField name="--stack" type="string">
  Which stack's ledger to open. Required only for a remote ledger store.
</ResponseField>

<ResponseField name="--tf-dir" type="string">
  Directory of `.tf` files to compute a corrective diff against. Optional, never written to.
</ResponseField>

## Notes

This command never writes a file and never touches real infrastructure,
on purpose. Making the actual correction, to source or to the live
resource, is deliberately left to your own tooling, the executor's trust
model doesn't yet extend to applying a revert automatically.
