---
title: "ubx blame"
description: "Per-attribute provenance: which proposal last set each attribute, and who signed it."
---

`ubx why` explains a resource's whole history. `ubx blame` goes one
level deeper, per attribute. For a resource with a dozen fields set
across several changes over months, this answers exactly which proposal
set this one specific value, not just that the resource changed at some
point.

## Usage

```bash
ubx blame <stack>.<type>.<name> [flags]
```

## Examples

```bash
ubx blame payments.aws_sqs_queue.pipeline-events
```

```bash
Blame  payments.aws_sqs_queue.pipeline-events

▸ 1 attribute(s) · set by 8224643bbbc5... (change) · 2026-08-05T18:02:00Z
    message_retention_seconds: 1209600

▸ 4 attribute(s) · set by 45f63ce10849... (change) · 2026-08-04T18:07:04Z
    name: "pipeline-events"
    fifo_queue: false
    · 2 provider default(s) hidden -- --all to show
```

## Flags

<ResponseField name="--ledger-dir" type="string" default=".">
  Root directory containing `ledger/` and `.ubx/` (default `.`).
</ResponseField>

<ResponseField name="--all">
  Show every attribute, including zero/null/empty provider defaults hidden by default.
</ResponseField>

<ResponseField name="--json">
  Emit one JSON document instead of human text.
</ResponseField>

<ResponseField name="--full-hashes">
  Render every hash in full.
</ResponseField>

## Notes

Entries that share identical provenance, the same proposal, the same
acceptance, are grouped under one header rather than repeated per
attribute, since one proposal usually sets several attributes at once.
A destroyed resource still blames cleanly, it shows the final,
pre-destroy state and names the proposal that removed it.
