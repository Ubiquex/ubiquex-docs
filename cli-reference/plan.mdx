---
title: "ubx plan"
description: "Resolve any medium into a reviewable draft, saved for ubx ship."
---

`ubx plan` is the fast, terraform-shaped path through this project's own
four-verb ceremony: it fuses drafting, resolving, and previewing into
one command, rendering the full receipt right here and saving the
result for `ubx ship` to pick up later by hash. Nothing about it
touches the ledger, it's preview and staging, not a signed decision.

It accepts any of the four mediums this project supports: a
hand-written intent file, an SDK program (`--from-code`), a markdown
document (`--from-doc`), or a D2 diagram (`--from-diagram`). Run with no
arguments at all in a directory with exactly one recognizable medium
file, and it detects which one you meant automatically, never guessing
when more than one candidate exists.

## Usage

```bash
ubx plan [intent-file] [flags]
ubx plan --from-doc <file>.md --stack <stack>
ubx plan --from-diagram <file>.d2 --stack <stack>
ubx plan --from-code <entry>.go|.ts|.py
```

## Examples

Planning from a real SDK program:

```bash
ubx plan --from-code create_platform.go
```

```bash
Plan  payments · from create_platform.go

  + aws_sqs_queue.pipeline-events create

delta: +1 create(s), ~0 change(s), -0 terminate(s)
blast radius: +1 ~0 -0

ubx-proposal: 45f63ce10849...
next: ubx ship 45f63ce10849...
```

Planning with no arguments, one candidate file found automatically:

```bash
ubx plan
```

```bash
Plan  payments · from platform.md
...
```

## Flags

<ResponseField name="--from-code" type="string">
  Evaluate a TypeScript, Go, or Python SDK program, dispatched by file extension.
</ResponseField>

<ResponseField name="--from-doc" type="string">
  Path to a markdown document, transcribed via the configured `[intent]` provider.
</ResponseField>

<ResponseField name="--from-diagram" type="string">
  Path to a `.d2` diagram, transcribed from its real topology.
</ResponseField>

<ResponseField name="--stack" type="string">
  Target stack name. Required with `--from-doc` or `--from-diagram`.
</ResponseField>

<ResponseField name="--ledger-dir" type="string" default=".">
  Root directory containing `ledger/` and `.ubx/`, also where the plan is saved (default `.`).
</ResponseField>

<ResponseField name="--source / --provider-version / --provider" type="string">
  Same provider selection as `ubx ship`.
</ResponseField>

<ResponseField name="--out" type="string">
  Additionally write the full resolved proposal to this path.
</ResponseField>

<ResponseField name="--summary" type="string">
  Sets `intent.summary` for a diagram draft, which has no prose to derive one from.
</ResponseField>

<ResponseField name="--neighbor-ledger" type="list(string)">
  `<stack>=<path>`, overrides a diagram's cross-stack reference convention. Repeatable.
</ResponseField>

<ResponseField name="--known-dependent" type="list(string)">
  A neighbor stack's ledger directory to check for cross-stack orphan references. Repeatable.
</ResponseField>

<ResponseField name="--full-hashes">
  Render every hash in full.
</ResponseField>

<ResponseField name="--show-defaults / --hide-defaults">
  Force the "AI defaults" block open or collapsed, overriding config.
</ResponseField>

<ResponseField name="--timeout" type="string" default="120s">
  One shared budget for provider acquisition, drafting, and evaluation (default `120s`).
</ResponseField>

## Notes

The saved plan lives at `.ubx/plans/<hash>.json`, addressed by content
hash, never a name you choose. `ubx ship <hash>` (or any unique prefix
of it) looks there directly. This file is a draft, not a ledger entry,
it carries no weight until something actually accepts or ships it.
