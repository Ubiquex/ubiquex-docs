## Download a release (recommended)

Pre-built binaries for darwin/linux × amd64/arm64 are published to
[GitHub Releases](https://github.com/Ubiquex/ubiquex/releases) starting at
`v0.1.0`. The repo is currently private, so use the `gh` CLI (it handles auth
for you) rather than a plain `curl`:

```bash
gh release download v0.1.0 --repo Ubiquex/ubiquex \
  --pattern 'ubx_0.1.0_darwin_arm64.tar.gz' --pattern 'checksums.txt'
```

Replace `darwin_arm64` with your platform: `darwin_amd64`, `linux_amd64`, or
`linux_arm64`.

Verify the checksum before running anything:

```bash
grep ubx_0.1.0_darwin_arm64 checksums.txt | shasum -a 256 -c -
```

(`sha256sum -c` works the same way if you don't have `shasum`.)

Extract, make it executable, and put it on your `PATH`:

```bash
tar -xzf ubx_0.1.0_darwin_arm64.tar.gz
chmod +x ubx
sudo mv ubx /usr/local/bin/ubx
```

Confirm it's the right binary:

```bash
ubx version
```

## Build from source instead

You need [Go](https://go.dev) 1.26 or later and a working `git` installation.

```bash
git clone https://github.com/Ubiquex/ubiquex.git
cd ubiquex
go build -o ubx ./cmd/ubx
```

This produces a single `ubx` binary in the current directory. Move it onto your
`PATH`, or invoke it as `./ubx`. A source build reports its version as
`dev+<commit>` rather than a release tag — see [`ubx version`](/cli/version).

```bash
./ubx version
```

## What you'll also need

- **A Terraform provider binary** for whatever you're reading — cloud
  resources, or a Kubernetes cluster/Helm releases. ubx speaks the Terraform
  provider wire protocol directly, to any provider binary, not just AWS's.
  `ubx scan`/`ubx accept` can acquire and verify one for you
  (`--source hashicorp/aws --provider-version <version>`, or
  `--source hashicorp/google --provider-version <version>` for GCP, or
  `--source hashicorp/azurerm --provider-version <version>` for Azure, or
  `--source hashicorp/kubernetes --provider-version <version>` /
  `--source hashicorp/helm --provider-version <version>` for a cluster), or
  you can point at a binary you already have
  (`--provider /path/to/terraform-provider-aws`).
- **Credentials** for whichever cloud (or cluster) you're reading, in your
  environment — ubx uses whatever the provider binary itself picks up (the
  same credential chain Terraform's own providers use): AWS's usual chain,
  `GOOGLE_APPLICATION_CREDENTIALS`/`gcloud auth application-default login`
  for GCP, Azure's own default credential chain (environment variables,
  managed identity, or a working `az login` session — the same one
  `--provider-config '{"subscription_id":"...","use_cli":true,"features":[{}]}'`
  picks up) for Azure, or a working `kubectl` context (`~/.kube/config` and
  `--provider-config '{"config_path":"...","config_context":"..."}'`) for
  `hashicorp/kubernetes`/`hashicorp/helm` — see
  [Kubernetes and Helm](/cli/lookup#kubernetes-and-helm).
- **A GitHub personal access token** (`GITHUB_TOKEN`), only if you're using
  PR-merge acceptance or the drift-surfacing features — see
  [Attribution](/concepts/attribution) and the CLI reference for `ubx accept`
  and `ubx scan`.

## Next

Run [`ubx init`](/cli/init) to write a runnable [`.ubx/config`](/cli/config)
— your stack, provider, and region defaults, so daily commands stop
repeating them. Give it a provider by flag (or answer the short prompt it
asks if you don't) and the very next command can drop `--stack`/`--source`
entirely:

```text
$ ubx init --source hashicorp/aws --provider-version 6.60.0 --region us-east-1
wrote .ubx/config.hcl
next: write an intent file and run `ubx plan <file>.json`, or `ubx plan --from-doc <file>.md --stack payments` -- see https://github.com/Ubiquex/ubiquex-docs, cli/config
```

Then continue to [Proposal](/concepts/proposal) for the mental model,
[The two-step flow](/guides/plan-ship-flow) if you're creating something
new (`ubx plan` + `ubx ship`), or jump straight to the
[CLI reference](/cli/scan) if you already know what you're looking for.
