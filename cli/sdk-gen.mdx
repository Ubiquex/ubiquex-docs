---
title: "ubx sdk gen"
description: "Generate typed TypeScript, Go, or Python bindings for every provider declared in [providers] -- local, never published"
---

```text
ubx sdk gen [--lang ts|go|py] [flags]
```

Reads `.ubx/config`'s own [`[providers]` table](/cli/config#multi-provider-stacks)
(the same source of truth [`ubx resolve`](/cli/resolve)/[`ubx ship`](/cli/ship)
already read), acquires each declared provider's real binary at its pinned
version, dumps its real schema (no `Configure`, no credentials needed -- a
pure local gRPC call against the launched binary), and writes a
**repo-shaped tree** of idiomatic bindings under `--out/<lang>/`, in the
language named by `--lang` (`ts`, the default, `go`, or `py`), whose
generated field map maps back to the provider's real wire attribute names
at evaluation time.

Every language writes the same shape: `--out/<lang>/<source-sanitized>/`,
its own manifest stub (`package.json` for TS, `go.mod` for Go,
`pyproject.toml` for Python), one directory per AWS-service boundary
derived from each resource type's own wire name (`aws_ecr_*` → `ecr`,
`aws_iam_*` → `iam`, ...), one file per resource type. `--lang` is its
own path segment specifically so generating multiple languages against
the same `--out` never interleaves their manifests/source trees into one
directory.

<Note>
  Go specifically also *requires* this shape to compile at all: a flat
  single-file/single-package layout hits a real Go compiler limit
  (`internal compiler error: NewBulk too big`) once a package holds
  enough of a real provider's 1,682 types' worth of declarations,
  unrelated to naming. TypeScript's `deno check` and a real Python
  `import` do NOT hit an equivalent limit -- checked directly, not
  assumed -- but write the same repo-shaped structure anyway, for
  reviewability and consistency across languages.
</Note>

Always regenerates from the exact config-pinned version's real,
freshly-acquired schema -- never a stale cache from a different version.
Generated files are meant to be **committed to git** like any other
reviewable generated code; re-run this command after bumping a provider's
pinned version in `[providers]`.

<Note>
  `ubx sdk gen` requires a real `[providers]` table -- unlike `ubx
  resolve`/`ubx ship`, it has no legacy single-`--provider`/`--source`
  fallback. Codegen is a multi-provider-stacks-era feature; there's no
  earlier CLI shape it needs to stay compatible with.
</Note>

## Flags

| Flag | Description |
| --- | --- |
| `--lang string` | target language for generated bindings: `ts`, `go`, or `py` (default `ts`) |
| `--out string` | root directory for the generated repo-shaped tree(s), one per `--lang` under `<out>/<lang>/<source-sanitized>/` (default `sdk/generated`) |
| `--timeout duration` | timeout for launching each provider and fetching its schema -- applied **per provider**, not once for the whole command (default `1m0s`) |
| `-h`, `--help` | help for gen |

Every generated type name drops the redundant `Aws<Service>` prefix,
since the directory already encodes provider+service -- `ecr.Repository`,
never `generated.AwsEcrRepository` -- identically across all three
languages. The runtime binding's own wire type (`wireType`/`WireType`/
`wire_type`) always carries the real, full, unshortened wire type string
(`"aws_ecr_repository"`), regardless of what the identifier dropped.

<Note>
  The AWS-service boundary is derived mechanically from each wire type's
  own name (`<provider>_<service>_<local...>`), not from a hand-curated
  AWS-service taxonomy -- `ubx sdk gen` stays fully offline, with no
  network-fetched taxonomy lookup. This is exact for services that always
  carry an explicit prefix in their wire names (`ecr`, `iam`, `sqs`, ...)
  but not a faithful reproduction of AWS's own real service grouping for
  a subset of EC2/VPC "core" resources whose wire names predate that
  convention (`aws_vpc`, `aws_instance`, `aws_subnet`, and similar) --
  these land in their own small package (e.g. Go's `vpc.Vpc`) rather than
  a single curated `ec2` package. See the [SDK Reference](/sdk) for the
  full account.
</Note>

A service or resource name that collides with the target language's own
reserved words is escaped with a trailing underscore, checked separately
per language (not assumed to transfer from one language to another):

- **Go**: a real language keyword (`default` → `default_/`) or a name
  the `go` tool itself treats specially (`main` → `main_/`, since a
  package literally named `main` is treated as a command).
- **Python**: a real language keyword -- `lambda` is both a Python
  keyword and a real 20-type AWS service, so it becomes `lambda_/`.
- **TypeScript**: no escaping needed at all -- ES module resolution is
  purely string-based, so a directory literally named `default/`,
  `main/`, or `lambda/` is unremarkable to Deno.

## Example: TypeScript

```toml .ubx/config
[providers]
"hashicorp/aws" = "6.54.0"
```

```text
$ ubx sdk gen --out sdk/generated
generated 1682 resource type(s) for hashicorp/aws@6.54.0 -> sdk/generated/ts/hashicorp-aws
```

```text sdk/generated/ts/hashicorp-aws/ (excerpt)
package.json                        # name "@ubx/sdk-aws"
ecr/
  doc.ts                            # banner + __ubxSourceProvenance (once per directory)
  repository.ts
  repository_policy.ts
  lifecycle_policy.ts
  ...
iam/
  doc.ts
  role.ts
  role_policy_attachment.ts
  ...
```

Each resource type gets a `Config` interface (settable fields), an `Attrs`
interface (every field, including computed-only ones like `id`/`arn`), and
a runtime binding object a program passes to `resource()`:

```typescript sdk/generated/ts/hashicorp-aws/ecr/repository.ts (excerpt)
export interface RepositoryConfig {
  forceDelete?: boolean | Computed<boolean>;
  imageTagMutability?: string | Computed<string>;
  name: string | Computed<string>;
  // ...every other real aws_ecr_repository settable attribute
}

export interface RepositoryAttrs {
  arn: string;
  id: string;
  // ...every field, plain types -- Computed<T> wrapping happens once,
  // generically, when a resource() call returns a handle
}

export const Repository: ResourceBinding<RepositoryConfig, RepositoryAttrs> = {
  wireType: "aws_ecr_repository",
  fields: {
    forceDelete: "force_delete",
    imageTagMutability: "image_tag_mutability",
    name: "name",
    // ...
  },
};
```

A field is only ever settable in `Config` if the real schema marks it
`Required` or `Optional` -- a pure output attribute like `id` never
appears there, only in `Attrs`. A program imports the specific resource
file it needs:

```typescript
import { resource } from "@ubx/sdk";
import { Repository } from "./generated/ts/hashicorp-aws/ecr/repository.ts";

resource(Repository, "app-images", { name: "app-images" });
```

## Example: Go

```text
$ ubx sdk gen --lang go --out sdk/generated
generated 1682 resource type(s) for hashicorp/aws@6.54.0 -> sdk/generated/go/hashicorp-aws
```

The tree is structured, and named, after
[Pulumi's own real repo+package convention](https://github.com/pulumi/pulumi-aws):

```text sdk/generated/go/hashicorp-aws/ (excerpt)
go.mod                               # module github.com/ubiquex/ubx-sdk-aws
ecr/
  doc.go                             # package banner + SourceProvenance (once per package)
  repository.go
  repository_policy.go
  lifecycle_policy.go
  ...
iam/
  doc.go
  role.go
  role_policy_attachment.go
  ...
```

Each resource type gets a `Config` struct (settable fields, every field
typed `any`) and a runtime binding value a program passes to
`sdk.Resource()`:

```go sdk/generated/go/hashicorp-aws/ecr/repository.go (excerpt)
package ecr

type RepositoryConfig struct {
	ForceDelete         any
	ImageTagMutability   any
	Name                 any
	// ...every other real aws_ecr_repository settable attribute
}

var Repository = sdk.ResourceBinding{
	WireType: "aws_ecr_repository",
	Fields: sdk.FieldMap{
		"ForceDelete":        sdk.FieldSpec{WireName: "force_delete"},
		"ImageTagMutability": sdk.FieldSpec{WireName: "image_tag_mutability"},
		"Name":               sdk.FieldSpec{WireName: "name"},
		// ...
	},
}
```

A program imports the specific service package it needs:

```go
import (
	sdk "github.com/ubiquex/ubx-sdk-go/runtime"
	ecr "github.com/ubiquex/ubx-sdk-aws/ecr"
)

sdk.Resource(ecr.Repository, "app-images", ecr.RepositoryConfig{
	Name: "app-images",
})
```

No separate `Attrs` type, unlike TypeScript -- Go's `Computed` has no
static per-field shape (`.Field(name)` drills in dynamically regardless
of what it's addressing), so there's nothing for a generated `Attrs`
type to describe.

## Example: Python

```text
$ ubx sdk gen --lang py --out sdk/generated
generated 1682 resource type(s) for hashicorp/aws@6.54.0 -> sdk/generated/py/hashicorp-aws
```

```text sdk/generated/py/hashicorp-aws/ (excerpt)
pyproject.toml                      # name "ubx-sdk-aws"
ecr/
  __init__.py                       # Python's own real package marker; banner + SOURCE_PROVENANCE
  repository.py
  repository_policy.py
  lifecycle_policy.py
  ...
iam/
  __init__.py
  role.py
  role_policy_attachment.py
  ...
```

Each resource type gets a `@dataclass` Config class (settable fields,
every field typed `Any`) and a runtime binding value a program passes to
`sdk.resource()`:

```python sdk/generated/py/hashicorp-aws/ecr/repository.py (excerpt)
@dataclasses.dataclass
class RepositoryConfig:
    force_delete: Any = None
    image_tag_mutability: Any = None
    name: Any = None
    # ...every other real aws_ecr_repository settable attribute

Repository = sdk.ResourceBinding(
    wire_type="aws_ecr_repository",
    fields={
        "force_delete": sdk.FieldSpec(wire_name="force_delete"),
        "image_tag_mutability": sdk.FieldSpec(wire_name="image_tag_mutability"),
        "name": sdk.FieldSpec(wire_name="name"),
        # ...
    },
)
```

No case conversion needed for field names at all here, unlike
TypeScript's camelCase or Go's PascalCase -- every real provider wire
name this project generates against is already a valid Python
identifier verbatim (lowercase-with-underscores). The one real exception
is a wire name that collides with a Python keyword (e.g. a field
literally named `class`), closed with a trailing underscore (`class_`) --
the same convention `lambda_`, above, uses at the service-directory
level. No separate `Attrs` type, same reasoning as Go's. A program
imports the specific service package it needs (`PYTHONPATH` including
`sdk/generated/py/hashicorp-aws` itself):

```python
from ecr.repository import Repository, RepositoryConfig
import ubx_sdk as sdk

sdk.resource(Repository, "app-images", RepositoryConfig(name="app-images"))
```

## Offline after generation

`ubx sdk gen` is the one step in the SDK authoring flow that touches the
network (to acquire a provider binary, if it isn't already cached; the
first `--lang py` evaluation also downloads and caches a CPython-WASI
build, ~40MB, separately from this command -- see [the SDK Reference's
own Python evaluator section](/sdk#the-python-evaluator)).
[`ubx resolve --from-code`](/cli/resolve#authoring-in-typescript) never
touches the network to evaluate -- it evaluates a program against
whatever bindings already exist on disk, inside a hermetic sandbox with
no network access at all (Go's own evaluator additionally sets
`GOPROXY=off` at build time, so a program's `go.mod` can't reach for an
unfetched dependency mid-evaluation either). This is deliberate:
generation and evaluation are separate, explicit steps, the same way
`ubx propose --from-doc` (network) and `ubx resolve` (offline) are
already two separate commands.

## Runtime and generated-bindings publish status

TypeScript's `@ubx/sdk` (`stack`, `resource`, `secret`, `cross`,
`intent`, `Computed<T>`) is embedded directly inside the `ubx` binary and
made available to the evaluator automatically -- you don't need to
install anything for `ubx resolve --from-code` to work with a `.ts`
entry. It's also genuinely published, for real, on
[JSR](https://jsr.io/@ubx/sdk) (`jsr:@ubx/sdk`) -- useful for editor/IDE
type-checking outside the evaluator. It is **not** meaningfully published
on npm: an `@ubx/sdk` package exists there too, but as a deliberate
placeholder pointing at the real JSR package, not the real thing itself.

Go's `github.com/ubiquex/ubx-sdk-go` (`sdk.Stack`, `sdk.Resource`,
`sdk.Secret`, `sdk.Cross`, `sdk.Intent`, `sdk.Main`, `*sdk.Computed`) is
genuinely published to the real public Go module proxy -- a plain
`require github.com/ubiquex/ubx-sdk-go v0.0.0` in your own `go.mod`
resolves it with no `replace` directive and no credentials needed.

Python's `ubx_sdk` (`sdk.stack`, `sdk.resource`, `sdk.secret`,
`sdk.cross`, `sdk.intent`, `sdk.run`, `sdk.Computed`) is embedded inside
the `ubx` binary and made available to the evaluator automatically, so
you don't need `pip install` anything for `ubx resolve --from-code` to
work with a `.py` entry. It's also genuinely published, for real, on
[PyPI](https://pypi.org/project/ubx-sdk/) (`pip install ubx-sdk`) --
useful for editor/IDE type-checking, or for using generated bindings
outside the evaluator entirely.

**The generated bindings tree itself** (this command's own `--out`
output -- `package.json`/`go.mod`/`pyproject.toml` named `@ubx/sdk-aws`/
`ubx-sdk-aws`/etc.) is never published BY `ubx sdk gen` itself, in any
language -- it's a repo-*shaped* local directory (ready to become its
own real repo), not a real package this command pushes anywhere;
whether/how it becomes one is left entirely to you (or CI).

<Note>
  **In practice, this has already happened, repeatedly.** This project
  maintains 12 real, separately-hosted, per-(provider,language) bindings
  repos this exact way -- `ubx-sdk-aws-go`, `ubx-sdk-aws-ts`,
  `ubx-sdk-aws-py`, and the same three-language row for Google,
  Kubernetes, and Azure. Each was seeded with a real `ubx sdk gen --out .`
  run, then manually pushed and renamed (the mechanical, unsuffixed
  `ubx-sdk-aws` this command derives isn't the real repo's own final
  name -- see the [SDK Reference](/sdk#published-packages) for the
  full list and the naming distinction). Each is kept current
  automatically by a real GitHub Actions workflow: a scheduled + manually
  dispatchable check against the real Terraform Registry API, which
  regenerates and opens a PR on a version bump -- never auto-merges. This
  is the recommended way to keep a real pushed bindings repo current,
  rather than re-running this command by hand.
</Note>
