---
title: "ubx revert-plan"
description: "Emit the reconciliation plan for an accepted drift_revert proposal -- never applies anything"
---

```text
ubx revert-plan <proposal-id> [--tf-dir <dir>] [flags]
```

Takes an already-*accepted* `drift_revert` proposal and prints the
reconciliation artifact a human (or their own tooling) needs to actually fix
cloud: what changed, and what restoring it requires. **`ubx revert-plan`
never writes a file and never touches cloud** — unlike [`ubx writeback`](/cli/writeback),
it has no `--write` flag at all. Applying the correction, to `.tf` source or
to the live resource, is the operator's own tooling to run; this command only
ever emits.

<Note>
  `ubx revert-plan` still never applies anything, even now that
  [`ubx ship`](/cli/ship) exists. Reach for `ubx ship` when you want `ubx`
  itself to execute the revert; reach for `ubx revert-plan` pre-acceptance,
  or whenever you'd rather apply the correction through your own tooling —
  and it's still the only path for an attribute `ubx ship` declines (a
  redacted restore target, see [Secrets](/concepts/secrets)).
</Note>

## Flags

| Flag | Description |
| --- | --- |
| `--ledger-dir string` | root directory containing `ledger/` and `.ubx/` (default `.`) |
| `--stack string` | which stack's ledger to open — required only when `.ubx/config`'s [`[ledger]`](/concepts/ledger-stores) store is a remote store, since a bare proposal-id argument carries no stack of its own; unused for the default git store |
| `--tf-dir string` | directory containing `.tf` files to compute a corrective diff against (optional) — never written to |
| `-h`, `--help` | help for revert-plan |

## Example: the plan alone (no `--tf-dir`)

Always produced, regardless of whether `--tf-dir` is given: one line per
changed attribute, current (drifted) value → restore-to (ledger-truth)
value.

```text
$ ubx revert-plan 3a0f78f5733f8aae0242e884035fb71d52b28f42128c8e28c9fe2fa25fc6a575 --ledger-dir .
--- plan ---
payments.fake_widget.api-cache: tags.env: "staging" -> "prod"

no --tf-dir given -- apply the correction above to cloud via your own tooling; ubx never applies it
```

## Example: a redacted attribute

An attribute the provider flagged `Sensitive` (see
[Secrets](/concepts/secrets)) renders `(redacted)` on both sides of the
plan — never the salted hash, and never the real value:

```text
$ ubx revert-plan 943b70c0f1bc0bf3cd2e744a4b9338ffae7af7ebd7dc06500a1e28a186440c66 --ledger-dir .
--- plan ---
payments.fake_db_instance.payments-db: master_password: (redacted) -> (redacted)

no --tf-dir given -- apply the correction above to cloud via your own tooling; ubx never applies it
```

With `--tf-dir`, a redacted attribute is declined by the same mechanism
`ubx writeback` uses (see [`ubx writeback`'s own redacted example](/cli/writeback#example-a-redacted-attribute-is-always-declined))
and lands in the manual-steps section, never written into `.tf` as a
literal — `ubx` genuinely can't know the real value to restore, redacted
or not, so this is always a manual step regardless of `--tf-dir`.

## Example: `--tf-dir`, a mixed literal/non-literal case

Reuses the exact same [`tfwrite`](/cli/writeback) machinery `ubx writeback`
uses — fed a modification whose *after* value is already the restore
target, so "reverse direction" is semantic, not a different code path.
Attributes that are plain literals in `.tf` get a real diff; anything
expressed as a variable, function call, or interpolation is declined and
listed in a manual-steps section instead, exactly like `ubx writeback`
declines the same shape of attribute:

```text
$ ubx revert-plan 0f146f3d38e261dc97eea65f039040759822d72c19675abfe7b0d8f7ce79ba61 --ledger-dir . --tf-dir tf
--- plan ---
s.aws_instance.web: ami: "ami-new" -> "ami-old"
s.aws_instance.web: instance_type: "t3.large" -> "t3.medium"

--- .tf diff ---
--- tf/compute.tf (before)
+++ tf/compute.tf (after)
@@ -1,4 +1,4 @@
 resource "aws_instance" "web" {
-  instance_type = "t3.large"
+  instance_type = "t3.medium"
   ami           = var.ami_id
 }


--- manual steps ---
ami -- current value is not a literal: Variables not allowed (current value: var.ami_id) -- apply this correction manually
```

Nothing is written for a declined attribute — the file is left exactly as
it was. A resource block `--tf-dir` doesn't contain at all (a `drift_revert`
can target a resource that was only ever adopted via `ubx scan`, never
written to `.tf`) is reported the same way, in the same manual-steps
section, not a crash or an error. It does exit `1` when this happens,
though — see [Exit codes](/cli/exit-codes) — since manual steps are exactly
the kind of actionable finding a CI step should gate on.

<Note>
  `--tf-dir` falls back to [`.ubx/config`](/cli/config)'s `tf_dir` if not
  given explicitly, same as `ubx writeback`.
</Note>
