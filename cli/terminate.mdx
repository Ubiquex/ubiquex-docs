---
title: "ubx terminate"
description: "Author a destroy proposal directly from the ledger's own knowledge of one or more addresses -- no AI, no authoring document"
---

```text
ubx terminate <address>... [flags]
```

`ubx terminate` is UBI-49's own answer to a gap the terraform-shaped
[plan/ship flow](/guides/plan-ship-flow) otherwise leaves open: decommissioning
something the ledger already tracks costs an AI call through the
intent-provider prose path, or a hand-written `destroys[]` intent file, for
something the ledger already knows everything about. `ubx terminate` skips
both — the address **is** the spec.

Each `<address>` is self-contained (`<stack>.<type>.<name>`, the same
convention [`ubx blame`](/cli/blame)/[`ubx why`](/cli/why) already use), so
multiple addresses can be terminated in one command as long as they all
belong to the same stack. Under the hood this builds a destroys-only intent
and resolves it through the identical, unmodified `core/resolver.Resolve`
every other entry point already uses — the exact same orphan-protection,
duplicate/missing-target, and no-recorded-lookup checks a hand-written
`destroys[]` intent file already gets.

Like [`ubx plan`](/cli/plan), this command **never touches a ledger** —
nothing is accepted or applied here. The full receipt renders for review (the
destroyed resource's own last-known state, per the full-state-at-review
requirement drift review already follows), and the resolved-but-unaccepted
proposal is saved to `.ubx/plans/<hash>.json`, ready for `ubx ship <hash>`.

## Example

Adopt a resource the ledger doesn't track yet, then terminate it:

```text
$ ubx scan --provider ./fakeprovider --stack payments --type fake_widget --name old-widget \
    --lookup '{"id":"old-widget"}' --ledger-dir . --out adopt.json
New resource found  payments.fake_widget.old-widget

  adoption      dd28a22624e9     record-only · adopts into the ledger

  saved to plan store            next: ubx ship dd28a22624e9

$ ubx accept adopt.json --ledger-dir .
accepted dd28a22624e931b167a9f598da17eac476777b44180d149eb8508528679d35d9 (stack payments)

$ ubx terminate payments.fake_widget.old-widget --provider ./fakeprovider --ledger-dir .
Plan  payments

  - destroy: payments.fake_widget.old-widget
    id: "old-widget"
    name: null
    tags: {}

delta: +0 create(s), ~0 modify(ies), -1 destroy(s)

blast radius: +0 ~0 -1
cost delta: $0/mo

ubx-proposal: 046090bd56b1…
next: ubx ship 046090bd56b1
```

The destroyed resource's full last-known state renders red-led, `- destroy:`,
the same `+`/`~`/`-` create/modify/destroy verb-coloring
[`ubx plan`](/cli/plan)/[`ubx ship`](/cli/ship) use everywhere a delta
renders — and, per the compact-JSON rule every receipt follows, a nested
value like `tags` always renders on one line, never re-indented from
whatever whitespace happened to be in a saved plan file on disk.

`ubx ship` still enforces the standard double consent for anything with
`blast_radius.destroys > 0` — a bare `ubx ship <hash>` refuses, and (UBI-62)
a non-interactive shell also needs `--yes` to actually apply once destroys
are confirmed, the same typed-confirmation gate every `ubx ship` now goes
through:

```text
$ ubx ship 046090bd56b1 --provider ./fakeprovider --ledger-dir .
ship: this proposal has blast_radius.destroys > 0 -- pass --confirm-destroys to accept it

$ ubx ship 046090bd56b1 --provider ./fakeprovider --ledger-dir . --confirm-destroys --yes
Ship  payments · 18s old · +0 create(s) ~0 modify(ies) -1 destroy(s)
accepted 046090bd56b1… (stack payments) via local plan
payments.fake_widget.old-widget
  · pending
  · in_flight                                          0:00
  · unknown_post_timeout -- provider reported a successful destroy -- verifying via a post-destroy read-back before recording it as destroyed 0:00
  ⠧ provider reported success -- verifying via read-back (attempt 1/10) 0:00
  ✓ applied -- confirmed by reconciliation             0:00
✓ applied: payments.fake_widget.old-widget
1 resource(s), 1 applied, 0 failed, 0 still unknown -- outcome: applied
```

`ubx ship` does **not** re-render the full receipt shown at plan time —
just a one-line summary (stack, plan age, blast radius) confirming this is
still the plan being signed, since the full receipt already rendered once,
above, at `ubx terminate` time. `--yes` is the non-interactive equivalent
of typing `yes` at an interactive prompt (terraform's own pattern); omit it
in a real terminal and `ubx ship` prompts for that typed confirmation
instead of refusing outright.

`ubx why` renders the resulting tombstone the same way it renders any other
destroy:

```text
$ ubx why 046090bd56b1257b4160cec2740c85fb76e3ebdd99e26c4d4f6d2ecd4d808b5a --ledger-dir .
proposal 046090bd56b1… (change)
stack:  payments
status: accepted
intent: terminate payments.fake_widget.old-widget
accepted by [roozbeh] via local at 2026-07-31T19:37:28Z
blast radius: +0 ~0 -1
- destroy: payments.fake_widget.old-widget
  id: "old-widget"
  name: null
  tags: {}
apply history:
  attempt 1: outcome=applied
    payments.fake_widget.old-widget:
      pending at 2026-07-31T19:37:28Z
      in_flight at 2026-07-31T19:37:28Z
      unknown_post_timeout at 2026-07-31T19:37:28Z -- provider reported a successful destroy -- verifying via a post-destroy read-back before recording it as destroyed
      applied at 2026-07-31T19:37:28Z -- confirmed by reconciliation (destroyed)
      reconcile: present_matches at 2026-07-31T19:37:28Z
      reconcile: destroyed at 2026-07-31T19:37:28Z
```

The `proposal …` header line truncates to 12 chars + `…` by default, same as
every other command that renders a proposal hash this session — pass
`--full-hashes` to render it in full instead.

## Orphan protection

Terminating a resource another resource still depends on is refused, exactly
like a hand-written `destroys[]` intent file would be:

```text
$ ubx terminate payments.fake_widget.primary --provider ./fakeprovider --ledger-dir .
terminate: resolve: destroy target is still referenced by a resource this proposal does not also destroy or update: payments.fake_widget.primary is still referenced by payments.fake_widget.mirror, which this proposal does not also destroy or update
```

Terminate both together (or destroy the dependent first) once you've decided
what should happen to the dependent.

## Missing target

An address the ledger has never recorded gets a clean, actionable error, not
a partial or misleading receipt:

```text
$ ubx terminate payments.fake_widget.never-existed --provider ./fakeprovider --ledger-dir .
terminate: resolve: destroy names an address the ledger has never recorded: payments.fake_widget.never-existed
```

## `ubx destroy` is not an alias

Terraform muscle memory reaches for `destroy` first. `ubx destroy` exists so
that muscle memory finds *something* — but it's deliberately not a silent
alias for `ubx terminate`. Every other consent-relevant surface in this
project is explicit rather than implicit (double consent, typed
confirmations, the plan/ship split itself), so `ubx destroy` always teaches
toward the real verb instead:

```text
$ ubx destroy payments.fake_widget.old-widget
destroy: there is no "ubx destroy" -- use "ubx terminate" (same destroys[] machinery underneath, ledger-derived, no authoring document needed)
```

## Flags

| Flag | Description |
| --- | --- |
| `--ledger-dir string` | root directory containing `ledger/` and `.ubx/` — also where the plan is saved, at `.ubx/plans/<hash>.json` (default `.`) |
| `--provider string` | path to the provider binary (mutually exclusive with `--source`) |
| `--source string` | provider source address, e.g. `hashicorp/aws` (mutually exclusive with `--provider`; requires `--provider-version`; unused if config declares `[providers]`) |
| `--provider-version string` | explicit provider version to acquire (required with `--source`) |
| `--out string` | additionally write the full resolved proposal here (the plan is always saved under `.ubx/plans/` regardless) |
| `--timeout duration` | timeout for provider acquisition/schema fetch (default `1m0s`) |
| `--known-dependent stringArray` | `ledger_dir` of a neighbor stack to check for cross-stack orphan references before destroying (repeatable) |
| `--full-hashes` | render every hash in full instead of the default 12-char short form |
| `-h`, `--help` | help for terminate |
