title: "ubx init"
description: "Write a minimal, runnable .ubx/config.<format> -- a real stack and provider if given, a pointer to the full reference for everything else"
---

```text
ubx init [--dir <dir>] [--force] [--full] [--format hcl|toml|yaml] [flags]
```

Writes [`.ubx/config.<format>`](/cli/config), the defaults file every `ubx`
command reads. Default output is **minimal and runnable**: a real `stack`
(from `--stack`, or this directory's own name) and, if one was given, a real
provider — written into the modern `providers`/`provider_configs` map, the
same shape a multi-provider stack uses. Everything else (`github_repo`,
`tf_dir`, `k8s_audit`, `ledger`, `intent`) is left out of the default output
entirely, rather than shown commented — see the full key reference at
[`.ubx/config`](/cli/config), or pass `--full` to get the same reference
written inline instead.

If no provider is given by flag and you're at a real terminal, a short
prompt asks for one — press enter at the first question to skip it and
configure a provider later by hand. Refuses to overwrite an existing config
unless `--force` is given.

<Note>
  Before this session (UBI-59, a founder first-user test finding), `ubx
  init` wrote pure documentation — every key commented out, so `ubx plan`
  failed immediately after `ubx init` with no edits. The generated file is
  now runnable the moment a provider is configured, by flag, by prompt, or
  by hand.
</Note>

## Flags

| Flag | Description |
| --- | --- |
| `--dir string` | directory to write `.ubx/config.<format>` into — also where the stack name defaults from, if `--stack` is omitted (default `.`) |
| `--force` | overwrite an existing `.ubx/config.<format>` |
| `--full` | write the full, exhaustive annotated reference instead of the default minimal runnable config (every key, real values where given, commented examples for the rest) |
| `--format string` | config format to write: `hcl` (canonical), `toml`, or `yaml` (strict); falls back to `~/.ubx/config`'s own `init_format` (a personal preference, never project config), then `hcl`, if not given |
| `--stack string` | default stack name to write into the config (default: this directory's own name) |
| `--source string` | default provider registry source, e.g. `hashicorp/aws` — written into the modern `providers` map (mutually exclusive with `--provider`; requires `--provider-version`) |
| `--provider-version string` | explicit provider version, e.g. `6.54.0` (required with `--source`; no "latest" resolution) |
| `--provider string` | default provider binary path — a local/dev escape hatch, written into the legacy singular `provider` table (mutually exclusive with `--source`; there is no local-path slot in the modern map) |
| `--provider-config string` | default provider config, e.g. `{"region":"us-east-1"}` — merged with `--region` if both are given |
| `--region string` | shorthand for `--provider-config`'s most common key — equivalent to `--provider-config '{"region":"<region>"}'` |
| `--github-repo string` | default GitHub repository, e.g. `acme/infra` |
| `--tf-dir string` | default `.tf` directory |
| `-h`, `--help` | help for init |

## Example: no flags — a minimal, non-interactive run

With nothing given and no real terminal attached (a script, a redirect —
same as every transcript in this documentation), the stack still comes from
the directory's own name; only the provider is left unconfigured, shown as
a short commented example rather than the old exhaustive encyclopedia:

```text
$ cd payments && ubx init < /dev/null
+ .ubx/config.hcl has been generated successfully
    see https://github.com/Ubiquex/ubiquex-docs, cli/config
next: add a provider (re-run with --source/--provider-version, or edit .ubx/config.hcl by hand -- see https://github.com/Ubiquex/ubiquex-docs, cli/config), then ubx plan
```

```hcl
# .ubx/config.hcl -- generated by `ubx init` (HCL is the canonical format).
# CLI flags always override these; see https://github.com/Ubiquex/ubiquex-docs, cli/config.
# Unknown keys warn, they don't fail -- safe to hand-edit.

stack = "payments"

# providers = {
#   "hashicorp/aws" = "6.60.0"
# }
# provider_configs = {
#   "hashicorp/aws" = {
#     region = "us-east-1"
#   }
# }

# Full key reference (github_repo, tf_dir, k8s_audit, ledger, intent, the
# legacy single-provider shape, ...): https://github.com/Ubiquex/ubiquex-docs, cli/config
# -- or `ubx init --full` for the same reference written inline.

# next: add a provider above (uncomment providers/provider_configs, or
# re-run `ubx init --source <registry-source> --provider-version <version>`),
# then `ubx plan --from-doc <file>.md --stack payments` -- see https://github.com/Ubiquex/ubiquex-docs, cli/config
```

Real, unedited output. The closing `next:` comment is the one thing every
generated file ends with, and its wording depends on whether a provider
made it in — this one still needs one before `ubx plan` will get anywhere.

## Example: a real provider, from flags

```text
$ ubx init --source hashicorp/aws --provider-version 6.60.0 --region us-east-1 < /dev/null
+ .ubx/config.hcl has been generated successfully
    see https://github.com/Ubiquex/ubiquex-docs, cli/config
next: write an intent file and run `ubx plan <file>.json`, or `ubx plan --from-doc <file>.md --stack payments` -- see https://github.com/Ubiquex/ubiquex-docs, cli/config
```

```hcl
stack = "payments"

providers = {
  "hashicorp/aws" = "6.60.0"
}

provider_configs = {
  "hashicorp/aws" = {
    region = "us-east-1"
  }
}
```

`--region` is shorthand for the single most common `--provider-config` key
— `--provider-config '{"region":"us-east-1"}'` alone gets you the identical
`provider_configs` block; both together merge (`--region` wins if the two
disagree on the `region` key specifically). This is the entire point of
`ubx init`'s existence: the file above `ubx plan`s immediately, no editing
required — see [the end-to-end proof below](#a-provider-here-is-immediately-plan-able-no-edits).

## Example: the short TTY prompt

Give no `--source`/`--provider`, and `ubx init` asks for one — at a real
terminal only; every command in this documentation runs non-interactively,
so this transcript was captured through a real pty (`expect`), not piped:

```text
$ ubx init
Provider registry source, e.g. hashicorp/aws (enter to skip, configure later): hashicorp/aws
Version, e.g. 6.60.0 (required -- no "latest" pin): 6.60.0
Region, optional (enter to skip): us-east-1
+ .ubx/config.hcl has been generated successfully
    see https://github.com/Ubiquex/ubiquex-docs, cli/config
next: write an intent file and run `ubx plan <file>.json`, or `ubx plan --from-doc <file>.md --stack payments` -- see https://github.com/Ubiquex/ubiquex-docs, cli/config
```

Real, unedited output — the resulting file is byte-identical in shape to
the flag-driven example above. Pressing enter at the very first question
skips the whole prompt and leaves the provider unconfigured, exactly like
a flag-less, non-interactive run:

```text
$ ubx init
Provider registry source, e.g. hashicorp/aws (enter to skip, configure later): 
+ .ubx/config.hcl has been generated successfully
    see https://github.com/Ubiquex/ubiquex-docs, cli/config
next: add a provider (re-run with --source/--provider-version, or edit .ubx/config.hcl by hand -- see https://github.com/Ubiquex/ubiquex-docs, cli/config), then ubx plan
```

The prompt never hangs waiting past that first question if you skip it,
and it's never attempted at all on a non-interactive stdin (a script, CI,
a pipe) — you get the same minimal-with-commented-provider file as the
no-flags example above, no timeout, no ambiguity.

## Example: `--provider`, the local/dev escape hatch

`providers`/`provider_configs` has no slot for a local binary path — it's
keyed by registry source, the same identity [`ubx ship`'s own multi-provider
pool](/cli/config#multi-provider-stacks) launches by. `--provider <path>`
still works, writing the legacy singular `provider` table instead — the one
case where the "modern map only" rule has a deliberate, documented
exception:

```text
$ ubx init --provider ./terraform-provider-aws < /dev/null
+ .ubx/config.hcl has been generated successfully
    see https://github.com/Ubiquex/ubiquex-docs, cli/config
next: write an intent file and run `ubx plan <file>.json`, or `ubx plan --from-doc <file>.md --stack payments` -- see https://github.com/Ubiquex/ubiquex-docs, cli/config
```

```hcl
stack = "payments"

provider = {
  path = "./terraform-provider-aws"
}
```

A local path still counts as "a provider is configured" for the closing
`next:` hint — `ubx plan` works immediately either way.

## `--full`: the exhaustive annotated reference, inline

Everything the original `ubx init` always wrote — every key, real values
where given, commented examples for the rest — is still one flag away for
whoever wants it inline instead of [`.ubx/config`](/cli/config)'s own
reference:

```text
$ ubx init --full --stack payments < /dev/null
+ .ubx/config.hcl has been generated successfully
    see https://github.com/Ubiquex/ubiquex-docs, cli/config
next: add a provider (re-run with --source/--provider-version, or edit .ubx/config.hcl by hand -- see https://github.com/Ubiquex/ubiquex-docs, cli/config), then ubx plan
```

```hcl
# .ubx/config.hcl -- generated by `ubx init --full` (HCL is the canonical format).
# CLI flags always override these; see https://github.com/Ubiquex/ubiquex-docs, cli/config.
# Unknown keys warn, they don't fail -- safe to hand-edit.
# Literal values only: no variables, functions, or interpolation.

# Default stack for commands that need one (e.g. `ubx scan`, `ubx status --stack`).
stack = "payments"

# Default GitHub repository for --from-merge / --verify-acceptance / --surface-as.
# github_repo = "acme/infra"

# Default .tf directory for --tf-dir (ubx writeback, ubx revert-plan, ubx scan --surface-as).
# tf_dir = "./terraform"

# Provider identity, legacy single-provider shape -- a local/dev escape hatch
# only; new stacks should prefer `providers` below instead.
# provider = {
#   path = "/path/to/terraform-provider-aws"
#   source = "hashicorp/aws"
#   version = "6.54.0"
# }

# Provider configuration for the legacy provider shape above.
# provider_config = {
#   region = "us-east-1"
# }

# A stack's whole declared provider set -- source -> pinned version, explicit
# pins only. The modern, preferred shape for any stack, single- or
# multi-provider alike.
# providers = {
#   "hashicorp/aws" = "6.60.0"
# }

# Per-source provider configuration, for `providers` above.
# provider_configs = {
#   "hashicorp/aws" = {
#     region = "us-east-1"
#   }
# }

# EKS control-plane audit log attribution for kubernetes_*/helm_release
# drift -- entirely optional, no CLI flag equivalent. Absent or cluster unset
# means such a drift's attribution records audit_unattributed/not_configured,
# never blocking detection.
# k8s_audit = {
#   cluster = "my-eks-cluster"
#   region = "us-east-1"
#   log_group = "/aws/eks/my-eks-cluster/cluster"
# }

# Which LedgerStore backs this stack -- absent or "git" is today's exact
# in-repo directory behavior (--ledger-dir), unchanged. A stack name is
# always appended as a further path segment, never configured here.
# ledger = {
#   store = "s3://acme-ledger/acme/prod/"
# }

# next: add a provider above (uncomment providers/provider_configs, or
# re-run `ubx init --source <registry-source> --provider-version <version>`),
# then `ubx plan --from-doc <file>.md --stack payments` -- see https://github.com/Ubiquex/ubiquex-docs, cli/config
```

Real, unedited output. `--full` and the default template share every real
value, the destructuring logic, and the closing `next:` hint — `--full`
only changes how much of the *unconfigured* rest gets spelled out.

## `--format`: hcl (default), toml, or yaml

```text
$ ubx init --format toml --stack payments < /dev/null
+ .ubx/config.toml has been generated successfully
    see https://github.com/Ubiquex/ubiquex-docs, cli/config
next: add a provider (re-run with --source/--provider-version, or edit .ubx/config.toml by hand -- see https://github.com/Ubiquex/ubiquex-docs, cli/config), then ubx plan
```

```text
$ ubx init --format yaml --stack payments --source hashicorp/aws --provider-version 6.60.0 < /dev/null
+ .ubx/config.yaml has been generated successfully
    see https://github.com/Ubiquex/ubiquex-docs, cli/config
next: write an intent file and run `ubx plan <file>.json`, or `ubx plan --from-doc <file>.md --stack payments` -- see https://github.com/Ubiquex/ubiquex-docs, cli/config
```

```yaml
# .ubx/config.yaml -- generated by `ubx init --format=yaml`.
# CLI flags always override these; see https://github.com/Ubiquex/ubiquex-docs, cli/config.
# Unknown keys warn, they don't fail -- safe to hand-edit.
# Strict mode: quote every value explicitly -- an unquoted numeric-looking
# value that would silently narrow (e.g. 6.60 -> 6.6) is a hard error.

stack: "payments"

providers:
  "hashicorp/aws": "6.60.0"
```

YAML output is always fully quoted, including values that look numeric
(`"6.60.0"`) — strict mode's own safety margin, see
[`.ubx/config`'s own YAML section](/cli/config#formats-hcl-canonical-toml-forever-yaml-strict).

### A personal default, from `~/.ubx/config`

If you always prefer one format, set it once, per-machine, rather than
typing `--format` on every `ubx init`:

```text
# ~/.ubx/config
init_format = "yaml"
```

```text
$ ubx init
+ .ubx/config.yaml has been generated successfully
    see https://github.com/Ubiquex/ubiquex-docs, cli/config
```

`--format`, when given, still wins outright. This is the one
personal-preference key `~/.ubx/config` supports today — see
[User-global `~/.ubx/config`](/cli/config#user-global-ubx-config) for why
it's the *only* kind of key allowed there.

<Warning>
  `ubx init` refuses to write into a directory that already has a config
  file under a **different** name — not just the exact target filename.
  Discovery reads only one file per directory (`config.hcl` →
  `config.toml` → `config` → `config.yaml`, first found wins), so writing
  a new one alongside an existing file of a different format would
  either silently shadow that file's values or itself never be read at
  all. Pass `--force` to proceed anyway once you've confirmed that's what
  you want:

  ```text
  $ ubx init
  init: .ubx/config already exists in this directory -- writing .ubx/config.hcl would create two config files with only one ever read per discovery order (config.hcl -> config.toml -> config -> config.yaml); use --format to match the existing file, or --force to write .ubx/config.hcl anyway
  ```
</Warning>

## A provider here is immediately plan-able, no edits

The whole point of writing a runnable config rather than documentation:
`ubx init --source ... --provider-version ...` (or the equivalent TTY
prompt), then `ubx plan` against a hand-written intent file, with **no
further flags at all** — `--stack`, `--provider`, `--source` all come from
the config `ubx init` just wrote:

```text
$ ubx init --stack payments --source fake/widget --provider-version 0.1.0
+ .ubx/config.hcl has been generated successfully
    see https://github.com/Ubiquex/ubiquex-docs, cli/config
next: write an intent file and run `ubx plan <file>.json`, or `ubx plan --from-doc <file>.md --stack payments` -- see https://github.com/Ubiquex/ubiquex-docs, cli/config

$ ubx plan intent.json --ledger-dir .
Plan  payments · from intent.json

  + fake_widget.widget1 create
      name: "widget1"

delta: +1 create(s), ~0 modify(ies), -0 destroy(s)

blast radius: +1 ~0 -0
cost delta: $0/mo

ubx-proposal: <hash>…
next: ubx ship <shorthash>
```

Real output (a hermetic `fake/widget` provider stands in for a real
registry source here — see `cli/init_test.go`'s own
`TestInit_OutputImmediatelySupportsPlan_ViaMirror`, which drives exactly
this sequence and is this claim's own regression test).
