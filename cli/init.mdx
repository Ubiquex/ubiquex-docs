---
title: "ubx init"
description: "Write a starter .ubx/config.<format> -- real values for whatever flags are given, commented examples for the rest"
---

```text
ubx init [--dir <dir>] [--force] [--format hcl|toml|yaml] [flags]
```

Writes [`.ubx/config.<format>`](/cli/config), the defaults file every `ubx`
command reads. Any flag you give `ubx init` is written as a real, active
value; anything you don't is written as a commented-out example showing the
correct syntax — the generated file is immediately useful as its own
documentation of what's possible, not just a blank template. Refuses to
overwrite an existing config unless `--force` is given.

## Flags

| Flag | Description |
| --- | --- |
| `--dir string` | directory to write `.ubx/config.<format>` into (default `.`) |
| `--force` | overwrite an existing `.ubx/config.<format>` |
| `--format string` | config format to write: `hcl` (canonical), `toml`, or `yaml` (strict); falls back to `~/.ubx/config`'s own `init_format` (a personal preference, never project config), then `hcl`, if not given |
| `--stack string` | default stack name to write into the config |
| `--provider string` | default provider binary path (mutually exclusive with `--source`) |
| `--source string` | default provider source, e.g. `hashicorp/aws` (mutually exclusive with `--provider`; requires `--provider-version`) |
| `--provider-version string` | default provider version, e.g. `6.54.0` (used with `--source`) |
| `--provider-config string` | default provider config, e.g. `{"region":"us-east-1"}` |
| `--github-repo string` | default GitHub repository, e.g. `acme/infra` |
| `--tf-dir string` | default `.tf` directory |
| `-h`, `--help` | help for init |

## Example: no flags — a fully-commented template

```text
$ ubx init
wrote .ubx/config.hcl
```

```hcl
# .ubx/config.hcl -- generated by `ubx init` (HCL is the canonical format).
# CLI flags always override these; see https://github.com/Ubiquex/ubiquex-docs, cli/config.
# Unknown keys warn, they don't fail -- safe to hand-edit.
# Literal values only: no variables, functions, or interpolation.

# Default stack for commands that need one (e.g. `ubx scan`, `ubx status --stack`).
# stack = "payments"

# Default GitHub repository for --from-merge / --verify-acceptance / --surface-as.
# github_repo = "acme/infra"

# Default .tf directory for --tf-dir (ubx writeback, ubx revert-plan, ubx scan --surface-as).
# tf_dir = "./terraform"

# Provider identity: EITHER a local binary path, OR a registry source + explicit version.
# provider = {
#   path = "/path/to/terraform-provider-aws"
#   source = "hashicorp/aws"
#   version = "6.54.0"
# }

# Provider configuration, e.g. the region a provider should read from.
# provider_config = {
#   region = "us-east-1"
# }
```

(The generated file also includes commented `providers`/`provider_configs`,
`k8s_audit`, and `ledger` examples — trimmed here for length; see
[`.ubx/config`](/cli/config) for the full reference.)

## Example: real values for whatever you supply

```text
$ ubx init --stack payments --provider ./terraform-provider-aws --provider-config '{"region":"us-east-1"}'
wrote .ubx/config.hcl
```

```hcl
# .ubx/config.hcl -- generated by `ubx init` (HCL is the canonical format).
# ...

# Default stack for commands that need one (e.g. `ubx scan`, `ubx status --stack`).
stack = "payments"

# Default GitHub repository for --from-merge / --verify-acceptance / --surface-as.
# github_repo = "acme/infra"

# Default .tf directory for --tf-dir (ubx writeback, ubx revert-plan, ubx scan --surface-as).
# tf_dir = "./terraform"

# Provider identity: EITHER a local binary path, OR a registry source + explicit version.
provider = {
  path = "./terraform-provider-aws"
  # source = "hashicorp/aws"
  # version = "6.54.0"
}

# Provider configuration, e.g. the region a provider should read from.
provider_config = {
  region = "us-east-1"
}
```

`stack` and `provider`/`provider_config` are real, active values; `github_repo`
and `tf_dir` stayed commented examples, since no flag supplied them.

## `--format`: hcl (default), toml, or yaml

```text
$ ubx init --format toml --stack payments
wrote .ubx/config.toml
```

```text
$ ubx init --format yaml --stack payments --source hashicorp/aws --provider-version 6.60.0
wrote .ubx/config.yaml
```

YAML output is always fully quoted, including values that look numeric
(`version: "6.60.0"`) — strict mode's own safety margin, see
[`.ubx/config`'s own YAML section](/cli/config#formats-hcl-canonical-toml-forever-yaml-strict).

### A personal default, from `~/.ubx/config`

If you always prefer one format, set it once, per-machine, rather than
typing `--format` on every `ubx init`:

```text
# ~/.ubx/config
init_format = "yaml"
```

```text
$ ubx init
wrote .ubx/config.yaml
```

`--format`, when given, still wins outright. This is the one
personal-preference key `~/.ubx/config` supports today — see
[User-global `~/.ubx/config`](/cli/config#user-global-ubx-config) for why
it's the *only* kind of key allowed there.

<Warning>
  `ubx init` refuses to write into a directory that already has a config
  file under a **different** name — not just the exact target filename.
  Discovery reads only one file per directory (`config.hcl` →
  `config.toml` → `config` → `config.yaml`, first found wins), so writing
  a new one alongside an existing file of a different format would
  either silently shadow that file's values or itself never be read at
  all. Pass `--force` to proceed anyway once you've confirmed that's what
  you want:

  ```text
  $ ubx init
  init: .ubx/config already exists in this directory -- writing .ubx/config.hcl would create two config files with only one ever read per discovery order (config.hcl -> config.toml -> config -> config.yaml); use --format to match the existing file, or --force to write .ubx/config.hcl anyway
  ```
</Warning>
