Everything so far involved an assistant helping you *author*. This
tutorial connects one so it can *answer questions* about what you've
already shipped, with no ability to change anything.

## Start the server

```bash
ubx mcp
```

This blocks, serving requests over stdio. Leave it running, or let your
MCP client start it for you.

## Connect a client

```json
{
  "mcpServers": {
    "ubx": { "command": "ubx", "args": ["mcp"] }
  }
}
```

Point your client's working directory at your real `payments/`
directory, same defaults a human sitting there would get.

## Ask it something real

In your assistant's own chat interface:

```
Why does the pipeline-events queue have a 14 day retention?
```

The assistant calls `ubx_why` internally, reads the exact same ledger
`ubx why` would from your terminal, and answers from real data, your
own real proposal, your own real signature.

## Confirm it can't change anything

Ask it to change the retention period. It can't, there's no tool
exposed for that. It can only describe what already happened.

## What you just did

You gave an AI assistant real, direct access to your infrastructure's
history, and confirmed it structurally cannot act on your behalf, only
help you understand what you already decided.
